# Poster Figure Data

The active performance figures compare the current generated Fortran implementation labelled esm.md with six earlier Fortran, Julia and Python controls. Tuned and Vanilla keep their recorded meanings. Vanilla uses unchanged control source with strict target-aware compiler optimisation, while Tuned uses retained measured source changes. Python is compiled with Numba. The CPU and GPU appear in separate panels, and colour and marker shape identify each grid size. CPU axes are linear and GPU axes are logarithmic, so a major GPU tick step changes the rate by a factor of ten.

Every point is the median of twelve individual complete-cell-update rates. A complete update advances all model fields through both time stages and the boundaries. Whiskers show the observed minimum and maximum rather than a confidence interval. Historical per-run rates are calculated from their retained elapsed times so both cohorts use this same median estimator. The original historical summaries remain unchanged, including their earlier estimator based on the median elapsed time.

The current esm.md cohort was recorded on 8 November 2026. Earlier CPU controls were recorded on 5 October and earlier GPU controls on 8 October. The cohorts use separate nodes and runs. They use compatible frozen mathematics, input generators, grid sizes and batch lengths, and each passed its own retained physical and exact-output checks. This poster revision performs no new simulation, timing or comparison of output states between cohorts. The figures show recorded absolute rates rather than a newly paired speedup.

CPU wall-clock intervals cover complete native update runs on one Neoverse V2 core. GPU event intervals cover complete launch-graph replays on one NVIDIA GH200 device. Compilation, setup, validation and file output are excluded as declared by each protocol. GPU transfers and graph construction are also excluded. These kernel rates do not measure complete application turnaround time or x86 performance.

The results-current.json snapshot retains the accepted current observations, timing source hashes, original node and job identities, and current source-path aliases. The historical benchmark.json and gpu-benchmark.json files retain the earlier CPU and GPU evidence. The performance-figure-evidence.json file records the exact plotted per-run rates, summaries, source-variant mappings and cohort metadata. Normal plotting needs only these copied records and the local font and style assets. Importing new current records with prepare_results.py requires the local research archive.

The separate historical figures retain the earlier six-control CPU view. The physical-model binary inputs and outputs in this folder support the unchanged scientific illustrations, whose values, units and colour scales are preserved.
