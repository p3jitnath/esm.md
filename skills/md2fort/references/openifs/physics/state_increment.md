## Ordered Update And Domain

Let $`K`$ count input horizontal columns and $`N`$ count levels. Support $`0\leq K\leq4096`$ and $`0\leq N\leq1024`$, valid selected indices `KIDIA` through `KFDIA` within `1..K`, and empty selected ranges. Complete active state owners can have up to 8,192 horizontal elements, padded storage and different 32-bit lower bounds. The cloud owner has at most 64 components. Each state descriptor is contiguous, has first stride one, includes the selected columns, and has exactly $`N`$ vertical elements. The cloud descriptor also contains components one through four.

For each supplied and enabled increment, round `old+increment` once to FP64, the 64-bit floating-point format. Preserve the source order of wind U, wind V, temperature, vapour, ozone, cloud fraction, turbulent kinetic energy, liquid cloud water, cloud ice, rain and snow. Optional absent pointers are zero. Wind and temperature need no field mask. Every other field needs its own logical mask set to one. A disabled mask is zero. An absent or disabled increment is never accessed and changes no bytes.

The four cloud increments update the corresponding component in `CLD`. The routine does not separately write through the `QL`, `QI`, `QR` and `QS` descriptors. An unused view can observe a cloud update when it shares that owner, without requiring another numerical stage. All cells outside the selected columns keep their complete incoming bytes. Require finite inputs and finite sums. Physical increments must leave temperature positive, mass fractions and cloud fraction in $`[0,1]`$, and turbulent kinetic energy nonnegative. Wind can have either sign.

Require FPCR zero for nearest rounding with ties to even, gradual underflow and preserved signed zeros. There is no contraction, reassociation, reduced precision or external numerical helper.

## Original GNU ABI And Owners

The application binary interface, or ABI, fixes 13 ordinary pointers. Registers `x0` through `x7` address the dimension object, state object and optional U, V, T, ozone, vapour and cloud-fraction increments. Caller stack offsets 0, 8, 16, 24 and 32 hold optional liquid water, ice, rain, snow and turbulent kinetic energy increment pointers. Each present increment owns $`8KN`$ bytes in Fortran order and little-endian FP64.

The dimension object is 192 bytes. Four-byte integers at offsets 0, 4, 12 and 48 give `KIDIA`, `KFDIA`, `KLON` and `KLEV`. The state object is 1,240 bytes. Four-byte masks for ozone, vapour, cloud fraction, liquid, ice, rain, snow and energy occur at offsets 0, 4, 8, 12, 16, 20, 24 and 28. Rank-two descriptors for U, V, T, ozone, vapour, cloud fraction, energy, QL, QI, QR and QS begin at offsets 32, 120, 208, 296, 384, 472, 560, 648, 736, 824 and 912. The rank-three cloud descriptor begins at offset 1000.

Each GNU descriptor stores its data pointer at byte 0, element offset at byte 8 and element length and span at bytes 16 and 32. Dimension records give stride, lower bound and upper bound at bytes 40, 48 and 56, followed by records at 64, 72 and 80, and at 88, 96 and 104 for the cloud component. Strides count elements. The element address is `data+8*(offset+sum(index*stride))`. A vertical colon visits the descriptor's complete vertical range, including its actual lower bound, while increment levels start at one.

Descriptors, dimensions and increments stay read-only. Active state owners can use different horizontal sizes, align to eight bytes and are disjoint from all input owners and each other. Unused descriptors need not be associated and are never read by the numerical body. Nonempty active owners have valid complete storage. The leaf assembly must preserve `x19` through `x30`, leave `x18` and the preserved low 64 bits of `v8` through `v15` untouched, and restore its aligned 192-byte frame. The frame stores the 11 optional pointers and uses no array scratch. Each independent pair of columns uses an Arm SIMD addition, which applies the same single rounding to each lane, followed by a scalar remainder.
