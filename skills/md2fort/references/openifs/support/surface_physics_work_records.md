# Surface Physics Work Records

These services replace `SURF_AND_MORE_TYPE_INIT`, `SURF_AND_MORE_TYPE_UPDATE_VIEW` and `SURF_AND_MORE_TYPE_FINAL` from `ecphys_surface_type_mod.fypp`. They include the nine prognostic group initializers and view updates from `surface_views_module.fypp`. The generated source supplies field names and statement order only. Direct assembly implements each address, allocation and view operation. No surface equation or stored weather value is calculated here.

The raw initializer is `int md2asm_initialize_surface_work_record(record, geometry, variables, surface_variables, levels, persistent)`. Registers `x0` through `x4` carry five addresses. `w5` is zero or one. The first four objects span 13,680, 17,096, 72,696 and 160,800 bytes, with eight-byte alignment, mapped complete storage and no overlap. `levels` is a mapped four-byte aligned array of three nonnegative integers, in soil, snow and ocean order. The geometry supplies positive row and block counts, and complete shape products fit signed address arithmetic and their allocations. The record owns no live fields on entry. The selected forecast uses 24 rows and 86 blocks. The live source metadata supplies its level counts. The critical cases use four soil, five snow and two ocean levels as well as empty counts. The numerical storage inputs remain caller-owned and live throughout use.

Initialization first binds all nine nested surface groups. It copies 99 field pointers, stores nine source group addresses and preserves every public array view. A group field named F_GROUP is an embedded FIELD object in the source variable group, so its destination receives that object's address. The other field slots receive the stored source pointers. This distinction is established by individual typed queries. The initializer then borrows five tile fields and creates 35 temporary owners in source order. Their level counts come from the original soil, snow or ocean argument, as recorded by the source table. Four owners contain 32-bit integer vegetation or soil indices. The remaining owners contain FP64 values. Nonpersistent storage has one thread-local block. Persistent storage has every geometry block. New numerical bytes remain undefined until a producer writes them.

`md2asm_update_surface_work_views(record, block)` selects a one-based block through the original field rules. It writes 99 nested group views followed by 40 direct views, retaining the source order. Each null optional F_GROUP leaves its incoming PGROUP descriptor unchanged. All other consumed field pointers must be live and satisfy the accepted original FIELD descriptor and block preconditions. The qualified FP64 rank-two leaf and unchanged rank-three and rank-four leaves select numerical storage. The new integer rank-two leaf uses the same address calculation with four-byte elements and GNU integer dtype. No view operation changes a numerical buffer or allocates storage.

`md2asm_finalize_surface_work_record(record)` releases only the 35 owned DATA and FIELD allocations, in original order, and clears their field-pointer slots. Borrowed fields, nested groups, public views and all other bytes remain unchanged. Null owned slots are allowed during direct initialization failure cleanup. The initializer releases a failed partial construction and returns one. A successful call returns zero. The original-interface constructor terminates on failure, matching the nonreturning original allocation failure.

The parent entries use 192-byte frames aligned to 16 bytes and preserve saved registers, `x18`, FPCR, FPSR and errno. Original GNU adapters preserve the eight-argument constructor order, with three referenced level integers and an optional persistent logical. Their constructor frame is 64 bytes. The two metadata methods use the original class and referenced block arguments. The new int32 allocator uses the accepted owned-field descriptor mechanism with four-byte elements and integer dtype. Its FIELD object spans 256 bytes. Only direct assembly, the accepted allocator and C allocation, cleanup and error-address services supply production operations. Original geometry and variable metadata remain explicit caller inputs.

The 421 individual typed queries establish every consumed field slot, source pointer and view descriptor. Three complete source cases cover thread-local storage, the persistent last block, empty soil, snow and ocean layers, and null optional group views. Nine raw or original-interface calls preserve the ABI and numerical status. All source-defined owned descriptors, complete public descriptors, pointer relationships, unchanged record bytes and complete numerical buffers agree. Independently allocated addresses are compared through their owners and offsets. Undefined values before a producer writes them are not compared. Independent source review and the joint complete forecast passed, including the native counts and complete byte gate recorded in [the auxiliary contract](auxiliary_physics_work_records.md). Original metadata construction remains an explicit caller boundary.

The three original-interface entries also increment their own aligned 64-bit integer counters in INIT, UPDATE_VIEW and FINAL order. These private observations use only caller-saved integer registers and do not change a field, numerical flag or library error value. The joint gate reads these three words and retains the earlier state-view counter scope.
