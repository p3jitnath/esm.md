# Runtime field-variable lifecycle

A field variable records a name and pointers to its stored arrays. This component checks the three metadata methods that prepare private variables for one physics block, select that block's array views and release the private variables. A view contains an address, dimensions and spacing between elements. These methods do not calculate a weather value.

The input is a fresh [runtime field registry](../setup/runtime_field_registry.md), with actual assembly-created MODEL, FIELDS, configuration, surface and radiation owners. Its 66 caller numerical arrays are explicit component inputs. The Geometry-shaped record declares storage dimensions and is not complete physical Geometry or loaded weather. This check does not call the original registry methods again.

The three raw entries are unchanged: `md2asm_clone_field_variable_arrays` receives the complete 72,696-byte FIELD_VARIABLES address in x0; `md2asm_update_field_variable_views` receives that address in x0 and a positive block index by value in w1; `md2asm_reset_field_variable_arrays` receives the address in x0. They have no declared integer return, so the value left in x0 is ignored. Records and pointer slots require eight-byte alignment. Every complete record, array and referenced field must remain mapped, within its declared bounds and separate from mutable outputs. The raw caller must establish these prerequisites.

The checked profiles use width 17, 137 levels and either one block with block index one or seven blocks with block index seven. All 18 shared array families have associated original one-dimensional descriptors with one-based bounds. Their actual metadata contains 18 VARIABLE_3D records in total: NOGW has two, PHYS has zero and every other family has one. Clone creates 18 private allocations containing 13,104 logical record bytes. The empty PHYS allocation still has a distinct associated address and counts as one owner. Its logical extent remains zero.

Clone copies the six field pointers FT0, FT1, FT9, FPH9, FDL and FDM into source-default private variables. It borrows those fields and does not copy or release their numerical storage. Update visits the 61 source-listed scalar variables and 18 array families in order, with the five ECMWF physics variables last. It selects the stored block according to each field's active, owned and thread-buffer flags, then aliases P to T0. Reset frees only the 18 private arrays and restores their pointer descriptors to the shared arrays. Scalar views retain the selected block after reset. The underlying [private-variable methods](field_variable_arrays.md) and [field-view rules](physics_field_block_views.md) remain unchanged.

Before each source transaction, the checker saves a typed restoration map and complete preimages for all 1,340 reachable original metadata owners. These include the outer record, FIELD records, shared VARIABLE arrays and surface metadata. It captures complete returned records after clone, update and reset, then restores every original metadata span before the separate native transaction. All 843 registry numerical owners and 66 caller arrays remain read-only. Numerical payloads are never restored to conceal a change. Both routes preserve every declared caller and radiation payload byte, all borrowed fields and MODEL, the Geometry-shaped record and FIELDS, and release every observed owner.

The comparison includes every source-defined metadata byte and each typed pointer's target, offset and alias relationship. Each new private VARIABLE_3D has an undefined 16-byte NAME; its source-defined CNAME, code, logical flags and six field pointers remain compared. Each unassociated 88-byte public-view descriptor defines its null base at bytes 0–7; bytes 8–87 have no source-defined value. An associated view is compared through its complete 88-byte descriptor. The exact remaining inactive descriptor ranges are those already declared by the runtime registry. No associated descriptor word or numerical payload byte is excluded.

Two genuine source and native lifecycle pairs pass. Each profile compares 325,184 source-defined metadata bytes after clone, 332,560 after update and 329,184 after reset. Across the two profiles, this gives 1,973,856 compared metadata snapshot bytes per route. Each route releases all 18 private owners per profile, including the empty PHYS owner. The existing independent source, ownership, first/final-block and critical leaf records are reused; no passed leaf bank is replayed.

The application binary interface (ABI) defines register and stack rules. All six native method observations have ABI mask zero. The original clone and update have the known x18 mask two, while original reset has mask zero. Immediate FPCR, which controls floating-point operations, remains zero; FPSR, which records status flags, remains 24; and the C error word errno remains 777. The native route preserves x18, saved integer registers, required vector-register halves and sixteen-byte stack alignment. Three fresh isolated assemblies reproduce the complete accepted objects exactly. Actual native joins remain local, and their external services are public C allocation, release, copying, error-address lookup and the previously declared allocation-failure termination.

The original typed controls and source modules remain a separate verification route. No original OpenIFS routine supplies a production stage. There is no assembly body change, main Fortran rebuild, STATE or work-record construction, EC_PHYS_DRV, CALLPAR, loaded-weather or forecast acceptance in this component.
