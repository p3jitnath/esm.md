# Selected output requests and views

Revision 1 replaces three read-only children from `selected_output_metadata.F90`: `md2asm_output_field_map_`, `md2asm_output_block_views_` and `md2asm_output_io_views_`. A view is an address into an existing array. These children read integer requests and return addresses; they calculate no field values, allocate no storage and call no original procedure. Three private integer counters record their calls.

The input records are genuine GNU Fortran 12 objects from the selected single-process forecast. Their pointers are associated, their array descriptors are valid, and each requested index lies within its source allocation. A descriptor records an array address, its element size, its bounds and the distance between adjacent indices. These are entry conditions, rather than descriptor checks in the assembly. The supported block shape has 24 rows, 19 levels and 86 blocks, with eight active rows in the last block. The GMV and GFL field indices must select existing fields, and block indices lie in 1 through 86. All address calculations fit signed 64-bit integers; the source block-count calculation also fits signed 32-bit integers.

For a scalar element with logical indices $`i_d`$, the byte address is `base + element_bytes * (offset + sum(i_d * stride_d))`. The assembly retains the descriptor's stored offset and every consumed stride, including the second dimension of `IGT1` and `ILVP`. A whole-array `LOC`, such as `LOC(OROG)` or `LOC(GM)`, returns its stored base address. It does not substitute the address of logical element 1. Each returned pointer remains valid only while its original owner remains allocated.

The field-map interface receives `Q`, an address of a 32-bit field code, and `P`, an aligned five-word integer buffer. It writes all 40 bytes. A request with a false `LL(CODE)` returns five zeros. Selected true codes are 5 for temperature, 6 for humidity and 454 for logarithmic surface pressure. It retains signed integer extension, chooses `IGT1(CODE,1)` when `ISF>0`, otherwise chooses `IGPX(CODE)`, and returns `LOC(ILVP(1,CODE))` with the original buffer pitch. Unsupported true codes and `ISF>1` terminate with source exit code 109. The raw operating-system exit omits the Fortran runtime's diagnostic text. Codes outside the allocated `LL` bounds are outside the interface contract.

The block-view interface receives addresses of Geometry, GMV, GFL, Model, a 32-bit block index and an aligned 24-word buffer. It writes all 192 bytes, including the four trailing zero words. Words 1 through 3 contain row count, level count and active rows. Words 4 through 20 contain the source temperature, humidity, condensate, pressure, wind, orography, map-factor and vertical-coordinate addresses in unchanged source order. Orography is the terrain height field, and the map factor converts distances between the model grid and physical space. The assembly reads the existing owner arrays without copying or changing them.

The I/O-view interface has eleven address arguments: `F,E,S,M,PHY,SP,GP,OFN,KSTEP,TSTEP,P`. Arguments 1 through 8 arrive in x0 through x7. `KSTEP`, `TSTEP` and `P` arrive at incoming stack offsets 0, 8 and 16 bytes. `SP` and `GP` are unused in the original body. The aligned `P` buffer receives all 18 words, or 144 bytes, in source order. These addresses identify geometry dimensions, existing physical configuration, output names, step and time records. This child constructs no strings or message handles.

Every output buffer must be writable, aligned to eight bytes and separate from all input owners and arrays. Each input object must cover its typed size: Geometry 17,096 bytes, GMV 1,560 bytes, GFL 1,096 bytes, Model 4,275,088 bytes, FULLPOS 503,824 bytes, Surface 18,224 bytes, TRQFP 744 bytes, TFPOFN 1,536 bytes and request 1,160 bytes. The retained typed layout records the exact component offsets and derived-array record sizes. The user-geometry record is 472 bytes, TOROG is 384 bytes and TGSGEOM is 1,472 bytes.

All three entries are leaf procedures with no stack frame. They use only x0 through x17 and condition flags, while x18, x19 through x29, the stack pointer and the saved vector registers remain unchanged. No floating-point instruction changes the floating-point control register (FPCR) or status register (FPSR). The normal return also preserves `errno`. Counters have unsigned 64-bit words in field-map, block-view and I/O-view order; `md2asm_output_metadata_count_get(index)` returns a word for indices 0 through 2 and zero otherwise. Counter updates assume the selected serial call route.

The focused source comparison uses unchanged copies of the three Fortran bodies solely as controls. Ten cases compare all 1,064 output-table bytes, with first, penultimate and partial last blocks, false requests, spectral and grid requests, signed integer values and both FPSR seeds 0 and 31. Twenty seeded source/native ABI calls preserve x18 and all saved registers. Complete supplied type records and three large field buffers, totalling 8,652,600 bytes per snapshot, remain unchanged. Both rejection cases retain exit 109. The constructor-only loaded-context proof uses all 70 retained R4 preloads plus this one prefix and resolves the three actual consumer jump slots to this exact DSO, with zero child calls and no model run.

## Retained services

The remaining seven original metadata wrappers stay explicit dependencies. `md2asm_fullpos_request_prepare_` calls `SU4FPOS` to allocate and initialise request records; `md2asm_fullpos_request_release_` calls `DEALLOC_FPFIELDS` to release them. `md2asm_output_scan_metadata_` selects a source level list, calls `ALLOCATE_FPRQDYN`, `SUVPOS` and `CPVPOSPR` at scan entry, and calls `SUVFPOSL` and `DEALLOCATE_FPRQDYN` at scan exit. `md2asm_output_request_metadata_` calls `SUVFPOSL` to initialise selected output request maps.

`md2asm_output_header_metadata_` retains `SUFPOFNAME` string construction, `SUFPTR2` physical-request initialisation and allocation of the zero-field auxiliary descriptor. `md2asm_output_header_release_` retains the compiler's derived-type release semantics for that record. `md2asm_output_auxiliary_metadata_` retains the selected zero-climatology `SUFPDATA` descriptor setup and its calendar-month selection. These allocation, initialisation, naming and cleanup services have not been replaced by this revision. Their original bodies remain outside the three direct read-only children's credit.

The assembly is built directly from AArch64 assembly with GNU assembler/linker through GCC 12.3.0. It has no dynamic library dependencies or undefined symbols. Independent source review and the complete selected forecast check pass. No autonomous-forecast completion or performance claim follows from these component checks.

The [complete forecast check](../../../../../src/openifs/README.md#verification) passes for the selected route. Its declared upstream data and branch limits remain in force.
