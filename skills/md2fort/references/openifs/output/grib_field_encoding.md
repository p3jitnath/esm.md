# GRIB Field Encoding

Revision 1 defines `md2asm_encode_grib_field`, which gives ecCodes one field and its ordered metadata to produce a GRIB message. GRIB is the weather file format used by the retained ten output files. All forecast field calculations remain in their accepted direct controllers. Assembly owns the field rules and spectral fit; ecCodes is the declared C file-format service.

The C interface is `int md2asm_encode_grib_field(spec, values, message, length, owner)`. Registers `x0` through `x4` carry five addresses. The immutable 64-byte specification contains eight 64-bit words: a raw C template handle, parameter identifier, original level number, representation (one for spectral and zero for grid point), level type (one for model and zero for pressure), forecast seconds, value count and the logical flag that forces the original log-surface-pressure packing operator. The three output addresses each hold one eight-byte word. The returned message pointer stays valid until the caller releases the returned owner through `codes_handle_delete`. The caller supplies complete, mapped, aligned and disjoint records and value spans. No saved forecast payload supplies an input.

The selected spectral inputs have 506 finite FP64 values at truncation 21, parameters 130 or 152, and pressure or model levels. The selected grid input has 2048 finite values, parameter 133 and a model level. Original model levels lie from 1 through 19, and pressure levels are positive Pa. Forecast seconds lie from 0 through 86,400 and use whole hours. The template already contains the declared common metadata and geometry. The selected grid bit-count policy has no external precision table, no model-level compression override and returns 16 bits. Missing values and other parameters or shapes are outside this entry contract. Unsupported input or FPCR other than zero returns status 2 without an output write.

Clone the C template first. For a spectral field, repeat the original J, K and M setters with 21. Set type to `fc`, time-range indicator to zero, step type to `instant`, step units to seconds and end step to the supplied seconds. At time zero repeat the instant setter and set time-range indicator to one. For a positive whole hour, restore step units to hours. These calls retain the original setter order.

Set 16 packed bits. For a forced model-level parameter 152, set the packing operator to the exact value 0.5. Other spectral fields call the accepted direct FITSPECTRUM child with controls 21, 506 and 10, negate its slope and clamp the result to the interval −9.9 through 9.9. Then set subset J, K and M to 10. Grid fields retain the ordered minimum and maximum scans before the fixed 16-bit policy. Next set hybrid or pressure level, query and check the forecast type, set the parameter, set all FP64 values and obtain the complete encoded message. Assembly introduces no fused operation, numerical fallback or precomputed encoded field.

The frame occupies 224 bytes with sixteen-byte alignment. Preserve x18, saved general registers, required vector low halves and FPCR. C file-format calls and the frozen numerical arithmetic determine FPSR and errno; both must match the original reference on the admitted route. Inputs and guards remain unchanged. Return zero transfers one live C handle to the caller. A nonzero ecCodes result releases the private clone and returns the original error, leaving all three outputs unchanged. A clone allocation failure returns one. No original Fortran output procedure is called by production code.

Acceptance compares complete message bytes, input spans, status and seeded ABI with the original GRIB_CODE_MESSAGE and GRIB_UPDATE_MESSAGE procedures. Both start from the same ordinary library sample metadata. Common-template construction and original WROUT entry adapters are separate assembly stages and remain required before the ten-file forecast gate.

The required joint selected forecast passes the unchanged complete-owner, raw-status and ten-file byte gate through the [GRIB field writers](grib_field_writers.md). The format boundary remains the ecCodes C interface, with no original Fortran numerical callable.
