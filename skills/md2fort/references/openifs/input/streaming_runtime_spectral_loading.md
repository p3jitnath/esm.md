# Streaming Spectral Initial-State Loading

This loader reads the initial wave coefficients from GRIB, the binary weather-file format, into the existing local model arrays. A coefficient is one stored wave value. The loader keeps one decoded global record and a private copy of the local arrays. It publishes the local data only after every required record, the end of the file and file closure pass. This reduces temporary storage while preserving the original input order and every decoded bit.

Let $`N`$ be the largest total wave index and $`L`$ the number of global atmospheric layers. Each global record has $`C=(N+1)(N+2)`$ real FP64 words. FP64 is the 64-bit floating-point format. There are $`R=3L+2`$ records. The first is logarithmic surface pressure with parameter 152 and level 1. Each global layer then supplies vorticity 138, divergence 155 and temperature 130 in that order. The last record is orography 129 at level 0. Vorticity and divergence use inverse seconds, temperature uses kelvin, and orography geopotential uses square metres per square second. Logarithmic surface pressure retains its source dimensionless encoding.

The application binary interface, or ABI, defines argument registers and saved state. `md2asm_load_streaming_runtime_spectral_state(path, spectral_record, record_capacity, loaded_orography, map_view, view_capacity)` takes six arguments in `x0` through `x5`. The same canonical model owns the spectral record and all of its arrays. The record needs 2992 bytes and the read-only map view needs 160 bytes. Both have eight-byte alignment. The four-byte output flag has four-byte alignment. The nonempty path ends with a zero byte within 4096 mapped bytes. Every complete range is mapped, does not wrap and remains stable during the call. The destination arrays and flag are separate from each other, the path, records and all consumed maps.

The caller first completes the qualified runtime spectral constructor. Its descriptors, ownership and full backing bounds remain valid through return. The map view carries the local real-coefficient count at byte 144, the local wave count at 148, global $`N`$ at 152 and global $`L`$ at 156, as 32-bit integers. Supported global bounds are $`1leq Nleq4096`$ and $`1leq Lleq256`$, within the constructor's admitted combinations and process maps. The loader cross-checks the consumed record dimensions and descriptors. It requires the source field order 138, 155, 130, 152 and 129.

MYMS lists local wave numbers. NASM0 and NASM0G give their one-based local and global starting words. MYLEVS gives the local layers' one-based global numbers. For wave $`m`$, the zero-based global start is $`m(2N+3-m)`$, and its span has $`2(N+1-m)`$ real words. Before opening the file, the loader checks every consumed wave span, the complete local coefficient coverage, increasing layer numbers, field identifiers and writable-range separation. The local volume array stores layer first, then coefficient and field. The surface array stores coefficient first, then logarithmic pressure and orography. All placement uses integer loads and stores, so it preserves signed zeros and every other decoded FP64 bit.

Let $`ell`$ be the local layer count, $`K`$ the local real-coefficient count and $`S`$ the local surface-field count, which is zero or two. One allocation holds the global row, both uncommitted local copies, a 128-byte private context, the schema and complete record metadata. Its exact byte count is

```math
8C+max(8,24ell K)+max(8,8SK)+176+56R.
```

The two minimum eight-byte spaces retain alignment. Empty numerical owners keep their existing dummy bytes. Every actual local output byte starts from its incoming value and changes only through selected record placement. The loader releases its temporary allocation on every returning path. It sets `loaded_orography` to one only after success, including when this process owns no local surface coefficients.

Return zero means success. Return one refuses an argument, descriptor or map, and two reports temporary allocation failure. A file-stage error returns 16 plus the accepted reader status, including 20 for missing required records. Every returning failure preserves both complete numerical outputs and the flag. The selected private reader retains the original ecCodes calls, metadata checks, completed-record count, end-of-file checks and cleanup order. It reuses the same row buffer and scatters each accepted record into private storage. Original date and other metadata limits remain those of the accepted spectral reader.

The owning entry uses a 768-byte stack frame and the private reader uses 224 bytes, both aligned to 16 bytes. The private scatter is a leaf and uses only scratch registers. Preserve `x18`, saved integer registers, required vector halves and the stack pointer. FPCR controls floating-point arithmetic and must be zero on entry. Both FPCR and FPSR, which records floating-point status, retain their incoming values on return. The runtime error number `errno` is also preserved. Production calls only public ecCodes and C services, with no original OpenIFS routine or harness stage.

The focused check passed 60 constructor, loader, failure and release calls across 12 partitions on two genuine ecCodes files with global shapes $`N=3,L=3`$ and $`N=8,L=2`$. It includes zero local waves, both surface ownership cases and different local layer counts. A separate coefficient-first traversal matched complete numerical outputs, with exact records and map views across 60,411 compared bytes. Register, status, allocation-size, live-owner guard and cleanup checks passed. A late end-of-file failure discarded the staged prefix, and allocation refusal changed no published output. The actual operational file, canonical input connection and full forecast still require their own acceptance. Detailed controls and results stay local.
