# Runtime Partitioned Upper-air Placement

This direct assembly component places the seven selected upper-air fields into one process's model buffer. It follows the accepted SUGRIDUG assignments through the live NGLOBALINDEX map, which gives each local point's one-based index in the global decoded field. Integer copies preserve every stored FP64 bit and the input units. FP64 means a 64-bit floating-point number. The same assembled entry reads its supported counts and strides at runtime.

The selected source profile has nine destination fields. Its zero-based parameter-to-slot pairs are 133→0, 246→1, 247→2, 76→3, 75→4, 248→5 and 203→6. These are specific humidity, cloud liquid water, cloud ice water, snow-water content, rain-water content, cloud fraction and ozone. Slots seven and eight are diagnostic fields set to positive zero. The caller retains this field profile; the component does not introduce a new field family.

`md2asm_bind_runtime_partitioned_upper_air_shape(out64, Geometry20400, YGFL1359136, headers, header_capacity)` receives five arguments in x0–x4. The application binary interface (ABI) defines these argument registers and the saved state. Return zero publishes all 64 output bytes, while two refuses before any output change. The eight unsigned 64-bit output words are local point count, map address, consumed map bytes, block count B, columns per block P, layers L, global point count and destination field count D.

The binder reads P, L, B, local points and global points at Geometry bytes 5,144, 5,224, 5,160, 7,376 and 7,388. It calls the accepted [runtime grid-point shape binder](../setup/runtime_distributed_gridpoint_field_storage.md) and requires the live D value at YGFL+48 to equal nine. Require $`1\le P\le 1{,}024`$, $`1\le L\le256`$, positive signed-32-bit point counts, $`N_{\mathrm{local}}\le N_{\mathrm{global}}`$ and $`B=\lceil N_{\mathrm{local}}/P\rceil`$. The remaining field counts retain that child's supported bounds. Counts have no unit.

The borrowed map descriptor starts at Geometry+6,648. It is a complete 64-byte GNU Fortran rank-one int32 descriptor: its base names the map owner, element size and span are four bytes, bias is minus one, stride and lower bound are one, and upper bound is the local count. The consumed map extent is exactly four times that count. The accepted Geometry producer supplies unique local points and distributed coverage. The map-owning Geometry remains live until placement ends.

The accepted [header record](initial_model_file_headers.md) supplies L at byte 16, northern row count R at byte 56 and positive int32 row lengths at byte 4,208. Require $`1\le R\le1{,}280`$, total rows $`2R`$, retained width equal to the largest northern row and twice the northern sum equal to Geometry's global count. Header L must equal Geometry L. The complete consumed header span is max(5,232,align8(4,208+4R)), no more than 9,328 bytes. Geometry, YGFL, headers and map remain source-valid through their consumers. Their counts remain fixed during binding and placement.

The complete output span has eight-byte alignment and is disjoint from Geometry, YGFL, the consumed header and map. Geometry and YGFL retain the shape child's separate complete spans. Other read-only views need no additional separation. All consumed spans are mapped and nonwrapping; map addresses have four-byte alignment. The binder neither decodes a file nor creates a Geometry.

`md2asm_place_runtime_partitioned_upper_air_fields(values, value_capacity, metadata, metadata_capacity, GFL, GFL_capacity, partition64)` receives seven arguments in x0–x6. The last argument is the binder's read-only 64-byte result. The other pointers have eight-byte alignment. Required value bytes are $`8\times7L N_{\mathrm{global}}`$, metadata bytes are $`40\times7L`$ and output bytes are $`8PLDB`$. GFL is disjoint from the complete consumed value, metadata, partition and map spans; the read-only inputs may alias. Capacity beyond each consumed span remains unchanged.

The first 2L records alternate parameters 133 and 203 at each increasing layer. The next 5L records contain 75, 76, 246, 247 and 248 at each increasing layer. Each metadata row has five signed 64-bit words: parameter, one-based layer, value count, date and time. The placer checks all map indices in 1..Nglobal, then every row's first three words before any destination store. Date and time remain unused here, matching the accepted placement child; the reader checks them.

GFL has shape [P,L,D,B], with columns varying fastest. For zero-based column r, layer l, slot s, block b and local point i, its destination word w and input word v are

```math
i=Pb+r,\qquad w=r+P\bigl(l+L(s+Db)\bigr),\qquad v=qN_{\mathrm{global}}+\mathrm{map}[i]-1,
```

where q is the input record number. Both diagnostic fields are zeroed across complete blocks, including padding. The seven copied fields update active points only, so their final-block padding retains its incoming bytes. The final active count is $`N_{\mathrm{local}}-P(B-1)`$. A fresh owning caller defines copied-field padding before loading.

All byte products and address offsets fit signed 64-bit arithmetic under the admitted bounds. Conservative maxima are 30,786,325,563,392 value bytes, 71,680 metadata bytes and 39,582,437,437,440 output bytes. Actual mapped capacity and the owning caller's allocation budget still apply. The raw placer returns zero on success, one for invalid shape/span/capacity, two for metadata refusal and three for a map-index refusal. Refusals preserve the complete destination.

The exact P=17, L=137 and Nglobal=6,599,680 specialization forwards to the unchanged accepted partitioned placer after the new complete 64-byte partition-span checks. Other admitted tuples use the generic body. Each new entry has a 160-byte frame with sixteen-byte alignment; the specialized child raises maximum nested depth to 256 bytes. Both preserve x18, required saved integer/vector state, the floating-point control and status registers FPCR/FPSR, and the C library error code errno. The generic path uses integer instructions only. Production linkage resolves the accepted direct shape and placement children; it supplies no original OpenIFS calculation.
