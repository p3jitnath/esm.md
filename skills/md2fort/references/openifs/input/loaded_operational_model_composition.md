# Loaded Operational Model Composition

This direct assembly parent creates the selected final MODEL and FIELDS storage and loads the three initial-state files. It composes the already accepted storage, configuration, trajectory-control and file-loading children. It leaves source-unwritten next-time arrays in their declared state. It supplies no missing physical initialisation, grid calculation, time loop or forecast output.

The seven arguments are the live startup9968 owner, complete Geometry sidecar1872, spectral path, surface path, upper-air path, alias-destination table120 and a fresh eight-byte output pointer. They use registers x0 through x6, with an integer return in w0. The two owners and table are eight-byte aligned, mapped for their full sizes and live through every child. The output slot starts null. All input paths end in zero bytes. The alias table names fifteen distinct aligned eight-byte slots initially zero. These slots and output are disjoint from each other, the table, all input records, text, paths and their borrowed owners. Every declared span is mapped and nonwrapping. The startup and Geometry sidecar refer to the same final vertical Geometry. All consumers hold exclusive use during this construction.

The caller produces startup with md2asm_create_operational_startup_inputs and complete Geometry with md2asm_complete_owned_distributed_geometry. This parent is local and makes no new collective call. A verification driver may serialize independent rank allocations with MPI barriers to bound memory, while the forecast route uses one rank per node. The parent itself neither chooses a rank nor provides a serial numerical substitute.

The ordered calls create MODEL/FIELDS, attach final configuration and the live partition, initialise the accepted trajectory scalars, create saved-pressure work, advance to saved-step controls and saved-temperature work, allocate fourteen main motion planes and three surface motion planes, allocate local spectral fields, load spectral fields, create and load surface state, load the distinct upper-air file, and finally allocate next-time work. The spectral field IDs are the selected standard GRIB parameter codes138,155,130,152,129; values and metadata still come from each live file. Model and field records stay at their final owned addresses throughout.

Return zero publishes the same800-byte owner returned by the accepted model-storage constructor. Failure preserves the caller's null output, releases all acquired child owners through the accepted model release, and clears its fifteen aliases. An entry refusal returns two. Each child failure adds a stage code10,20,25,30,40,50,60,70,80,90,100 or110, respectively. The caller releases this owner with md2asm_release_distributed_operational_model_storage before releasing Geometry and startup. The parent has a160-byte frame, preserves x18 and all required saved Arm registers, requires FPCR zero and retains natural child FPCR,FPSR and errno effects.
