# Runtime Initial Upper-air Field Reader

This direct assembly reader extends the selected seven-family upper-air file intake. It reads real GRIB messages through the accepted public ecCodes C interface and derives dimensions from the output of [initial model header intake](initial_model_file_headers.md). The same assembled reader selects supported row and layer counts at runtime. The existing fixed-shape entries remain available.

`md2asm_read_runtime_initial_upper_air_fields(path, values, value_capacity, metadata, metadata_capacity, completed_count, headers, header_capacity)` receives its eight arguments in x0–x7 and returns status in w0. The path ends with a zero byte. Output values, metadata, eight-byte count and the complete consumed header span have eight-byte alignment and mapped, nonwrapping ranges. The three outputs are pairwise separate and separate from the header. The path may alias an output because fopen consumes it before the first output change.

The accepted header supplies layer count L at byte 16, northern row count R at 56 and positive int32 northern row lengths at 4,208. Require $`1\le L\le256`$, $`1\le R\le1{,}280`$ and total row count $`N_j=2R`$ at byte 8. The consumed header size is $`\max(5{,}232,\operatorname{align8}(4{,}208+4R))`$, no more than 9,328 bytes. Require its retained width at byte 12 to equal the largest northern row. Global point count N is twice the northern sum and must fit a positive signed 32-bit integer (int32). These are dimensionless counts.

For each layer from one through L, read specific humidity Q (paramId133) then ozone (203). Next, for each layer, read rain-water content (75), snow-water content (76), cloud liquid water (246), cloud ice water (247) and cloud fraction (248). There are $`7L`$ messages, each with N values stored as 64-bit floating-point numbers (FP64). Required value bytes are $`8\times7L\times N`$, at most 30,786,325,563,392. Required metadata bytes are $`40\times7L`$, at most 71,680. Each metadata row has five little-endian int64 words: parameter, layer, decoded value count, dataDate and dataTime. Numerical units and value bits remain those supplied by the source file and codec.

Header bytes 44 and 48 supply grid date and seconds after midnight. Require a positive date no greater than 99,991,231 and a whole-minute time from zero through 86,340 seconds. Exact integer conversion produces HHMM for the source message comparison. The header step belongs to its clock consumer; this reader retains the accepted date/time identity scope.

Before decoding each value array, check parameter, layer, date, time, actual value count, numberOfDataPoints, Gaussian grid template40 and scan mode zero. Gaussian order N in the GRIB key must equal header R, while $`N_j`$ must equal $`2R`$. For a reduced grid with missing Ni, compare every complete PL row with the mirrored header list. For a regular grid, require $`R\le256`$, Ni equal to every retained northern width and checked $`N_iN_j`$ equal to the derived point count. The source missingValue setting stays −9999. No interpolation or weather calculation occurs.

Return zero means all expected messages were read and EOF occurred at the expected position. One refuses invalid arguments, spans, header bounds, capacity or nonzero FPCR before changing public output. Two means open failure; the completed count becomes zero after fopen consumes the path. Three means a codec, read or handle-delete error, four means an identity, grid, count or EOF mismatch, and five means close failure without an earlier error. Later failure keeps the complete decoded prefix and may keep the current value row. Count advances only after a complete accepted message. Every held handle is deleted and every opened file is closed once, preserving the first error.

The public 57,648-byte frame contains a private trusted identity schema derived in assembly. The unchanged accepted reader body uses 256 bytes and the full row checker uses 20,624, giving 78,528 maximum nested stack bytes aligned to sixteen bytes. The application binary interface (ABI) defines argument registers, saved registers and stack alignment. Preserve x18, required saved integer registers, low vector halves, the floating-point control register (FPCR), the floating-point status register (FPSR) and the C library error code (errno). Set FPCR to zero before entry. Only public ecCodes, C file and error-address calls supply external services; no original OpenIFS routine, module-data constructor or numerical fallback is used.

Source, ABI and exact loaded-provider checks passed. The runtime gate passed two real GRIB paths: a reduced Gaussian grid with four rows, 24 points and two layers, and a regular Gaussian grid with eight rows, 64 points and three layers. All decoded value bytes and complete metadata matched an independent C traversal through the public codec. A wrong complete row list and short file retained exactly the accepted seven-message and five-message prefixes. Insufficient capacity refused before file or output access. File and codec-handle counts balanced on success and both later failures, and protected boundaries passed. The defined 40-byte status records were archived; the unchanged ABI probe checked its return mask immediately in process. The independent traversal shares ecCodes, so it does not independently verify codec mathematics.

This reader alone does not extend owning partition placement, source padding, spectral placement, virtual temperature or the enclosing forecast owner. Those providers retain their earlier bounds until their runtime extensions pass. The same assembled reader served both cases, and the main Fortran reference executable was not rebuilt.
