# Operational Spectral Loading Utility

Revision 1 loads the accepted 137-layer, truncation-1279 spectral input into caller-owned arrays. Spectral truncation limits the horizontal wave numbers. This shape has 1,639,680 real coefficients per field. The utility composes the accepted [file decoder](initial_spectral_field_reader.md) and [coefficient placement](operational_spectral_field_placement.md) entries. It adds no floating-point equation or conversion. The [coarse loading caller](spectral_initial_state_loading.md) remains unchanged.

The interface is `int md2asm_load_operational_spectral_initial_state(path, geometry, configuration, spectral, loaded_orography)`. The five addresses occupy x0 through x4 under the Arm application binary interface (ABI). The path is a readable C string that ends within 4096 bytes. Geometry, configuration and spectral records occupy 17,096, 1,556,112 and 2,992 bytes and align to eight bytes. The final address selects a writable four-byte logical flag, aligned to four bytes. The flag and complete output arrays are disjoint from each other, the input records, code owner and path. The caller supplies mapped storage of every declared size.

The supported records select normal initial input, one wave process, one thermodynamic field, three upper-air fields and two surface fields. Geometry holds resolution index 1, coefficient count 1,639,680 and global/local level counts 137. These are input conditions, not constructed defaults. The configuration supplies the contiguous parameter codes 138, 155 and 130, which identify vorticity, divergence and temperature. Surface codes 152 and 129 identify logarithm of surface pressure and orography geopotential. Units and the complete 413-record order follow the decoder contract. No date or input-file hash is hardcoded.

The configuration permits at most 2,163 component records and no spectral component. Each requested grid-point component must already select grid-point or trajectory input. Thus this route does not omit a required spectral-to-grid conversion. The utility reads only the declared scalar fields and GNU 12-compatible descriptors; it does not consume geometry-owned mesh, transform, hybrid-coordinate or reduced-grid arrays. A complete geometry or configuration producer remains separate work.

The spectral record supplies contiguous eight-byte floating-point arrays through its descriptors: SP2D at byte offset 0 has shape (1,639,680, 2), and SP3D at offset 88 has shape (137, 1,639,680, 3). Every lower bound is 1. SP2D requires 26,234,880 bytes and SP3D requires 5,391,267,840 bytes. The configuration's descriptor at offset 40 supplies three contiguous four-byte codes. Descriptor sizes, strides, biases and address bounds use 64-bit arithmetic. Other record bytes and addresses remain unchanged.

The utility validates the supported metadata and complete pointer ranges before allocation. One 5,417,512,632-byte scratch owner holds 5,417,502,720 decoded value bytes followed by 9,912 metadata bytes. Only complete decoder success permits placement into the public arrays. Only complete placement sets the loaded-orography flag to 1. Argument, metadata, allocation and decoding failures preserve every public output byte and the incoming flag. Every acquired scratch owner is released.

The return value is 0 for success, 1 for a buffer refusal, 2 for unsupported metadata, 3 for allocation failure, 10 plus the decoder status, or 20 plus the placement status. The floating-point control register FPCR must be 0. The utility preserves FPCR, the floating-point status register FPSR, errno, x18 and the required saved registers. It exports no original SUSPECG alias and does not reproduce the original parent's diagnostic text, stream bookkeeping or full runtime effects.

Production uses only the two accepted direct assembly children, libc allocation/error services and public ecCodes file-format calls. The original program and all language controls remain verification tools. One bounded in-memory comparison used the independent public-ecCodes C decoder and accepted metadata-driven Fortran placement as its expected route. The typed metadata fixture and reference placement library were released and unloaded before native execution; process maps confirmed that no Fortran or OpenIFS library remained mapped in that phase.

The complete check matched all 5,417,502,720 output bytes. Each of five native calls preserved all 1,576,200 input-record bytes and the 12-byte code owner. The success, wrong-level metadata, wrong SP3D extent, real scratch-allocation failure and genuine one-message file cases returned 0, 2, 2, 3 and 14. All five ABI masks were zero, immediate FPCR/FPSR/errno values were 0/24/777, and all 385,772 guard bytes remained intact. Allocation and release counts, complete failure outputs and the orography flag agreed. The unchanged coarse fourteen-case evidence was reused through literal source correspondence, without replay.

This accepts the complete loading utility for the declared records and file schema. It does not qualify a full geometry/configuration producer, bootstrap, grid-point input, original parent or operational forecast. No multi-gigabyte payload file or hash was produced.
