# Surface Field Owner Allocation

Revision 1 implements the complete allocation and release substage in the original SURFACE_FIELDS_MIX ALLO_SURF and DEALLO_SURF procedures. The caller owns a mapped, eight-byte-aligned 18,224-byte TSURF record and its already selected surface-group counts. The raw entry md2asm_allocate_surface_field_owners receives this record in x0, a row count in w1 and a block count in w2. It requires all 34 numerical descriptors to be empty zero records. Other metadata remains unchanged. This is a storage constructor, not a complete surface-configuration constructor or a forecast.

The row count is 1 through 64, the block count is 1 through 128 and each field count is zero through 512. A four-dimensional group has zero through 64 levels. Each allocation has at most 64 MiB. Three-dimensional owners have shape (rows, fields, blocks), and four-dimensional owners have shape (rows, levels, fields, blocks), in Fortran order. All elements are eight-byte FP64 words. A descriptor records an array address, type, bounds and strides, where a stride gives the spacing between adjacent values in a chosen dimension. The independently typed source query supplies every descriptor and count offset.

The direct routine allocates all 34 owners in source order, including nonnull owners for empty shapes. It then sets every word in SP_SL, SP_RR, SP_SG and SD_VF to positive zero, matching the source assignments across complete allocations. Every other numerical byte remains incoming allocation storage until its later producer writes it. A verification-only allocator supplies identical incoming bytes to source and direct buffers. Production has no payload fill, imported model-state packet or original module address.

Status zero means complete success. Status one means allocation failure after all acquired owners are released. Status two rejects unsupported arguments, shapes or incoming descriptors before mutation. An allocation failure can leave the released prefix of descriptor metadata, with all owner data pointers cleared. The paired md2asm_release_surface_field_owners entry receives the record in x0 and accepts only a valid mapped selected live or partially acquired record, frees each live owner in original order and clears its data address while retaining source-defined descriptor metadata. Named field pointers outside these owners are not changed by the original procedures or this child. The caller must not consume a freed owner through any view.

FPCR must be zero at construction. The entries preserve FPCR, FPSR, errno, x18 and x19 through x29 and v8 through v15, with 16-byte stack alignment. The initializer uses a 144-byte frame and release uses 96 bytes. Their only external calls are libc malloc, free and the errno-address service. The numerical values are zero stores or preserved incoming bytes, so no new physical arithmetic is introduced. Independent source/ABI review, complete record and owner comparisons, empty-shape bounds, zero assignments, allocation-failure cleanup and the final dependency boundary must pass before admission. No original-routine credit or autonomous forecast is claimed at this child checkpoint.

Three genuine source/direct cases pass 14,301,504 complete owner bytes and 109,344 complete created/released record bytes, with zero differences. They include mixed empty and nonempty shapes and the actual ten nonempty selected owners under two allocation preimages. All twelve immediate ABI/status calls pass; every native saved-register mask is zero, while the original source has its recorded x18 change. The 1,434 independent shape, stride, offset, zero and preservation relations pass. Three allocation-failure paths release all acquired owners, four unsupported-input cases preserve the complete record and all 8,096 allocation guard bytes remain intact. A standalone assembly-entry lifecycle process exits zero without preload or library-path variables and links only libc. Independent source and ABI review passes. No model forecast or timing was run.
