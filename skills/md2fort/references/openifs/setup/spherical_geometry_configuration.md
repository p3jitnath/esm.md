# Spherical Geometry Configuration

This contract covers SUGEM_NAML for the selected global ECMWF grid with NHTYP zero. Each latitude row has NDLON longitude points. The constructor reads NAMGEM, constructs two integer-array owners and sets the source geometry controls. NLOENG contains every row length, including rows used at the poles. NLOEN is allocated here but receives its numerical contents from a later source stage.

The selected source route has unit stretching, NSTTYP one and NHTYP zero. The initial-file controls remain live inputs. The selected NSTTYP, NHTYP and unit-stretch values are checked before construction. UMUCEN and ULOCEN are finite inputs and are overwritten by the source pole-reset rule. The actual NAMGEM group sets only NHTYP=0. An empty group uses the same source default. Other NAMGEM assignments and grid families are outside this contract and must be rejected rather than forwarded to Fortran. LECMWF remains true. No physical equation or grid choice changes.

The raw entry receives complete writable Geometry in x0, three int32 words NSUPERSEDE, NUSTTYP and NUHTYP in x1, and three FP64 inputs UMUCEN, ULOCEN and USTRET in x2. The source dimensions and complete array-descriptor slots already exist inside Geometry. The raw entry requires fresh null NLOEN/NLOENG bases. It creates their independent buffers with bounds NDGSAG through NDGENG and records all source-defined associated-descriptor words. Allocation calls occur in source order. An allocation failure releases storage that this call owns. A separate direct cleanup releases these two owners and does not imply execution of an original forecast destructor.

When the file supersede flag is set, the source computes its initial RNLGINC guess using the ordered FP64 division, multiplication, integer nearest rounding and division. The ECMWF grid rule then selects the final RNLGINC. The implementation preserves those arithmetic stages and floating-point status even though that guess does not determine the final value on this route. NSTTYP one resets RMUCEN and RLOCEN to one and zero. RSTRET remains one, LNONHYD_GEOM false, NSTTYP one and NHTYP zero. All NLOENG entries are NDLON, while no NLOEN payload byte is written.

A complete Geometry record contains 17,096 bytes. Geometry contains a borrowed pointer to the LNONHYD_GEOM logical word. This separate four-byte output word must become false and its pointer must remain unchanged. All unrelated record bytes must retain their incoming values. Each integer-array descriptor has 64 bytes and each element has four bytes. The interface uses the AArch64 ABI, preserves x18, saved registers and 16-byte stack alignment, and changes floating-point status only through the source arithmetic. Allocation/file services must not supply a numerical stage. Source console printouts and optional DR_HOOK diagnostics are omitted under the canonical saved-output scope, and neither supplies forecast data. The original wrapper may read declared scalar module data during integration, but may call no original procedure, constructor, vtable or type service.

Source verification compares every produced owner byte, complete associated descriptors and the complete released record, including guards and unrelated incoming bytes. A verification-only allocator supplies a known incoming preimage to both source and direct allocations, so the full source-unwritten NLOEN owner can also be checked. The production allocator does not fill this numerical owner. Independent row-length and grid-symmetry checks, immediate ABI/status checks, file parser checks and a complete forecast comparison are required before admission. No source array payload is used as a precomputed production input.
