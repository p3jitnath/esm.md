# Runtime ECMWF Physics Working Fields

The runtime entry creates the [ECMWF physics working fields](ecmwf_physics_field_storage.md) from live dimensions. P is the number of columns in one block, L is the number of vertical levels, B is the number of blocks and T is the number of surface types. All four values are positive signed 32-bit integers in the caller’s shape record. P and L range from 1 through 1024, B ranges from 1 through 2147483647 and T ranges from 1 through 16. These storage bounds do not extend the supported range of a later numerical child.

The application binary interface, or ABI, defines argument locations and saved registers. The entry `md2asm_initialize_runtime_ecmwf_physics_fields` takes a fresh 704-byte record in x0, its capacity in x1, the four shape values in x2 and one writable four-byte field count in x3. Capacity must be at least 704 bytes. The record is aligned to eight bytes, while the shape and count are aligned to four bytes. All complete ranges are mapped, nonwrapping and pairwise disjoint. The entire fresh record begins with zero bytes, including every owner address and the source-defined false flag.

Five tile arrays each contain P times T times B FP64 values. The microwave array contains P times L times nine times B FP64 values. FP64 means a 64-bit floating-point value. Their combined byte size is

```math
S = 8 P B (5 T + 9 L).
```

At the largest supported dimensions, S is below two to the power 58. Every complete byte size, array stride and signed descriptor origin therefore fits in 64-bit integers. The shared body uses 64-bit registers for those products and addresses. Available memory can still cause a normal allocation failure. The caller budgets simultaneous owners before requesting a larger grid.

The source order is unchanged. The entry allocates all five tile owners, sets every tile value to positive zero, stores the field count nine, then allocates and zeroes the microwave owner. The GNU array descriptions retain the exact original bounds, strides and first-element addresses. The same directly emitted assembly body serves the runtime entry and the existing default entry. The complete default object is unchanged. The paired `md2asm_release_runtime_ecmwf_physics_fields` entry releases all six owners in declaration order and clears their addresses, retaining the other source-defined metadata.

Creation returns zero on success, one after allocation failure and cleanup, or two before mutation for invalid arguments. Release accepts the same live or partly acquired record as the original entry, and a null record is a no-op. The caller retains the outer record until its children are released. Creation has a 160-byte frame and release has 96 bytes. Both preserve x18, every required saved register, 16-byte stack alignment, FPCR, FPSR and errno. FPCR controls rounding, FPSR records arithmetic flags and errno records a C library error. Creation requires FPCR zero. The only strong external imports are malloc, free and the public errno-address service. No original OpenIFS calculation, constructor or global state supplies production.

Three new source/native profiles cover shapes {17,137,3,9}, {1024,1,1,16} and {1,1024,1,1}, with incoming FPSR zero, 24 and 16. All 1324280 complete numerical bytes and 4224 complete created/released record bytes agree with zero differences. Only actual allocation addresses are related for record comparison, with every pointer, dimension, stride and origin checked separately. All numerical elements are independently checked as positive zero. The gate passes 207 independent storage relations, 24 immediate ABI/status observations, two partial-allocation failures, eight new shape refusals, two extreme-size first-allocation failures and all 832 heap-guard bytes. The extreme cases prove the complete first-allocation size without attempting those large allocations.

The retained full operational profile {17,137,97055,9} already compares all 16868935440 numerical bytes and 1408 created/released record bytes. That evidence is reused because the new runtime entry changes only its positive dimension admission and entry names. The complete admitted allocation, zeroing, descriptor and release body is identical. No accepted bank is replayed and the original main Fortran executable is not rebuilt. The new check has a 120-second deadline and four-GiB address-space bound. Complete live FIELDS forwarding, enclosing physics initialisation and the autonomous forecast remain separate. No comparative timing is claimed.
