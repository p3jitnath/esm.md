# Owned Physical Constant Names

The [physical-constant producer](physical_constant_setup.md) already calculates the constants used by the forecast. This include gives those existing bytes the original GNU module names read by direct assembly callers. An alias is a second name for the same storage. It adds no calculation, allocation, copied state or original OpenIFS dependency.

Include `physical_constant_aliases.inc.S` after the owning initial entry defines `.Lphysical_constants`, a complete eight-byte-aligned 520-byte record. The accepted producer must succeed before any consumer uses these names. Sixty-four eight-byte aliases follow the complete offset, identifier and unit table in the physical-constant contract. The four-byte `__yomcst_MOD_l_has_been_setup` alias refers to bytes 512 through 515. The full-buffer name `md2asm_owned_initial_physical_constants` refers to all 520 bytes. The caller retains this record throughout the forecast. Its final four reserved bytes retain their existing producer policy.

The include emits only object-symbol declarations and has no callable interface, register use, stack, numerical operation or external API. A focused assembly check confirms every producer-relative address, complete width and record bound. All 65 original names and object widths match the genuine module exports. Instructions, constants, initialized data and uninitialized storage are unchanged from the qualified R11 entry. Existing complete constant-source, independent physical, ABI and initial-state checks are reused without another numerical execution. Full autonomous forecast acceptance remains separate.
