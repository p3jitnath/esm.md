# Consumed Spline Knot Intervals

The selected `SUVFE_MATRIX` source joins two already sorted knot arrays, sorts them with labels, and counts how many knots from each input have been passed. Its numerical work uses only consecutive intervals whose absolute length is strictly greater than the minimum interval. This raw utility returns those complete consumed interval records directly. It does not implement the general `DSORT` routine or preserve its unused equal-coordinate label permutation.

`int md2asm_spline_knot_intervals(const int32_t counts[2], const double *input_knots, const double *weight_knots, const double *threshold, void *records, int32_t *record_count)` takes six addresses in x0 through x5 under the Arm procedure call standard. The retained small route admits each knot count from 25 through 28. The new operational route admits exactly the input/weight count pairs 143/143, 143/144 and 144/144. Other larger pairs remain unsupported. Knot arrays are nondecreasing finite binary64 values from exact positive zero through exact one, with those endpoints present; negative zero is unsupported. Threshold is finite and nonnegative, with positive-zero sign when zero. The selected actual threshold is zero. All arrays are caller-owned, mapped and disjoint from outputs. Integer addresses are aligned to four bytes, and knot, threshold and record addresses to eight bytes. The output allocation has space for 55 records of 32 bytes (1760 bytes) on the small route, or 287 records (9184 bytes) on the operational route. The latter follows the complete bound of one fewer interval than the maximum 288 combined knot positions.

A record contains lower coordinate, upper coordinate and their separately rounded difference as three FP64 words at bytes 0, 8 and 16. Its two int32 words at bytes 24 and 28 give the cumulative input and weight knot counts at the lower coordinate. These are the source's one-based last-knot indices for each array. Output record_count gives the number of complete records; remaining record bytes preserve their incoming preimage. Return zero completes these outputs. Return two rejects null addresses, alignment, counts, knot order/domain/endpoints or threshold before mutation. Correct mapped extents and disjointness are caller preconditions.

Consume every knot equal to the current coordinate before finding the next coordinate from the two input arrays. Subtract current from next, take the absolute value and retain the interval only for the source's strict greater-than threshold test. Update both counts even when that interval is skipped. The source can choose any order for labels inside an equal-coordinate group, because all intervening zero-length intervals are skipped. At the last knot of that group, both cumulative counts are fixed by the complete group membership. Every consumed coordinate, rounded width, index and interval order is therefore retained. The sum of the two returned cumulative indices also gives the original source interval index, so a parent can preserve skipped-interval cumulative operations where required.

The leaf has no stack, allocation or external callable and uses only caller-saved registers. It preserves x18, FPCR and errno. FPCR is zero. Its genuine arithmetic is threshold subtraction, absolute value and comparison, which retains incoming FPSR bits and can add the corresponding source threshold flags. It does not force inexact or any other status bit.
