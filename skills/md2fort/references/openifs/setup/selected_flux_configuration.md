# Selected Diagnostic Flux Configuration

SUCFU and SUXFU set the requests for accumulated and instantaneous diagnostic fluxes. SUMCUF sets the filter controls for monitoring coupling updates. The selected global forecast requests none of these fields or filters, but the source still writes their control records and allocates two zero-length flux arrays. This utility owns those effects without an original module, constructor or procedure in production.

The frozen interface is `int md2asm_initialize_selected_flux_configuration(text, bytes, records, controls)`, with x0 through x3 and status in w0. Text is a mapped buffer of 1 through 262144 bytes. Records is six uint64 words containing address/capacity pairs for TCFU 162272, TXFU 330728 and TMCUF 936. The eight int32 controls are NPROMA, NGPBLKS, LECMWF, NFPOS, LMPHYS, LDPRECIPS, LDPRECIPS2 and NCONF. The selected values are 24,86,1,2,0,0,0,1. Each record address is eight-byte aligned, with its complete stated extent mapped and disjoint from every input and other output. The mapped, nonwrapping payload ranges and complete ownership are caller preconditions.

The first uppercase-exact NAMCFU, NAMXFU and NAMMCUF groups must be empty. The qualified physics output-request parser checks the first selected NAMFPC group. Its bounded supported keys include the actual integer field requests and levels, and exclude named flux arrays CFPCFU/CFPXFU/CFP2DF and LFPCAPEX. Their source declarations are blank name arrays and false LFPCAPEX, and SUFPC does not alter these defaults for the selected integer-only group. Thus SUFPCFU and SUFPXFU leave their flux switches false. Source LMPHYS, LDPRECIPS and LDPRECIPS2 must also be false. This is an explicit selected request domain; other requested flux configurations reject before mutation.

Write only the scalar, array and field-slot bytes assigned on this source path, in SUCFU, SUXFU and SUMCUF order. Preserve the complete unused TYPE_CFU/TYPE_XFU arrays, reset flags, inactive wind-array descriptors, unrelated scalar slots, padding and every other source-unwritten byte. The two flux arrays are GNU rank-three FP64 allocatables of shape 24 by 0 by 86, with bounds 1:24,1:0,1:86. Their byte extent is zero, but each source allocation owns a nonnull allocation token. Allocate one byte for each token, construct the complete 112-byte descriptor and leave that token byte unwritten. No numerical payload is imported or prepared by the driver. RMCUFSP and RMCUFFP remain unallocated because source LMCUF is false and NCUFNR becomes zero. The fixed RMCUFA/RMCUFB/RMCUFI values are source declaration-independent assignments, not captured table input.

Return zero means complete, two means a checked unsupported request/control/freshness/range condition, and one means allocation failure. All request and record checks happen before mutation. Allocation failure frees both new tokens, clears their data pointers and can retain source stores and partial descriptor bounds. A separate `int md2asm_release_selected_flux_configuration(records)` frees only the two new flux tokens and clears their data pointers. It requires one successful live initialization, or the corresponding cleared failure state, and is not a generic finalizer for arbitrary flux records. TMCUF has no new owner on this path.

The direct graph uses only the accepted assembly parsers plus libc allocation/error services. It preserves x18, the saved general and FP registers, FPCR and incoming FPSR, and preserves errno. The source's formatted output, profiling, unused local prefix/level arrays, and inactive filter scratch allocations are omitted utility effects. No active filtering or requested flux calculation is omitted. The complete genuine source control retains its natural I/O status separately. This utility does not claim full SUCFU/SUXFU/SUMCUF body equivalence outside the declared request domain. Caller integration at FIELDS+35304,+197576,+528320 and complete forecast acceptance remain separate.

The initializer frame is 5,952 bytes and the request parser adds 6,240 bytes, for a maximum 12,192-byte owned call chain. The release frame is 80 bytes. Each of two source cases compares 493,936 initialized record bytes and the same complete released bytes, using all-zero and repeated-byte-165 incoming records, with two allocated-address correspondences and zero differences. Their zero-length numerical payloads have zero bytes. Four native initialization/release ABI calls have zero failure masks; ten atomic request/control/capacity rejections also preserve the ABI and all record bytes. An assembly entry loads the actual text, initializes and releases the records, and writes 987,872 exact bytes under those same two pointer correspondences, with libc as its only shared dependency.

Fresh source SUCFU and SUXFU each return FPSR 0, while SUMCUF returns 16. The isolated original `WRITE` of its five 10800-second periods produces that same inexact flag without any coefficient calculation. The utility omits this text formatting and preserves incoming flags. Both source and direct preserve preseeded FPSR 24. Original namelist I/O clears incoming errno 33 to zero; the utility preserves 33. The separate original reference also changes x18, recorded as source ABI mask 2; all direct masks are zero. These effects are retained explicitly in `fresh_source_status_stages.json` and the critical result. No source numerical bytes, flags or outputs are repaired or normalized, and no complete original-body status-equivalence claim is made.

For final-address attachment, the record pairs point at FIELDS+35304, FIELDS+197576 and FIELDS+528320. SUINIF reads LCUMFU and LREACFU at the TCFU-relative offsets161768 and161772, and LXFU and LREAXFU at the TXFU-relative offsets330136 and330168. All four are source-produced false here. TMCUF LMCUF and LREACUF at928 and932 are also false. Keep both flux allocation tokens alive until the FIELDS cleanup, release them before the outer FIELDS record, and retain the complete TMCUF record without a separate numerical owner.
