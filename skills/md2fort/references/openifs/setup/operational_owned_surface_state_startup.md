# Owned Operational Surface State Startup

This component owns the surface metadata, numerical storage, initial defaults and complete surface-file loading for the accepted 9 km input. A surface field stores values at horizontal points; layered soil and snow fields also have depth levels. The caller owns the input physical constants and physics controls. Their complete operational configuration producers, enclosing model construction and forecast remain outside this component.

## Interface and complete storage

The application binary interface (ABI) is `int md2asm_initialize_operational_surface_state(path, constants, physics, surface, trajectory, descriptions, controls, effect)`. Registers x0 through x7 carry the eight arguments, and w0 returns status. The zero-terminated path contains one through 4,095 bytes. Constants and physics occupy complete read-only 520-byte and 448-byte records. The writable surface, trajectory and description records contain 18,224, 408 and 46,080 bytes. All three output records start with zero bytes, except that the descriptions may start with their eight accepted declared counts and a zero tail.

Controls are twelve signed 32-bit words in 48 read-only bytes. They give atmospheric levels, the undefined-field code, positive NSTOP, LWCOU, LWCOU2W, LWCOUHMF, LWCUR, LWSTOKES, LWFLUX, LAQUA, LIFSTRAJ and LECMWF. Their accepted values are 137, minus 999999, a positive NSTOP, 1, 1, 0, 0, 1, 0, 0, 0 and 1. The caller chooses NSTOP; this component does not choose a forecast duration. The physics record has the accepted operational metadata controls, including albedo scheme two and the declared ocean flags.

Effect is a separate writable four-byte signed control word representing the original NPTRSURF reset. It is not an original module variable. Every record is mapped, nonwrapping and eight-byte aligned, except effect, which needs four-byte alignment. The three output records and effect are disjoint from each other and every read-only input, including the path through its zero terminator. Immutable inputs may overlap if both remain valid. The complete bounds and freshness checks occur before construction.

The result owns seventy metadata allocations with 2,137,824 logical bytes and thirty-four numerical allocations with 29,197,024,136 logical bytes. Zero-sized arrays retain their declared nonnull allocation representation. There are ten nonempty numerical arrays, each with 17 rows per block and 388,217 blocks. The last block has eight physical points and nine padding rows. Metadata, descriptor bounds, field names, identifiers, borrowed aliases and every source-unwritten byte retain their accepted child contracts.

## Ordered construction and release

Construct operational surface metadata, allocate all numerical owners, then allocate a 119,632-byte private plan. This plan has a complete 17,096-byte shape adapter, 1,536 owner-table bytes, 98,304 assignment bytes, 64 result bytes, 2,304 conversion-configuration bytes, 96 file-owner bytes, 220 identifiers and twelve alignment bytes. Only the adapter's block width and block count at bytes 5144 and 5160 are read. It does not implement complete geometry. Every extent, product, descriptor offset and file-owner capacity uses 64-bit arithmetic.

Collect live default requests and use the accepted setter to write every assigned row, including padding. The actual supported metadata gives ten nonempty owners and 423 assigned planes. The setter validates its inputs before setting effect to zero and writing fields. Earlier refusal or failure preserves the incoming effect. Once defaults have reset it, a later loading failure retains that source-defined zero. No cleanup silently restores an earlier value.

Construct the conversion configuration from the owned constants. Check all six complete file-owner descriptors and all fifty ordinary plus five layered identifiers and request flags from the live owned metadata. Then call the complete operational surface loader. It owns file decoding, selection, ordered physical conversion and placement. It uses its own 8,236,403,880-byte private workspace. Loading changes physical points only; earlier defaults and source-unwritten storage remain as declared.

A successful constructor frees both private workspaces and retains 104 persistent owners. The paired `md2asm_release_operational_surface_state(surface)` releases numerical owners first, then metadata owners. It clears the source-defined owner data pointers and retains descriptor words and borrowed alias bytes. A borrowed alias must not be read after its owner is released. The caller keeps the three outer records and effect.

## Status and failure

The floating-point control register (FPCR) must be zero. Preserve FPCR, the C error value errno, x18, all required saved integer registers and saved vector halves. The arithmetic status register (FPSR) keeps incoming flags and every flag raised by accepted physical conversion. Protect this status around allocation and release. The constructor uses a 272-byte aligned frame; release uses 32 bytes. No numerical operation is added by this caller.

Return zero after success and two before mutation for unsupported input. Metadata allocation failure returns 101, numerical allocation failure 201 and private-plan allocation failure 301. Internal defaults, configuration and input-plan failures return 401, 501 and 601. A file-loader failure returns 1000 plus its unchanged status. Every failure after construction releases acquired owners and restores all three outer records to their fresh zero state, while preserving the declared effect boundary and the failing stage's status.

The old selected startup source is unchanged. An exact inverse records the new operational provider names, capacities, private plan, supported descriptor tables, controls and effect handling.
