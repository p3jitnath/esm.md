# Live scalar names for the forecast loop

LOCEDELAY is already source-produced by the accepted SU0PHY shared record. The standalone entry owns that 24-byte record at `.Lraw_physics_16`; byte 16 is the int32 LOCEDELAY word. The include `forecast_shared_control_alias.inc.S` declares the original GNU object name over exactly that address. It adds no instructions, storage, copy or initializer. Include it in the same assembly source as the final owned entry. The source producer and its value 1 remain unchanged.

The selected owned Geometry sidecar is 1872 bytes. Its transform control starts at byte 880, and control byte 0 is int32 NPROC. The existing Geometry producer constructs that word and requires the actual public message initialization's process count to equal one before transform setup succeeds. The stable heap address is known only at runtime, so a static ELF data alias cannot name that address directly. `int md2asm_initialize_owned_process_count(live_count, capacity)` takes the address of that already produced four-byte word in x0 and capacity in x1. It checks null, four-byte alignment, range wrapping, capacity 4 and source count 1. It copies the actual word once into `md2asm_owned_process_count`, which shares its four bytes with `__yommp0_MOD_nproc`. Return 0 succeeds and return 2 rejects before mutation. Mapping and input stability are caller obligations. No query, numerical calculation or new source default is inserted.

Call the copy immediately after successful complete Geometry setup, using the live sidecar owner plus 880. Keep the copied count unchanged through the selected serial loop. Its zero process-start storage is an unready preimage; it is not a forecast default. The function has no stack frame, call or dependency and preserves all nonvolatile registers, x18, FPCR, FPSR and errno. The optional LOCEDELAY include can share its source record directly, while NPROC uses this one explicit copy because its live source is a heap owner.

Verification rebuilds only the existing entry with the symbol include and checks unchanged instruction/data sections and BSS extent, plus exact LOCEDELAY address and width. A small static assembly entry checks the process count interface and own data alias without an OpenIFS dependency. Existing source/ABI/public-API evidence supplies the live input meaning and selected process count; no Geometry or physics arithmetic is rerun. Later root integration must pass the actual sidecar address, rather than the standalone verifier's declared count input.
