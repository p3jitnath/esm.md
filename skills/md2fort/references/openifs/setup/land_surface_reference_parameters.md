# Land Surface Reference Parameters

VAL923 sets reference values for land-data interpretation. This direct service owns all 36 scalar assignments made by that routine. Albedo is the fraction of incoming radiation that a surface reflects. Emissivity measures thermal emission relative to an ideal black surface. The source's old/new data switch changes only the minimum and maximum albedo values. The enclosing SUPHMF caller obtains that switch from LSOLV. No original module or callable supplies these production constants.

`int md2asm_initialize_land_surface_reference_parameters(output, capacity, LDNEW)` uses x0, x1 and w2. Output is a writable, eight-byte-aligned 272-byte namespace, with capacity at least 272. Its complete range must be mapped and nonwrapping. LDNEW must be zero or one. Return zero means success and two means rejection before any output store. The caller owns the namespace; no buffer is allocated or released. The raw leaf `md2asm_set_land_surface_reference_parameters_raw(output, LDNEW)` uses x0 and w1 and requires the checked interface.

The packed namespace follows the named assignment order in the source. Each integer has four bytes and each real value has eight bytes. Integers are aligned to four bytes and reals to eight bytes. The source namespace file states every scalar's offset, size and original GNU name. Its 36 original aliases are objects that point into this owned namespace, so direct consumers need no original module address. Other YOMCLI fields are outside this interface. Every output byte is defined in target little-endian order, without rounding, masking or padding repair.

The mask threshold is 0.5, and the missing-data sentinel is the original minus 9998. Sea, ice-cap, desert and lake type codes are one, two, three and five. Roughness lengths and soil depths are in metres. Clay and sand values are percentages, surface resistance is in seconds per metre, and all reflection/emission values and the thermal roughness ratio are dimensionless. Old data uses albedo limits 0.07 and 0.70. New data uses 0.05 and 0.80. All other original literal values stay the same.

The implementation copies the original FP64 literal representations with integer loads and stores. It has no floating-point calculation, stack frame, allocation, operating-system call, library API or numerical fallback. It preserves x18, all required saved registers, aligned stack, errno, FPCR and FPSR naturally. It permits any incoming floating-point control mode because it does not consume floating-point arithmetic. Source informational printouts are outside the quiet interface.

Both genuine VAL923 choices match all 544 named scalar bytes. All 64 physical range, ordering, positive-length and selected-albedo relations pass. Native ABI masks are zero and incoming arithmetic status is unchanged. Four rejected inputs leave the output unchanged, and a complete output ending at a protected page passes. A static assembly entry matches all 272 bytes with no undefined symbol or dynamic dependency and verifies all 36 owned aliases. No complete SUPHMF or forecast is claimed by this checkpoint.
