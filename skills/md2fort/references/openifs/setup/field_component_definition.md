# Selected grid field registration

`md2asm_define_grid_field_component(configuration, next_component, plan, family)` applies the source-defined `DEFINE_GFL_COMP` operation used by the selected eight-field `SUGFL2` path. The configuration is an owned 1,359,136-byte `TYPE_GFLD` layout; the next 368-byte component is its embedded `YCOMP(NUMFLDS+1)` entry at byte 3848. The 112-byte plan contains source input attributes, not a completed model record. Production reads no original module data, type object, virtual table or callable.

The fields are inserted in source order: five water fields, cloud fraction, then two non-orographic gravity-wave diagnostics. Family 0 selects the five water calls, family 1 selects cloud fraction and family 2 selects the last two calls. Each family fixes the original optional-argument presence. All fields use grid-point storage with no derivative or trajectory owner; the first six have a next-time value. Other field families are outside this entry contract.

The caller passes `configuration` in x0, `next_component` in x1, `plan` in x2 and the family integer in w3. All three buffers have 8-byte alignment. The plan is disjoint from the complete configuration, and every declared extent is mapped and writable where required. The function returns 0 on success or 2 before any write when a checked condition fails. It checks the selected prefix counters, previous-component links, family order, buffer arithmetic, canonical logical values and FPCR = 0. The caller supplies fresh declared defaults followed by the accepted component reset before registration; source-unwritten component members retain their incoming bytes.

The plan fields are CNAME (16 space-padded bytes) at 0, IGRBCODE at 16, IFID at 20, NREQIN at 24, LREQOUT at 28, LGPINGP at 32, LMGRID at 36, LTRAJIO at 40, LTHERMACT at 44, LPRECIP at 48, LMASSFIX at 52, LCOMAD at 56 and LNEGFIX at 60. These integers use 32 bits. Six FP64 values follow: REFVALI at 64, R at 72, RCP at 80, RLZER at 88, WENO_ALPHA at 96 and BETAMFBC at 104. Family 2 omits IFID, grid resolution, interpolation and water arguments; its required input count is zero. Family 1 omits the thermal and water arguments. The source's false thermal/water precondition is checked for these two families.

All real values are copied as 64-bit words; this child performs no floating-point arithmetic. The extension defaults retain the original FP64 encoding of −99999.9 and 1.0. Counter increments, MP indices and PREVIOUS/YLASTCOMP links are computed in integer assembly. Existing derivative and trajectory reindexing is inactive under the checked source path. The function uses only x0–x17, does not use a stack, and preserves x18, x19–x29, SP, all SIMD registers, FPCR, FPSR and errno. Condition flags and caller-saved integer registers may change.

The source is `arpifs/module/gfl_subs_mod.F90:91–427`; the selected caller is `arpifs/setup/sugfl2.F90`. Typed layout evidence is retained in `field_component_reset_reference/typed_registration_layout.json`. Verification compares each complete source/direct configuration at the same address, including every raw pointer byte and source-unwritten byte, and checks independent counts, membership and link identities. Source controls remain separate from the standalone production object. This child does not claim the complete SUGFL caller, configuration initialisation or autonomous forecast.
