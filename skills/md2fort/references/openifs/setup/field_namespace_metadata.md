# Main field namespace metadata

This child constructs the fixed field namespace used before the selected T1, T0 and T9 containers attach to live fields. It follows `FIELD_DEFINITIONS:MAIN_FIELD_SET_METADATA` and `FIELD_DEFINITIONS_BASE:SET_FVAR`. A field ID is a one-based integer that selects one of 4,200 records. Each record contains a name, a comment, dimensions, a GRIB parameter code and physical attributes. This is a raw buffer interface; it owns no original OpenIFS object, global variable, type descriptor or method table.

`int md2asm_initialize_main_field_metadata(void *records, size_t capacity, const double attributes[4], int32_t dimensions[2], uint64_t dynamic_name_count)` uses x0 through x4 in that order. The output is 772,800 bytes, comprising 4,200 consecutive 184-byte records. The four input words are RV, RCPV, RCW and RCS, in source units: J kg−1 K−1 for RV and J kg−1 K−1 for each specific heat. They are copied without arithmetic. The dimension output is `{11,2}`. This selected interface requires `dynamic_name_count=0`; the enclosing input producer must establish the absence of the optional `dynamic_namespace` input file. Nonempty dynamic namespaces remain unsupported.

Every address must be nonnull and eight-byte aligned, except that the dimension output needs four-byte alignment. All declared ranges must be mapped, disjoint and nonwrapping; these are caller obligations. The routine checks the basic addresses, alignment, capacity and zero dynamic count before its first output store. Return 0 means success and return 2 means unsupported input, with every output unchanged on rejection. Capacity bytes after the first 772,800 are unchanged.

The record offsets in bytes are name0/16, comments16/128, NDIMS144, D2TYPE148, D3TYPE152, IGRIBCODE156, R160, RCP168, IGFLGMV176 and LDEFINED180. All integer and logical words occupy four bytes. The routine first applies the source declaration defaults to every record, then applies the source literal setters, including the generated decimal field names. These decimal strings depend only on declared integer field IDs. The literal include comes from source text and declared constants, without executing a numerical constructor or importing constructed model state. Twelve live attribute stores preserve the source RV and specific-heat inputs. Default and inactive records are fully retained in the comparison.

The leaf routine allocates nothing and calls nothing. It preserves x18, x19–x29, d8–d15, the stack pointer, FPCR, FPSR and errno. It uses no floating-point instruction. Genuine reference execution with profiling disabled returns unchanged FPCR, FPSR and errno; integer name formatting does not change those observed values. All names and attributes are checked against the separate original method. Profiling and human diagnostic output are outside this raw interface. The enclosing field maps, container ownership and forecast integration remain separate stages, so this child alone gives no complete FIELDS_CONTAIN credit.
