# Original CAMS Aerosol Climatology Setup

This component owns the selected two-dimensional `SETUP_MACC` data stage. A climatology is an average seasonal pattern. The original CAMS NetCDF file supplies eleven aerosol mass fields on 120 longitudes, 61 latitudes and 12 months. Aerosols are small airborne particles. Each value is a column mass in kg m$`^{-2}`$. The species are two black-carbon types, two organic-matter types, three mineral-dust bins, three sea-salt bins and sulfates. Their original variable names and record offsets remain in the assembly field table.

`md2asm_initialize_cams_climatology(path, path_bytes, record, capacity)` receives its arguments in `x0` through `x3`. This is its application binary interface, or ABI. The complete `TEAERC_MACC` record has 6,432 bytes and requires eight-byte alignment. The mapped path has from one through 4,095 characters and a terminator exactly at its declared end. Path and record must be nonwrapping and disjoint. All 22 selected owner addresses and the `IS_INITIALISED` word at byte 6,424 must initially be zero. Other record bytes remain live caller inputs.

The loader opens the original file through the public NetCDF C interface. It checks every required name, three-dimensional rank and ordered file shape `(12,61,120)` before allocating anything. That C order matches the original Fortran shape `(120,61,12)`. The same external NetCDF provider converts the stored numbers to FP64, which stores each real value in 64 bits. The original helper performs no additional physical scaling or permutation for these fields. The assembly introduces no floating-point arithmetic.

Allocation follows the original order. First create the eleven monthly owners and read each complete field. Each has 87,840 values and 702,720 bytes. Close the file, then allocate eleven two-dimensional interpolation buffers with 7,320 values and 58,560 bytes each. Interpolation later computes values between the stored months. These work buffers have no defined values until that later stage writes them, and callers must not read them earlier. The accepted radiation-array allocator provides contiguous one-based GNU descriptors. Private descriptors become public only after all work succeeds, followed by the source `IS_INITIALISED=true` store. Unrelated fields and padding retain every incoming bit.

Return zero means success, one means allocation or file-API failure and two means unsupported metadata or file shape. Every failure closes the file, frees private owners and leaves the complete public record unchanged. `md2asm_release_cams_climatology(record, capacity)` frees only the 22 selected owners, clears their addresses and resets `IS_INITIALISED`. It preserves other bytes and permits repeated release. This explicit lifetime covers the selected two-dimensional owners. Three-dimensional shared storage remains outside this selected route.

The entries preserve the required Arm registers, including `x18`, and keep the stack 16-byte aligned. Initialization uses 2,720 stack bytes and at most 2,832 including the accepted allocator, before external-library work. Release uses 64 bytes. Natural floating-point controls, status and error-indicator effects come from the permitted file library. First-use library state is part of the comparison input. Separate fresh processes both return FPCR zero, FPSR 16 and errno zero. Warm source and assembly calls both return zero flags from a zero seed, while both preserve an incoming seed of 24. No flag is forced. Original information printing and profiling are omitted under the quiet startup policy.

Two complete genuine source cases match 16,773,888 record, payload and release bytes. The 22 declared addresses are joined only after each payload matches. Source-unwritten interpolation payloads use common allocation preimages set before either call, with no later repair. All 1,932,744 finite-mass and axis relations pass. Focused checks cover four allocation-failure positions, protected complete records, thirteen argument or schema failures and zero file-descriptor leaks. A separate ordinary-allocator assembly process reads the original file and matches all 7,731,948 declared output bytes. Its direct dependencies are NetCDF C and libc, with their declared external runtimes. No original OpenIFS library, constructed state, method table or numerical fallback supplies production. Full autonomous forecast acceptance remains separate.
