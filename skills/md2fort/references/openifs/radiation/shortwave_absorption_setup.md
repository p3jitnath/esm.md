# Shortwave absorption setup

This component owns the selected complete SRTM_INIT setup: SUSRTM source maps and reference profiles, SRTM_KGB16 through SRTM_KGB29 input and literal assignments, the source weight table and all fourteen SRTM_CMBGB reductions. Shortwave means solar wavelengths. Its 224 original absorption samples become 112 consumed samples. The selected water-vapour continuum control is zero, as the owned TERAD producer assigns; the original MODIFY_WV_CONTINUUM body does nothing for that control. Other continuum choices are rejected before mutation. The later SUSRTAB, SUSRTAER and SUSRTCOP calls remain separate.

`int md2asm_initialize_shortwave_absorption(bytes,length,out,capacity,continuum)` uses x0 through x4. Input contains exactly 1,332,584 bytes from the actual RADSRTM file, with thirteen big-endian Fortran sequential records. Output is a caller-owned 4,059,736-byte namespace, containing all source-declared band fields and numerical common fields. Both mapped spans must be eight-byte aligned, nonwrapping and disjoint. The output capacity must cover the full namespace. FPCR must be zero for nearest-even arithmetic with gradual underflow. Return zero succeeds; return two rejects before mutation. The public `shortwave_absorption_layout.inc.S` defines each field offset, byte extent, rank, shape and source lower bound; for example, `MD2ASM_SW_B16_KA_OFFSET` names the original absorption field and `MD2ASM_SHORTWAVE_ABSORPTION_BYTES` gives the full capacity.

`md2asm_decode_shortwave_absorption_inputs(bytes,length,out,capacity)` is the integer-only child. It checks every leading and trailing record length before any store, copies each original FP64 file array and its equal-precision model copy, and writes only literal source assignments and fixed SUSRTM maps. It preserves the reduced arrays until their numerical stage. One source constant, band-27 SCALEKUR, is the original compiler-folded FP64 expression 50.15/48.37; the genuine complete-source comparison checks its exact word. It performs no runtime floating-point calculation.

The declared reduced coefficient arrays retain sixteen slots per band although the selected maps consume fewer. The parent writes only each band's selected prefix, preserving all unused slots, source-unwritten WTSM entries, NGN/NGBSW tails and explicit layout padding. These preserved spans total 662,308 bytes. No undefined tail is replaced with a prepared packet. The caller controls incoming storage and its lifetime; a fresh standalone process uses zero BSS.

The numerical child computes weight sums from positive zero in increasing original-sample order and divides each source WT by its group's sum. WTSM remains a declared output, including the final band's first twelve values. Every reduced coefficient starts at positive zero, uses a separately rounded multiplication by the corresponding weight, then adds the rounded product. Solar-flux references use unweighted ordered sums. The accepted longwave ordered-field leaf can express the identical reduction operation through explicit strides. No fused multiply-add, reassociation, approximate operation or numerical fallback is permitted.

The production graph uses direct assembly only. The parent has an aligned 64-byte frame and preserves x18, all callee-saved registers and aligned stack; internal leaves use caller-saved integer and floating-point registers. Numerical work preserves FPCR and errno, and changes FPSR only through the original arithmetic. It allocates no owner. A separate Linux file service can read the actual named RADSRTM file into temporary storage, then call this parent. Filename selection remains an explicit caller responsibility.
