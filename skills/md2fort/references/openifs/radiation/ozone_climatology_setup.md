# Original Ozone Climatology Setup

This component owns the complete serial `SUECOZC` data stage. A climatology is an average seasonal pattern. The original `ECOZC` file supplies ozone mixing ratios at 19 latitudes, 34 pressure levels and 12 months, in parts per million by volume. The file contains 7,752 FP64 values, each stored in 64 bits. The direct loader reads that original file and owns its output storage. It changes no physical value.

The 62,024-byte file has a four-byte big-endian length marker, 62,016 payload bytes and the same four-byte marker at its end. Big-endian storage puts the most significant byte first. The loader checks both markers and the exact file size, then reverses each payload word's byte order with integer instructions. This preserves every FP64 bit, including signed zero, without floating-point arithmetic or rounding. It also loads the 61 already rounded `RPROC` pressure constants from the original source. Their unit is Pa. The first 36 entries run from zero through 110,000 Pa. The remaining 25 entries are source-defined zeros.

The application binary interface, or ABI, defines a call's arguments and register obligations. `md2asm_initialize_ozone_climatology(bytes, length, record, capacity)` receives these arguments in `x0` through `x3`. The complete writable `TEOZOC` record has 33,008 bytes and requires eight-byte alignment. Its rank-three `ZOZCL` descriptor starts at zero, and `RPROC` starts at byte 32,520. The descriptor's initial data address must be null. The input bytes and output record must be mapped, nonwrapping and disjoint. The routine checks their size, overlap and file markers before allocation. It allocates `ZOZCL(19,34,12)` through the accepted one-based radiation-array allocator, fills every payload word and commits the complete descriptor only after success. Every other record byte retains its incoming value.

`md2asm_read_ozone_climatology_file(path, path_bytes, record, capacity)` uses the same four argument registers. The mapped path must have a terminator exactly after its declared length and contain from one through 4,095 characters. Linux `openat`, `read`, `close`, `mmap` and `munmap` services load the file into temporary storage. The reader requires end-of-file after exactly 62,024 bytes, rejecting a truncated file or any extra byte. It reuses the accepted longwave reader's bounded loading and cleanup mechanism. No Fortran input routine or prepared state supplies production.

Both entries return zero on success, one on allocation or file-service failure and two on unsupported input. Every failure leaves the complete public record unchanged and releases private resources. `md2asm_release_ozone_climatology(record, capacity)` frees only the ozone owner and clears its data address. It leaves other bytes unchanged and permits repeated release. Release this owner before destroying its enclosing record.

The entries preserve `x18` and all Arm callee-saved registers, with 16-byte stack alignment. The raw entry uses 224 stack bytes and at most 336 including the accepted allocator. The file route needs at most 464 before external allocation services. Release uses 64 bytes. Integer decoding accepts nondefault floating-point controls and preserves their flags. Success and metadata rejection preserve the library error indicator. Allocation failure retains its natural allocator error. Original informational printing and profiling are omitted under the quiet startup policy.

Three genuine source cases match 384,072 complete record, payload and released-record bytes. Only the declared allocation address differs between separate owners. All 7,814 independent physical and axis checks pass, with 29 native ABI calls, protected buffers, 16 meaningful refusals and allocation failure on both loading routes. A separate assembly executable reads the original file and matches all 62,504 source-defined pressure and ozone output bytes. Its only linked dependency is libc. These checks qualify this component, while the full autonomous forecast remains a separate acceptance gate.
