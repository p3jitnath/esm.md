# Snow Warm Start on the GPU

A warm start initializes snow layers from an existing snow state. The [CPU contract](../../../../md2asm/references/openifs/surface/surfws_ctl.md) retains the profile tables, heat and mass sums, proposed temperatures and conditional four-field commit. Temperature is in kelvin, density is in kilograms per cubic metre, and total and liquid water are in kilograms per square metre. Its mode-two domain supports 1 to 4,096 columns and 5 to 512 layers, including signed strides and partial or empty intervals.

The application binary interface (ABI) keeps all 17 original addresses, the 8,192-byte frame and the original register, alignment and complete-owner rules. All 158 local floating-point sites use the accepted scalar GPU route. Temporary 128-byte call areas preserve live source values and integer condition flags. The original grid, profile-initialization, exponential-profile and mass-adjustment children run in source order through their complete GPU providers. Actual counters and each helper's accuracy limit remain unchanged. The host owns integer storage and control and has no weather arithmetic.

Twenty-four complete original Fortran, selected CPU and GPU calls match 216,832 output bytes and 154,368 read-only bytes. The unchanged independent water, temperature and liquid checks cover 21,356 relations, with 159,296 inactive bytes preserved. Thirteen prewrite controls, newly consumed mathematical arguments, exact provider bindings, native instructions and both source reviews pass. The reused grid child retains its documented original-versus-selected setup status distinction. This parent corpus has no such status difference. Complete forecast and performance acceptance remain separate.
