# Moist-Air Properties On The GPU

Revision 1 adds GPRCP and CTVTOT to the eight accepted [physics forecast calls](../physics_forecast_calls.md), giving ten live PTX routines. GPRCP calculates moist-air gas constants and heat capacities. CTVTOT converts virtual temperature to ordinary temperature. Virtual temperature is the temperature that dry air would need to have the same density as moist air at the same pressure. The [physical formulation](../../../../../formulations/openifs/dynamics/thermodynamics.md) and accepted [GPRCP](../../../../md2asm/references/openifs/dynamics/gprcp.md) and [CTVTOT](../../../../md2asm/references/openifs/dynamics/ctvtot.md) contracts fix equations, data layout, field maps and numerical order.

## Numerical Work And Storage

The [mixture source](../../../../../src/openifs/dynamics/gpu/mixture_properties.ptx) and [temperature source](../../../../../src/openifs/dynamics/gpu/virtual_temperature.ptx) retain each separate FP64 rounding point. FP64 is the 64-bit floating-point format, rounded to nearest with ties to an even last bit. Gas constant and heat capacity have units of joules per kilogram per kelvin. Water fractions use kilograms per kilogram, temperature uses kelvin, and their gas-to-heat-capacity ratio is dimensionless. Signed zero and gradual underflow remain. The qualified [mathematical helpers](../mathematical_support.md) return each rounded result and its new Arm-equivalent status flags.

GPRCP keeps all sixteen original address arguments, including optional outputs and separate or generic water fields. The separate route begins each sum with its dry constant and visits vapour, liquid, ice, rain, snow and graupel, which is soft ice pellets, in source order. The generic route begins with its first active product and adds its dry constant last. Preserve field selection and repeated mappings. Calculate both property sums even when only one output is requested, then calculate the ratio only when requested. This matches the accepted production CPU arithmetic. Original Fortran can skip an unrequested sum, so its per-call flags at that optional-output edge are a separate inherited limit.

Each entry takes two unsigned 64-bit addresses, the original argument vector and the [64-byte call context](../gpu_call_context.md). Every original argument occupies an eight-byte vector slot. Matrices have $`K`$ columns and $`N`$ layers, with columns contiguous. Preserve all selected and inactive cells in the complete allocated $`K`$ by $`N`$ buffers. The original signed 32-bit dimensions, finite arithmetic, alignment, nonoverlap and complete buffer limits remain those of the linked CPU contracts.

The immutable 64-byte routine record holds eight words. They identify the actual global YGFL object, the live RD, RV, RCPD, RCPV, RCW and RCS addresses, then the actual generic-field capacity. Load the YGFL object through its assembly-owned pointer slot. In this production binding, modes zero and nine use its `NDIM` capacity, while mode one uses `NDIM1`. Other modes need a separate caller-capacity contract before host admission. The qualified numerical component has its broader declared field-map coverage.

CTVTOT retains its six original address arguments. Host assembly allocates a private eight-byte-aligned R array of exactly $`8KN`$ bytes, calls the original sixteen-argument GPRCP wrapper with only its R output requested, then launches temperature conversion. The GPU separately rounds RD times virtual temperature, divides by the produced R value and stores ordinary temperature. The private R owner remains live and disjoint until synchronization, then host assembly frees it. Empty work needs no allocation. Both mixture sums and their flags remain present in the nested child call.

One thread owns one column and layer. Use 128 threads per block and enough blocks to cover all $`KN`$ cells. Threads outside the rectangle or selected columns return before numerical-array access. New flags combine by integer OR. Basic arithmetic writes no mathematical error event, preserving incoming errno. No host calculation or original OpenIFS numerical fallback supplies a stage.

## Original Host Interface

The [host assembly](../../../../../src/openifs/support/gpu/mixture_forecast_calls.S) replaces all five selected GPRCP providers with one original-interface body. Their names are `md2asm_scan_gprcp_body_7358525`, `md2asm_lassie_gprcp`, `md2asm_hydrostatic_private_gprcp`, `md2asm_lagged_grid_gprcp` and `md2asm_ec_mixture_7358525`. CTVTOT retains `md2asm_scan_ctvtot_body_7358525`. Other assembly adapters preserve their existing call order.

An application binary interface, or ABI, specifies argument locations and preserved registers. The 768-byte frame reserves bytes 0 through 63 for the nested GPRCP stack arguments, saved registers 64 through 167, the original vector 192 through 319, context 320 through 383, record 384 through 447 and service-state storage 512 through 559. Preserve `x18`, `x19` through `x28`, the frame pointer, return address, required saved vector-register parts and 16-byte stack alignment. Original stack arguments are copied from the incoming stack before service calls.

Assembly preserves the Arm floating-point control register (FPCR), numerical status register (FPSR) and system error value (`errno`) across `malloc`, `free` and [CUDA services](../cuda_runtime.md). GPRCP and CTVTOT successful-launch counters advance after synchronization. Calls are serial and nonrecursive. Invalid active shapes, unsupported capacity modes or a CUDA failure stop the process. Link these host objects before the CPU archives and confirm that all six replaced provider members are absent. Assemble PTX with `ptxas -c -arch=sm_90 --fmad=false`, then link its unchanged qualified helper objects with `nvlink`.
