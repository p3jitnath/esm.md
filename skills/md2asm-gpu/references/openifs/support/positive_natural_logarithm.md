# Positive natural logarithm on the GPU

The natural logarithm of a positive number is the exponent of the mathematical constant e that gives that number. This GPU-backed assembly entry exports `md2asm_log_positive_normal` and preserves the frozen [original numerical contract](../../../../md2asm/references/openifs/support/positive_natural_logarithm.md) from Arm optimized-routines v26.01. FP64 means the 64-bit floating-point format. The dimensionless input must be finite and at least 2 raised to −52. The largest finite FP64 value is supported. Other inputs and a nonzero floating-point control register, FPCR, stop with exit 116 before the accepted-call counter changes. This bounded entry is distinct from the general public `log` function.

The [GPU host](../../../../../src/openifs/support/gpu/positive_natural_logarithm.S) keeps the original bit-based range selection, 128-record lookup, near-one branch and ordered polynomial. Every original FP64 operation calls a qualified GPU scalar entry through the complete-state [preserved-state header](../../../../../src/openifs/support/gpu/preserved_scalar_calls.inc.S). Each addition, subtraction and multiplication retains its separate nearest-even rounding point, gradual underflow and signed-zero rule. No fused arithmetic, reassociation or reduced precision is used. This is the actual qualified GPU numerical wrapper. The unchanged CPU [coefficient table](https://github.com/p3jitnath/esm.md/blob/28940eb213fb69ab2b64cc0bf154ca733f7c1c21/src/openifs/support/positive_natural_logarithm_tables.S) supplies 4,240 bytes of read-only coefficients, aligned to 16 bytes; it performs no logarithm calculation.

The application binary interface (ABI) takes and returns the value in `d0`. It preserves `x18`, the required saved general registers and the required low halves of vector registers `v8` through `v15`. The original leaf has no permanent frame; each GPU operation uses an additional 1024-byte frame aligned to 16 bytes and saves all general and full vector registers before restoring the original destination. No input buffer is written. The original serial accepted-call counter advances once. FPCR is unchanged; the floating-point status register, FPSR, retains incoming flags and adds the frozen arithmetic flags, while errno, the runtime error number, is preserved.

The implementation requires the qualified startup signed-integer-to-FP64 mode and the qualified lake scalar add, subtract and multiply entry, plus their device dependencies and the common launch service. Shared code, coefficient and counter owners are linked once. The full source, data, symbols and relocations are bound to the selected provider; the compact host reproduces the accepted binary object.

The focused component check passes 96 CPU and 96 GPU calls with identical result, immediate status, errno and register records. Ninety-six independent 140-digit logarithm relations observe a maximum error of about 0.489 units in the last place, where one unit is the spacing between adjacent FP64 values near the result. This sample is not a universal error bound. The complete initialisation check in [physical setup](../setup/physical_setup.md) also passes with this GPU provider. The retained source error limits remain unchanged. These records establish component acceptance and make no whole-forecast, routine-credit or timing claim. The Arm copyright and dual-licence notice remain in the source.
