# Convective Cloud And Rain Diagnostics On A GPU

This source implements the complete original CUCCDIA calculation. It records cloud-top and cloud-base levels and a rain diagnostic for convective columns. Vapour and liquid fractions use kilograms per kilogram; mass and rain fluxes use kilograms per square metre per second. The equations are in [the convective cloud formulation](../../../../../formulations/openifs/physics/convective_cloud_diagnostics.md), and the original ordered CPU rules are in [the CUCCDIA contract](../../../../md2asm/references/openifs/physics/cuccdia.md).

The source either replaces the three diagnostics or accumulates them according to its radiation schedule and logical flags. Each selected convective column uses the supplied cloud levels, then combines base vapour and liquid, top vapour, upward mass flux and the larger of the computed and supplied rain rates. Accumulation preserves the original cloud-level maxima, minima and top-level sentinel rule. Its reciprocal interval weight is evaluated before the empty-column test, so a call with no payload work can still raise the original inexact status.

The application binary interface (ABI), which defines arguments and preserved machine state, retains eighteen addresses in the original order. They describe three configuration objects; first column, last column, column and level counts and step; supplied cloud base and top and convection flags; vapour, liquid, upward mass and rain; and the returned rain, cloud top and cloud base. The column count is from zero through 4096 and the level count from zero through 512. Active cloud levels lie within their column, with the top index no greater than the base index. Source logical words use zero or nonzero, and source signed division defines the radiation remainder. Skipped columns and source-unused payloads remain unchanged.

The device uses 64-bit floating-point (FP64), separately rounded after every original operation, including the exact stored word for 0.05. Numeric maxima preserve the source signed-zero rule. No fused operation, reassociation, reduced precision or approximate model arithmetic is used. The shared context retains incoming status and error events and joins natural new flags. This routine has no elementary-function or model counter event.

One block with one thread executes the complete calculation with zero shared memory. The 192-byte record contains eighteen owner capacities and zero reserved words; no scratch is needed. Complete outputs and the mutable context are disjoint from consumed owners and metadata, and all bounds, index and finite-value checks precede output writes. The metadata path admits the convection flags before numerical owners. When every selected flag is zero, unused level, input and output payloads may be absent while the scheduled reciprocal remains. The Arm boundary retains private entry `md2asm_cuccdia`, preserves the original eighteen-argument interface and numerical state and accepts only a serial caller.

Qualification passes 518 protected GPU and 518 selected CPU calls, with 257 original Fortran placements, across 1,276,768 complete output bytes with zero differences. The 65,746 distinct exact-rational cloud, rain and inactive-cell relations include signed zero, subnormal outputs, cancellation, negative radiation frequency, empty work and the final legal index of a 4096-by-512 field. Fifty-five prewrite or early-return controls and five ordinary device-memory graphs pass. Immediate status, errno, preserved registers, readonly bytes and guard padding agree. The actual selected 360-byte provider, three new native functions and independent numerical and host source reviews also pass. The native integer remainder uses the assembler's corrected integer-division sequence; its reciprocal seed does not replace a model FP64 operation. These checks qualify one component and give no full GPU forecast or timing claim.
