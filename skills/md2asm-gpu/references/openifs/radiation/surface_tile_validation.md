# Surface Tile Fraction Validation

A surface tile is one part of a model grid cell, such as water, soil or vegetation. Its fraction has no unit. The radiation preparation routine, called RADPAR, prepares radiation inputs and checks these fractions before it calls the surface calculations. The [physics formulation](../../../../../formulations/openifs/radiation/radiation_preparation.md) remains unchanged.

The [direct GPU stage](../../../../../src/openifs/radiation/gpu/surface_tile_validation_entry.ptx) keeps the complete original validation loop on the device. It adds the tile fractions in their original order, checks the sum against the original limit of 1.01, then checks the two separately rounded subtractions that form the remaining fraction. A negative fraction, an excessive sum or a negative remaining fraction reaches the original first error exit. The original comparison rules also determine how a not-a-number value reaches that exit.

The host makes one request for this loop. The GPU keeps columns and tiles in their original order, so the floating-point state at the first error remains exact. The preparation, physical constants and later radiation calculations retain their accepted providers.

The application binary interface, or ABI, defines the arguments and preserved registers. The entry receives two 64-bit device-visible addresses for its argument vector and call context. Its launch has one block, one thread and no shared storage. The vector points to an 832-byte source register state, a 640-byte environment and a 16-byte completion record. The context uses revision 1 and a 96-byte capacity record. The existing setup mode 85 selects the checked transport. The caller supplies the complete original source frame and valid array bounds. The arrays use column-major order, with neighbouring columns next to each other. Readonly arrays can share storage under the accepted transport rules, while mutable protocol owners remain separate.

The source state records all general and vector register words, including upper vector halves, so the complete original result can be compared. The return preserves the original floating-point flags, integer condition flags, error indicator, counter owners and first error position. The stage changes no model input array. Its production host adapter restores the normal source result and continues at the original surface branch. On a source error, it calls the original abort service, as the source parent does.

The original Arm-loop comparison passes 13 critical controls with all 832 source-state bytes exact, including first error exits. The complete protected parent passes 28 calls across 14 conditions, with 131,376 canonical output bytes, unchanged input owners, exact numerical state and all six actual counters. The original 7,941 independent physical relations remain applicable. This component evidence does not establish a complete autonomous forecast runtime.
