# Complete Ordered Radiation Field Reduction on the GPU

The internal `md2asm_reduce_longwave_field` call combines absorption samples into groups. The original longwave and shortwave parents supply 186 field plans. The GPU phase performs each complete field in one launch. It retains the mathematics and units in the [longwave](../../../../md2asm/references/openifs/radiation/longwave_gpoint_reduction.md) and [shortwave](../../../../md2asm/references/openifs/radiation/shortwave_absorption_setup.md) contracts.

The Arm application binary interface, or ABI, uses `x0` for source, `x1` for destination, `x2` for positive 32-bit group counts, `x3` for group count, `x4` for weights or zero and `x5` for five 64-bit shape words. Those words give cell count and source-cell, source-term, destination-cell and destination-group strides in bytes. Original parents provide complete mapped, aligned and nonwrapping spans. FP64 spans need eight-byte alignment; counts need four-byte alignment. The selected plans contain at most 1175 cells, 16 groups and 16 terms. The internal call has no declared return value.

One GPU thread visits cells, groups and terms in increasing source order. Each group sum starts at positive zero. A weighted term uses a separately rounded multiplication before its addition. The body writes a group before reading the next group, then advances the cell bases. It uses the unchanged `md2asm_gpu_mul_status` and `md2asm_gpu_add_status` functions that supplied the previous scalar calls. It does not fuse, regroup or approximate arithmetic, and it does not add a finite-value preflight.

The transport keeps the original model addresses live. Source, destination and weights can share storage, and all write/read dependencies retain their serial order. The entry does not require the model spans to be mutually disjoint. The selected parents keep count controls outside written storage. Only the five shape words are copied at entry, matching the original leaf's initial loads. The body rereads counts for every cell and weights for every term.

The private vector has 96 bytes. It contains source, destination, counts and optional weights at bytes 0, 8, 16 and 24; group count at 32; the five shape words at 40 through 79; and two zero words. The 64-byte context contains error at zero, flags at eight, event at sixteen and a capacity-record address and length at 48 and 56. The 64-byte capacity record holds vector, context, source, destination, count and optional-weight extents, followed by two zero words. Extents include strided holes, whose bytes remain unchanged. The private vector, context and capacity record are mutually disjoint and disjoint from model spans. The launch uses one block, one thread and zero shared memory.

The host uses an aligned 1536-byte frame. It preserves `x18`, the saved registers, complete vector registers, FPCR and errno, and joins newly raised flags into incoming FPSR. It retains the former scalar route's refusal for nonzero FPCR and an active OpenMP parallel region. No counted product-sum operation occurs, so actual FAST and WIDE counters remain unchanged. The entry performs the original arithmetic on nonfinite values through the accepted IEEE functions.

The changed component passed all 115 longwave and 71 shortwave fields against retained genuine records: 5,289,088 complete output bytes and 3,148,928 unchanged input bytes, including holes and source-unwritten storage. Twelve small controls matched the unchanged GPU leaf across complete 512-byte images, including dependent source/output aliases, live weight/output aliases, shape/output aliases, nonfinite values and seeded flags. Strict ABI, FPCR, errno and actual counter values at wrap seeds passed. Fifty-four raw entry controls matched whole 8192-byte images. Native inspection confirms two arithmetic call sites, eight range-check calls, one host launch and no arithmetic outside the accepted numerical helpers.

The existing independent evidence is reused: 3443 longwave table and weighted-average relations, 2770 exact rounded sums, 1746 shortwave physical relations and 1448 exact rounded sums. No CPU reference or physical model was run for this transport change. Each numerical process had an external 14.13-second limit. Local commands, source pins and raw results remain outside the published tree. These component checks do not establish complete forecast acceptance or a comparative timing result.
