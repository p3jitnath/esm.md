# Two-Stream Radiation Coefficients on the GPU

Revision 1 preserves the complete original `radiation_two_stream::calc_two_stream_gammas_sw` and `calc_two_stream_gammas_lw` calculations. Their selected production names are `md2asm_mcica_gamma` and `md2asm_mcica_lw_gammas`. The [shortwave](../../../../../formulations/openifs/physics/two_stream_gammas_sw.md) and [longwave](../../../../../formulations/openifs/physics/two_stream_gammas_lw.md) physical inputs and their [shortwave](../../../../md2asm/references/openifs/physics/calc_two_stream_gammas_sw.md) and [longwave](../../../../md2asm/references/openifs/physics/calc_two_stream_gammas_lw.md) CPU contracts define these dimensionless coefficients. Shortwave describes solar radiation. Longwave describes thermal radiation. The assembly source is [two_stream_coefficients.ptx](../../../../../src/openifs/radiation/gpu/two_stream_coefficients.ptx).

Let $`w`$ be the single-scattering fraction, $`g`$ the asymmetry factor and $`\mu`$ the solar cosine. RN rounds a single operation to FP64, with nearest-even ties. The shortwave route separately rounds $`f=0.75g`$, $`a=1.25+f`$, $`b=aw`$, $`\gamma_1=2-b`$, $`c=0.75-f`$, $`\gamma_2=cw`$, $`d=\mu f`$ and $`\gamma_3=0.5-d`$, in that order. The longwave route uses the exact FP64 words `L=0x3ffa8f5c28f5c28f` and `H=0x3fea8f5c28f5c28f`, then separately rounds $`f=Hw`$, $`a=1+g`$, $`b=af`$, $`\gamma_1=L-b`$, $`c=1-g`$ and $`\gamma_2=cf`$. Preserve every signed zero and subnormal value. Forbid model fusion, reassociation, reduced precision and approximate model arithmetic.

Each complete entry takes two unsigned 64-bit addresses: the original argument vector and the [common call context](../gpu_call_context.md). `md2asm_gpu_calc_two_stream_gammas_sw` uses seven original address slots: signed int32 count, FP64 solar cosine, then the omega, asymmetry, gamma1, gamma2 and gamma3 descriptors. `md2asm_gpu_calc_two_stream_gammas_lw` uses five slots: count, then omega, asymmetry, gamma1 and gamma2 descriptors. There are no hidden string lengths. A descriptor occupies 64 bytes. Only its data address at byte0 and signed element stride at byte40 select cells; stride zero means one. Preserve every other descriptor byte without adding its stored offset or lower label to an address. Count needs four-byte alignment; every other consumed owner needs eight-byte alignment. Each reached numerical value occupies eight bytes.

A nonpositive count returns before consuming the solar value, descriptors or numerical arrays. For a positive count, every reached range must fit signed 64-bit address arithmetic and actual mapped allocations. A one-cell range can use an otherwise unused extreme stride. Output bounding owners must be separate from one another, the input owners, all descriptors, the argument vector, count, used solar scalar and context. Input owners may overlap each other. All metadata, pointer and overlap checks finish before public writes. The caller owns complete mapped allocations and keeps read-only metadata stable through synchronization.

A positive one-dimensional grid and block, with all y and z dimensions one, is supported. Each thread traverses independent indices at the total grid stride, loads both input words, computes the full point and stores gamma1, gamma2 and, for shortwave, gamma3 in that order. Visible functions `md2asm_gpu_calc_two_stream_gammas_sw_fp64` and `md2asm_gpu_calc_two_stream_gammas_lw_fp64` expose the same array interface for an on-device parent. There is no scratch allocation or specific record. Preserve context bytes32 through63. A prior context error returns unchanged. Error361 denotes an unsupported launch or context revision. Error362 denotes unsupported active metadata, reached bounds or owner overlap.

The visible numerical children `md2asm_gpu_two_stream_gammas_sw_values(omega_word,asymmetry_word,solar_word)` and `md2asm_gpu_two_stream_gammas_lw_values(omega_word,asymmetry_word)` take raw 64-bit words. Each returns one aligned 32-byte parameter object: gamma1 at0, gamma2 at8, gamma3 at16, newly raised software Arm flags at24 and error-write event zero at28. Longwave's unused third result is positive zero. These children let a radiation parent own the full sequence without a host launch per point. Array entries join flags by integer atomic OR at context8. Basic arithmetic preserves the error value and context16. GPU hardware has no native Arm FPSR.

The [full mathematical helpers](../mathematical_support.md) retain every rounding point and source-special-value rule. A pre-emission 210-call original CPU probe, across widths1,2,3 and five signed, zero or padded descriptor layouts, fixes the product operand order. Both shortwave and longwave g-based products give the a or c operand first NaN priority; shortwave's solar product gives the solar operand first priority. Signalling NaNs precede quiet NaNs in original operand order, keep their selected sign and payload, become quiet and raise invalid. Invalid arithmetic without an input NaN gives the qualified Arm default quiet NaN. Physical cases use $`0\leq w\leq1`$, $`-1\leq g\leq1`$ and $`0\leq\mu\leq1`$; special-word checks qualify numerical semantics separately.

The component gate passes 852 complete calls: 640 retained physical calls, two new grid-stride calls and 210 replays of the frozen original special probe. It compares 397,432 result bytes, 139,591,680 complete output and guard bytes and 502,530,048 read-only input and metadata guard bytes, with zero differences. All 852 immediate FPCR, FPSR and error observations agree. Independent exact-rational checks on returned GPU values pass 48,629 coefficient relations, and the gate retains 1,822 nonzero subnormal outputs. A further 97 controls cover 87 refusals, two prior errors, four empty calls and four valid one-cell extreme-stride cases, preserving 57,933,824 complete owner and guard bytes. Raw controls add no separate host error-value acceptance; the numerical gate uses the qualified common runtime.

PTX is emitted directly from the equations and ordered contract, then assembled with CUDA12.6 `ptxas -c -arch=sm_90 --fmad=false` and linked with `nvlink`. The numerical bodies call unchanged qualified add, subtract and multiply helpers. Native instruction inspection finds no direct model DADD, DMUL, DFMA, MUFU, FADD, FMUL or FFMA. The assembler uses 18 HFMA2.MMA instructions with both multiplicands fixed at zero and only literal inputs to construct constant register words; no model value enters those instructions. This constant construction does not change the FP64 model arithmetic. Local records retain the source, tools, original probe, failures, hashes and independent peer. Component acceptance does not establish complete forecast agreement or a timing result.
