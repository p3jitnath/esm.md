# Ozone on Model Pressure Layers on the GPU

Revision 1 implements complete RADOZC from [ozone climatology](../../../../../formulations/openifs/physics/ozone_climatology.md). The climatology supplies average ozone mass fractions on latitude and pressure coordinates. The output is a layer amount in Pa times kg/kg. Preserve the selected `md2asm_grid_ozone_layers` calculation and its original normal and aquaplanet modes.

Use the sine latitude of the first selected source column. Retain the descending inclusive latitude search, including its original tie rule. Normal edge intervals still compute their weight before copying the lower profile. Aquaplanet endpoint branches copy without a weight. Blend each required profile value with separate operations, then form the original pressure slopes. For each selected model column, interpolate its pressure faces or copy the final climatology value beyond the last pressure. Each layer amount is its pressure thickness times the sum of its two rounded face values, then times one half. Preserve every FP64 operand order and rounding point.

The eleven original addresses name the 33,008-byte ozone object, first column, last column, allocated source columns, model layers, source spacing, destination columns, destination shift, model face pressures, sine latitude and output. Seven integer controls use four bytes each. Real cells use eight bytes with columns changing fastest. Source and destination columns each range from 1 to 4,096 and model layers from 0 to 4,096. Spacing is positive and every selected destination index fits its output. Empty ranges or zero layers return before numerical work, following the selected CPU boundary.

The object contains 64 latitudes at byte 776, a 64-by-61 ozone table at byte 1,288 and 61 pressure coordinates at byte 32,520. The live LAPE word selects 19 latitude points and 36 pressure levels in normal mode or all 64 and 61 in aquaplanet mode. Consumed coordinates are finite and strictly increasing. Selected model pressures increase and begin within the declared pressure domain. Sine latitude lies from minus one to one. Consumed ozone values are finite and nonnegative. Unused profile cells retain their original bytes and need no numerical inspection.

[The device entry](../../../../../src/openifs/radiation/gpu/ozone_pressure_layer_entry.ptx) takes the original vector and common 64-byte context. Its 16-byte record holds the live LAPE address and capacity. Nonempty work needs 1,024 private bytes for the rounded profile and slopes. Validate all complete owners, destination mappings, products, alignments and mutable overlaps before scratch or output stores. Readonly owners may overlap. Integers require four-byte alignment and real cells and metadata eight. Launch one thread in one block with no dynamic shared memory. The 32-byte pure return contains flags at 0, error at 4, event zero at 8, a completed-call observation at 16 and reserved zero at 24.

[Host assembly](../../../../../src/openifs/radiation/gpu/ozone_pressure_layer_calls.S) keeps the original eleven-address ABI, actual mode and serial-state query. Its 640-byte frame preserves x18, saved registers, aligned stack, FPCR, inherited FPSR and errno across allocation, launch and release. No original OpenIFS or Arm numerical fallback supplies a stage.

The component passes 1,248 protected GPU placements over 2,835,456 complete output bytes and 148,070 distinct independent physical relations. Fifty-four controls, source-unused success routes, an ordinary-device graph with fourteen address relocations, current provider identity, native inspection and two source peers pass. Nonempty original, selected-CPU and GPU numerical status agrees. In 624 empty placements the original setup flags differ, while GPU status exactly follows the selected CPU early return. This explicit boundary qualification does not establish complete RADINTG or GPU forecast acceptance.
