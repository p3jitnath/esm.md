# Complete spline operator matrix phase

The [scientific contract](../../../../md2asm/references/openifs/setup/spline_operator_matrix_contract.md) defines the unchanged equations, interface and accepted domain.

An owner is a complete allocated buffer. A stride gives the distance between neighbouring stored values. FP64 is the 64-bit floating-point format. The application binary interface, or ABI, fixes argument registers and the registers that a call must preserve. The [GPU calling rules](../gpu_call_context.md) define the shared context and status fields.

This GPU implementation moves the complete numerical matrix span after the unchanged knot-interval preflight into one cooperative GPU call. A spline represents a smooth vertical function with cubic polynomial pieces. The matrix integrates the product of a weight spline with an input spline, its derivative or its integral. These three choices are kind zero, one and minus one. Coordinates, coefficients and entries are dimensionless. The original six-address parent ABI, original guards and the knot-interval child stay unchanged; the existing coarse basis, knot and piece providers remain separate and are reused once.

The parent accepts the complete existing contract: 21 through 24 input and weight bases, each offset from zero through basis count minus 21, spline order four, 21 by 21 output, surface flag zero, exact positive-zero interval threshold and sample bounds positive zero and one. The six read-only owners contain two 16-word transforms, two knot arrays of basis count plus four words and two coefficient arrays of basis count times 16 words. The retained complete cases explicitly share read-only transform and knot owners. Such read-only aliases are allowed. The output and workspace are disjoint from each other, all read-only inputs and private transport owners. All consumed values and intermediates retain the original finite/provenance caller preconditions. No physical bound or stored numerical result is added.

The unchanged knot utility first validates both complete knot arrays and produces up to 55 interval records in the first 1760 workspace bytes. The GPU phase clears all 441 output words, then follows every original source knot position. For kind minus one it initializes and updates complete input and weight cumulative prefixes, including source additions at repeated or skipped knot positions. The four workspace regions start at bytes 1760,12512,23264 and 23456, with reserved capacities 10752,10752,192 and 192 bytes. Only the original required prefixes change. All interval records and unused workspace bytes retain their incoming bytes.

For each retained interval, coordinates use numerator subtraction, denominator subtraction and division in the original order. Local conversion repeats each original sample division, subtraction, multiplication and addition before Horner evaluation; its four-term matrix products begin at positive zero and accumulate in increasing sample order. Polynomial products accumulate valid terms in increasing first-factor index. Integration divides by the exact small integer degree; differentiation multiplies by that degree. Main matrix additions, the separately rounded cumulative product and the additional earlier-input contributions keep the source loop order. The original unused coordinate differences are still evaluated because they can change floating-point status. There is no reassociation, fused operation, approximation or reduced precision.

The private header has 256 bytes and eight-byte alignment. Four-byte words at offsets 0,4,8,12,16,20 and24 contain kind, input basis count, input offset, weight basis count, weight offset, total knot count and interval record count. Word28 is zero. Eight addresses at32 through88 contain the six read-only owners, output and complete workspace; corresponding capacity words start at96. Bytes160 through255 are zero. The output status owner has32 bytes and returns the original parent result code in its first word. The vector has16 bytes, the context64 and the record64. The record retains the qualified seven-owner scalar transport layout with mode zero and two private counter owners. No event counter is changed.

The phase uses one block with 32 threads. Threads zero through twenty each own one complete weight-basis column. Integral prefixes for separate input bases also use separate threads. Each thread retains the original knot, sample and contribution order within its column, so no ordered sum is divided among threads. Block barriers separate producers from consumers, and inactive threads join every barrier. A private 23,648-byte workspace and 3,528-byte output copy keep speculative stores separate from the public buffers. On success, the phase copies every byte back. If a child rejects a local polynomial or contribution, the phase discards private results and flags, then runs the literal serial tail on untouched public owners. This reproduces the first partial return and its original completed stores. Admission validates all private owners, all eight nested extents, mutable-owner separation and source interval metadata before numerical writes. Source metadata is supplied only by the unchanged knot utility; raw controls separately test invalid metadata. Return zero completes the matrix. Parent return two remains the original preflight rejection before output or workspace mutation. A local-polynomial or contribution child rejection returns three after the original completed writes, so callers discard those partial owners. Floating-point flags remain sticky, FPCR remains zero, errno and x18 are preserved, and every helper return is read on its own call path before the next helper call. The private Arm phase preserves all general registers and full vector registers required by the original continuation, then installs only its original integer result.

The [parallel phase](../../../../../src/openifs/setup/gpu/spline_operator_matrix_parallel_columns.ptx) is selected by the [Arm adapter](../../../../../src/openifs/setup/gpu/spline_operator_matrix_phase_calls.S). Keep the [callable serial module](../../../../../src/openifs/setup/gpu/spline_operator_matrix_phase.ptx) once for unchanged public and nested callers. It supplies both the original entry and its callable numerical body. The shared IEEE-status and scalar-arithmetic providers remain single dependencies.

Thirty-two retained paired cases match all 112,896 saved matrix bytes and 756,736 workspace bytes. Eleven complete raw images match 379,016 bytes, including both partial-return paths, read-only aliases, refusal before writes, status, preserved registers and actual counter wrap. The unchanged independent 80-digit integration checks remain applicable. Detailed records stay local. These component results do not establish complete forecast acceptance or a comparative runtime.
