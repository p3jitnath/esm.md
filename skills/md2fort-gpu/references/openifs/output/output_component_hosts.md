PTX is the directly written GPU assembly. FP64 is the 64-bit floating-point format. Fullpos prepares fields for output, and GRIB is a weather-data file format. The component contracts below remain authoritative for physical units, supported inputs, array shapes, complete output bytes and failure behaviour.

A norm measures the size of a field. Grid norms keep ascending global-cell order, the exact missing-data sentinel and the separate raw and displayed results. Spectral norms keep each coefficient square, wave multiplicity, metric, sum and square root in its original order. Packing retains field order, raw data words and the original signed integer conversions. The reference atmosphere keeps the original pressure search and later-index tie rule. The remaining sources retain Fullpos configuration, request selection, GRIB metadata and reporting inputs. The reporting route admits steps zero through 25, matching its qualified selected provider.

The application binary interface, or ABI, defines argument registers, preserved registers and buffer bounds. Original interfaces and storage frames stay unchanged. The [shared macros](../../../../../src/openifs/support/gpu/preserved_weather_calls.inc.S) preserve live registers around each inserted call. The 128-byte and 256-byte forms retain their original saved words; the 256-byte form also saves all sixteen upper FP64 registers before restoring them ahead of the result. The 1024-byte form saves all 31 general registers, all 32 complete vector registers and the integer condition flags. It installs only the original destination after restoration. Scalar and integer result widths stay unchanged.

Each FP64 operation uses the original separate rounding point, nearest-even rounding, gradual underflow and signed zero. Fused operations, approximate operations, reassociation and reduced precision are forbidden. The original caller domain still applies to each mathematical helper. The [numeric minimum and maximum helper](../support/numeric_minimum_maximum.md) retains the complete NaN domain where the original numeric operators require it. A NaN is a floating-point value that represents an invalid or undefined numerical result.

Link each shared scalar, conversion, pressure and logarithm provider once, using its accepted GPU source and counter owners. A CPU mathematical implementation does not supply an omitted GPU calculation. Keep the original public file-format, transform, allocation and formatted-I/O interfaces. The complete transitive provider list and frozen source bindings remain in the local publication packet.

The three existing component packets cover the four pressure/norm sources, four normalization/packing/atmosphere sources and fourteen setup/output/reporting sources. Their complete numerical owners, immediate status, actual counters, register obligations, critical bounds and independent physical evidence pass. For exact binary inputs, the original SPNORMD profiling calls to GSTATS can set the inexact flag, value 16 in the Arm floating-point status register (FPSR), while the unchanged selected Arm and GPU calls return zero. This inherited profiling difference is recorded separately; immediate selected CPU/GPU status must agree exactly without clearing flags. Each compact host produces an entire ELF object identical to its accepted expanded source; ELF is the object-file format used by the assembler and linker. This source-layout check reuses the accepted numerical records. The forecast loop, forecast step, output controller and output-grid caller remain separate pending complete-call checks. Component qualification supplies no complete-forecast or performance result.
