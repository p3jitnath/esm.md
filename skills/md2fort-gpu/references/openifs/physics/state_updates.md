# GPU Physics State Updates

Revision 1 supplies four complete physics calls: `STATE_UPDATE`, `STATE_INCREMENT`, `UPDATE_FIELDS` and `QNEGAT`. Their physical inputs are [state time update](../../../../../formulations/openifs/physics/state_update.md), [state increments](../../../../../formulations/openifs/physics/state_increments.md), [field transfer](../../../../../formulations/openifs/physics/field_transfer.md) and [humidity floor](../../../../../formulations/openifs/physics/humidity_floor.md), all revision 1. FP64 means the 64-bit floating-point format. Every multiply, add, subtract and divide rounds separately to nearest with ties to even. Preserve signed zero and gradual underflow. There is no fused arithmetic, reassociation, reduced precision or host-supplied numerical update.

The direct sources are [state updates](../../../../../src/openifs/physics/gpu/state_updates.ptx), [field transfer](../../../../../src/openifs/physics/gpu/field_transfer.ptx) and [humidity floor](../../../../../src/openifs/physics/gpu/humidity_floor.ptx). Each entry receives two unsigned 64-bit values: the original argument-address vector and the [64-byte call context](../gpu_call_context.md). Keep all original objects, pointers and optional null addresses. The host launches these kernels through the public CUDA driver interface. All floating-point operations call the separately qualified exact result and status helpers from the [GPU mathematics contract](../mathematical_support.md).

## State Objects And Time Update

`md2asm_gpu_state_update` keeps five original argument slots: physics object, dimension object, initial state, tendency state and output state. Its accepted CPU [time-update contract](../../../../md2fort/references/openifs/physics/state_update.md) defines the complete calculation. The physics object has 160 bytes, with timestep in seconds at byte 8. The dimension object has 192 bytes, with signed 32-bit first column, last column, full column count and level count at bytes 0, 4, 12 and 48. Support zero through 4096 columns, zero through 1024 levels and valid one-based selected columns, including empty ranges. For each active cell, round timestep times tendency, then separately round initial plus product. The source field order is U, V, temperature, vapour, ozone, cloud fraction, liquid, ice, rain, snow and turbulent kinetic energy. Only the output state's masks control its optional fields. Each active descriptor contains actual levels 1 through N.

`md2asm_gpu_state_increment` keeps thirteen slots: dimension object, state object, then optional U, V, temperature, ozone, vapour, cloud fraction, liquid, ice, rain, snow and energy increments. Its accepted CPU [increment contract](../../../../md2fort/references/openifs/physics/state_increment.md) defines the complete interface. Raw increments contain K by N cells, with columns contiguous and levels starting at one. Each active state descriptor visits its own complete vertical range of exactly N elements. Round old state plus increment once. The field order is U, V, temperature, vapour, ozone, cloud fraction, energy, liquid, ice, rain and snow. An absent increment or disabled own mask leaves its complete field untouched.

Both calls use the accepted 1240-byte state object. Masks for ozone, vapour, cloud fraction, liquid, ice, rain, snow and energy are signed 32-bit values at bytes 0 through 28. Rank-two descriptors for U, V, temperature, ozone, vapour, cloud fraction and energy start at bytes 32, 120, 208, 296, 384, 472 and 560. Cloud water fields update components 1 through 4 of the rank-three descriptor at byte 1000. The individual cloud views are not separately written. A descriptor stores data pointer, signed element offset, element bytes and span at bytes 0, 8, 16 and 32. Dimension records contain element stride, lower bound and upper bound at bytes 40, 48 and 56, then 64, 72 and 80, then 88, 96 and 104. The element address is data plus eight times (offset + column*stride1 + level*stride2 + component*stride3).

Require contiguous complete owners with first stride one, signed 32-bit bounds stored in 64-bit words, horizontal extent at most 8192, vertical extent at most 2048 and at most 64 cloud components including 1 through 4. Metadata and tendencies stay read-only. Different active output owners are disjoint. A matching initial and output owner may coincide with identical descriptors; every tendency owner remains disjoint from outputs. Unused descriptors need not be associated and are not accessed. Input and output arithmetic must remain finite, temperature positive, water and energy nonnegative and fractions between zero and one.

## Field Transfer

`md2asm_gpu_update_fields` keeps all 97 original address slots. Slots 0 through 5 address physics object, mode, first column, last column, full columns and levels. Seven groups of thirteen slots follow: PI, PS, PA, LDV, PTA, PTS and PO. The accepted CPU [field-transfer contract](../../../../md2fort/references/openifs/physics/update_fields.md) defines the field units and optional arguments. Each present raw array contains K by N FP64 cells with columns contiguous. Support the same column and level limits as the state calls. A field is active only when PO is present and LDV is absent or true. A disabled field causes no numerical-array reads.

In modes 1 and 2, first copy matching PI when present, otherwise retain incoming output. Mode 1 requires PTA. Separately subtract present PTS, multiply the resulting rate by the timestep, and add the product. Then add present PA and subtract present PS, in that order. Every operation rounds separately. Copy-only cells preserve all bits, including NaN payloads. Arithmetic inputs and results are finite. Output fields are disjoint; matching PI may share its complete output owner. All other input/output overlaps are outside the contract.

## Humidity Floor And Diagnostic Flux

`md2asm_gpu_qnegat` keeps eleven slots: condensation object, first column, last column, full columns, levels, timestep, humidity, correction, pressure edges, diagnostic flux and optional tendency. The accepted CPU [humidity-floor contract](../../../../md2fort/references/openifs/physics/qnegat.md) defines the physical equations. The condensation object has 16 bytes, with minimum humidity at byte 8. Context bytes 48 and 56 identify an immutable eight-byte record whose only word is the live original gravity address. The host supplies that address and performs no numerical calculation. Gravity has units of metres per second squared.

Use at least one full column and one level, positive timestep and gravity, nonnegative minimum humidity, finite arithmetic and positive selected pressure thicknesses. All arrays are separate, contiguous and naturally aligned. Address products fit signed 64 bits. Humidity, correction and optional tendency have K by N cells. Pressure and flux have K by N+1 cells, with edge zero first. The input object and timestep remain valid on an empty selected range; unused numerical arrays may be absent.

One GPU thread owns a complete selected column. It computes the rounded reciprocal timestep, initializes all correction levels from the optional tendency or positive zero, then visits layers from top to bottom. Separately multiply timestep by correction, add humidity, subtract from the minimum, take the maximum with positive zero, multiply by the reciprocal and add the correction increment. Above the bottom, multiply that increment by current pressure thickness, divide by next thickness and subtract the transfer from the next correction. After the complete repair, subtract the supplied tendency from every correction when present. For finite zeros, the maximum chooses positive zero.

Start private flux at positive zero. At each layer, negate final correction, multiply by pressure thickness, divide by gravity, add preceding private flux and add that result to existing diagnostic flux. Keep inactive columns and the original top flux row unchanged. Recomputing a pressure difference reads only unchanged pressure edges and preserves the original rounding order. No host stage or external OpenIFS routine supplies the repair or diagnostic calculation.
