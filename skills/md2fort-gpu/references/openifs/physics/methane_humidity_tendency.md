# Methane Humidity Tendency On A GPU

This source implements the complete original METHOX calculation, which adds water from methane oxidation and removes water through photolysis. Pressure is in pascals, humidity is in kilograms per kilogram and the returned humidity tendency is in kilograms per kilogram per second. The original equations are in [the methane humidity formulation](../../../../../formulations/openifs/physics/methane_humidity_tendency.md), and the accepted ordered CPU calculation is in [the METHOX contract](../../../../md2fort/references/openifs/physics/methox.md).

Each selected cell starts from positive zero. When pressure and humidity are below their oxidation limits, the source adds a relaxation rate towards the humidity limit. When pressure is below the photolysis limit, it then subtracts the water-loss rate. Both pressure laws retain every separately rounded logarithm, real power, cosine, exponential, product and division from the selected source. The original intermediate time is retained even near a very small photolysis denominator. The eleven model parameters remain variable live inputs.

The application binary interface (ABI), which defines arguments and preserved machine state, retains seven addresses: first column, last column, column count, level count, humidity, returned tendency and pressure. Arrays use column-first order and 64-bit floating-point (FP64) words. The column count is from zero through 4096 and the level count from zero through 512. The first column is from one through column count plus one; the last is from zero through column count. Empty work changes no payload or numerical state. An inactive reaction may retain a finite negative temporary humidity without consuming it in either rate.

The complete device entry uses one block with one thread and zero shared memory. A 256-byte record declares all seven owner capacities, eleven copied live parameter words and optional EXP, FAST and WIDE counter owners. There is no numerical scratch. Complete output, context and counter owners are disjoint from consumed inputs and metadata. All required owner and consumed-parameter checks precede output stores. The host retains the original private entry `md2asm_methox`, preserves incoming status and error state and accepts only a serial caller. Every weather calculation runs in the device body; the Arm host supplies storage and launch services.

Arithmetic uses FP64 round-to-nearest with ties to even, gradual underflow and preserved signed zeros. The qualified LOG, POWER, COS and EXP children retain the selected source order. Direct cosine helper classes do not add global counter events; POWER and EXP retain their actual selected counter effects. No fused model operation, reassociation, approximate division, reduced precision or output normalisation is used. The shared context joins incoming sticky status and retains an earlier error event when no new source event occurs.

Qualification passes 54 protected GPU and 54 selected CPU calls, compared with 27 original Fortran placements, across 33,571,904 complete output bytes with zero differences. There are 2930 distinct 120-digit physical relations, 41 prewrite or early-return controls, four valid integer-alignment controls, two seeded-context controls and three ordinary device-memory graphs. The maximum 4096-by-512 owner, last column, inactive negative humidity, unused parameters, large cosine angle and very large photolysis time are included. Immediate numerical status, errno, original registers, readonly owners and actual counters agree. The selected 640-byte CPU provider, three new native GPU functions and 17 logarithm inputs, 12 cosine inputs, four power pairs and five exponential inputs also pass; numerical and host source reviews are independent. These are component checks, with no full GPU forecast or timing claim.
