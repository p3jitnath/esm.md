# Complete spline inverse from LU factors on the GPU

The [accepted full-inverse calculation](../../../../md2fort/references/openifs/setup/spline_full_inverse_contract.md) is unchanged. LU factors are the lower and upper triangular parts of a factored square matrix. The [original public entry](../../../../../src/openifs/setup/gpu/spline_full_inverse_host.S) retains its Arm application binary interface (ABI), with four address arguments: X0 addresses a 32-bit dimension n, X1 addresses the n-by-n FP64 matrix, X2 addresses n read-only 32-bit pivots and X3 addresses one writable 32-bit info word. FP64 is the 64-bit floating-point format. The matrix is contiguous and column-major, so row i of column j is stored at element j*n+i, with indices starting at zero. The inherited domain has 1 through 24 rows, finite input cells and finite executed intermediate values. Pivot j is from j+1 through n. Integer owners have four-byte alignment; matrix and counter owners have eight-byte alignment. Complete owners are mapped and disjoint. Original null, alignment, dimension, pivot and source-return guards remain literal.

One [direct PTX call](../../../../../src/openifs/setup/gpu/spline_inverse_from_factors_phase.ptx) owns the complete numerical body. The [private upper inverse](spline_upper_triangular_inverse_complete_contract.md) runs first. A first zero diagonal returns code zero and its one-based info index with the matrix unchanged; an invalid source input returns code two without committing matrix or info. After a successful upper inverse, parent columns descend from last to first. Each lower entry is copied to private scratch and replaced by positive zero. Later columns and rows ascend in the original order. The factor uses one separate rounded multiplication by negative one, including zero and subnormal inputs. Each original product-sum call retains the accepted exact rounding of product plus addend, with its returned numerical flags and actual FAST/WIDE class. Pivot columns then descend, exchanging complete columns by bit copies. Nearest-even rounding, signed zero, gradual underflow and all original ordering remain fixed.

The pure values function md2asm_gpu_spline_inverse_from_lu_values takes n as a 32-bit value, then matrix and pivot addresses as 64-bit values. Its eight-byte-aligned, 32-byte return contains source code at byte 0, info at 4, new numerical flags at 8, reserved zero at 12 and actual FAST/WIDE totals at 16/24. The upper child uses the same return layout. Values, flags and classes are consumed immediately. Each finite counted product-sum contributes one FAST event for class zero or one WIDE event otherwise, including tiny results. The parent combines actual child and parent totals and publishes them to the existing public owners once, with unsigned 64-bit wrap. Only the unchanged public exact-product-sum interface is required, and the selected compact provider is linked once.

The GPU entry uses the standard two-address vector and 64-byte context. A 96-byte input record holds dimension, matrix, pivot and info addresses at bytes 0/8/16/24 and existing FAST/WIDE owner addresses at 32/40; bytes 48 through 95 are zero. A 16-byte metadata record gives input/output capacities 96/32. Before numerical work, the entry checks all eleven complete owners for bounds, alignment, overflow and overlap. Private lower scratch has 24 FP64 words, and every consumed word is copied before use. The [integer Arm transport](../../../../../src/openifs/setup/gpu/spline_inverse_from_factors_phase_calls.S) uses a 2048-byte temporary frame, preserves required registers, x18, the floating-point control register and errno, and joins incoming numerical flags with new flags. Source code zero writes info; source code two preserves matrix and info. The complete body requires one GPU launch and calls no original OpenIFS numerical routine.

Fourteen retained complete cases match 29,624 matrix/info bytes, source outcomes, ABI state, flags, errno and actual counters with zero differences. These cases include singular input, signed zero, nontrivial pivots and dimension 24. Seven changed source-outcome controls, 25 prewrite refusals and the focused native return/status/counter gate pass. An independent source/status peer recomputes the whole original-body inverse and verifies the current provider, child interface, scratch, order, owners and host state. The accepted 7,384 exact-rational matrix-inverse relations are reused. Missing status/count expectations came from unchanged accepted GPU records after exact archived-value agreement; no new CPU or Fortran numerical oracle is used. This component adds zero original routine credit. Combined selected-caller and forecast checks, and comparative timing, remain separate.
