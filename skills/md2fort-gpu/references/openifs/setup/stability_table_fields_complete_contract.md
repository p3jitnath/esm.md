# Complete stability-table construction on the GPU

This phase builds the complete vertical-diffusion stability table used by SUVDFS. It preserves the [accepted thermal and stability equations, constants and physical checks](../../../../md2fort/references/openifs/setup/thermal_diffusion_parameter_setup.md). The Richardson number measures the effect of stable air layering on turbulence, and the table gives the ratio of height to Obukhov length. Both quantities are dimensionless. A cubic spline, which is a smooth piecewise polynomial, uses the stored second derivatives to interpolate between the 101 points.

The [Arm provider](../../../../../src/openifs/setup/gpu/thermal_diffusion_parameter_setup.S) keeps its three original exports. Only md2asm_initialize_stability_table_fields changes its execution boundary. Its x0 argument is a mapped writable owner of 1,736 bytes, aligned to eight bytes, and w0 returns zero. The caller keeps this owner live until the synchronous call returns and supplies floating-point control register FPCR equal to zero. The guarded thermal parent still checks its 1,920-byte output and 520-byte constants, builds the first 184 thermal bytes, then calls this child at output byte 184. All other thermal instructions, constants and rejection rules remain unchanged.

The table owner stores 101 FP64 values of RITBL at bytes 0 through 807 and 101 FP64 spline second derivatives of ARITBL at bytes 808 through 1615. FP64 means a sixty-four-bit floating-point value. The following fifteen constants keep their accepted words and declaration order at bytes 1616 through 1735. The complete owner is written on every valid call; its incoming contents do not supply a numerical value.

The [values function](../../../../../src/openifs/setup/gpu/stability_table_values.ptx) exports md2asm_gpu_stability_table_values. It takes output:u64, where u64 is an unsigned sixty-four-bit integer that holds the mapped address. Its eight-byte-aligned sixteen-byte return record contains the source return code as u32 at byte zero, newly raised floating-point flags as u32 at byte four, and zero as u64 at byte eight. Here u32 means an unsigned thirty-two-bit integer. The caller admits the complete output owner before calling this private function.

One GPU thread visits table indices one through one hundred in increasing order. Each Newton solve starts from the preceding completed table value, so these rows cannot run independently under the accepted method. It uses five iterations when the separately rounded target is below one half and three otherwise. Every multiply, add, subtract and divide retains its original ordered operands and separate rounding point. The qualified arithmetic functions run on the GPU and return flags immediately after each call. The integer index conversion is exact over one through one hundred; the comparison operands are finite, and the sign changes act on the literal one half.

The same thread then performs the original spline forward recurrence from index one through ninety-nine, the final boundary equation, and backward substitution from ninety-nine through zero. Its private ZU scratch has 101 FP64 words; each consumed word zero through ninety-nine is written before it is read. There is no heap allocation, retained pointer or host numerical stage. Round to nearest with ties to even, gradual underflow and signed zeros remain fixed. Model arithmetic is not contracted, reassociated or replaced by approximate operations.

The [private launch entry](../../../../../src/openifs/setup/gpu/stability_table_phase.ptx) exports md2asm_gpu_stability_table. It takes original_vector:u64 and common_context:u64, and uses one block with one thread and zero dynamic shared bytes. The argument vector holds input-header and completion addresses. The sixteen-byte input header holds the output address and one zero u64. The sixteen-byte completion has the values function's return layout. A thirty-two-byte capacity record holds input capacity sixteen, completion capacity sixteen, output capacity 1736 and one zero u64.

The six complete owners are the sixteen-byte argument vector, sixty-four-byte common context, thirty-two-byte capacity record, sixteen-byte input header, sixteen-byte completion and 1,736-byte output. All use eight-byte alignment and are pairwise disjoint. The existing runtime supplies a mapped common context with a representable complete address range, revision one, zero reserved word and its initial error field. This context must remain readable and writable throughout the call. The five calculated owners receive explicit null, alignment, capacity, address-wrap and signed-address-limit checks. Pairwise checks finish before any numerical output or completion write.

The capacity-record address and capacity occupy common-context bytes forty-eight and fifty-six. Context byte eight accumulates floating-point flags. Private shape, revision or reserved-context refusals set context error 35400; range or overlap refusals set 35401; nonzero input-header or capacity-record reserved words set 35402. These refusals change only the context error. A seeded context error returns without writes. Arbitrary unmapped context addresses are outside the common runtime interface.

The [Arm transport](../../../../../src/openifs/setup/gpu/stability_table_phase_calls.S) exports md2asm_gpu_stability_table_phase_host and uses 2,048 private stack bytes. It saves all thirty-one general registers and all thirty-two complete vector registers before runtime services, restores x18 after each service, prepares the runtime and makes one synchronous launch. It restores FPCR, errno and the integer condition flags, unions the returned flags with incoming FPSR, restores the saved registers and returns the source code in w0. The supported call is serial at the host boundary. Runtime or private launch failure follows the existing fatal error path.
