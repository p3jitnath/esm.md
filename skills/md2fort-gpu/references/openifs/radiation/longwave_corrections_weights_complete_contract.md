# Complete longwave corrections and weights on the GPU

This phase implements `md2asm_longwave_corrections_and_weights` using the [longwave reduction equations and ordered arithmetic](../../../../md2fort/references/openifs/radiation/longwave_gpoint_reduction.md). It computes two dimensionless correction arrays with 201 entries each and sixteen relative weights for each of sixteen bands. The weights combine absorption samples within a band. The function reads live band controls, group lengths and sample weights. Archived records supply verification only.

The Arm application binary interface (ABI) receives an eight-byte-aligned live record in `x0` and returns no value. The complete owner is 8592 bytes. NGC has sixteen 32-bit controls at zero, NGN has 256 32-bit group words at 128 and WT has sixteen FP64 weights at 3200. FP64 means a 64-bit floating-point number. CORR1, CORR2 and RWGT occupy bytes 3328 through 4935, 4936 through 6543 and 6544 through 8591. All bytes before 3328 remain unchanged. The caller keeps the complete owner mapped until synchronous return.

The [storage entry](../../../../../src/openifs/radiation/gpu/longwave_reduction_tables.S) retains the original source constant and branches to the [host transport](../../../../../src/openifs/radiation/gpu/longwave_corrections_weights_phase_calls.S). Its private 2048-byte frame preserves the required general and vector registers, `x18`, stack alignment and integer condition flags. FPCR, the floating-point control register, must be zero for nearest-even rounding and gradual underflow. New flags join the incoming floating-point status register, FPSR. The function preserves `errno` and the actual FAST and WIDE product-sum counters. It allocates no retained storage.

For each correction index from 1 through 199, the source converts that integer exactly, multiplies it by the source word `0x3f747ae147ae147b` for 0.005, takes the square root and divides that root by the rounded product for CORR1. It separately subtracts the root from one, subtracts the product from one and divides those two rounded differences for CORR2. Every FP64 rounding point and operand order remains. Thread zero first stores one at CORR1[0], CORR2[0], CORR1[200] and CORR2[200], in that source order.

NGN is one advancing stream across all bands. A band whose NGC control equals sixteen stores sixteen unit weights and skips sixteen NGN words without reading them or WT. Other bands consume positive group lengths until their sum reaches sixteen. Each group starts a positive-zero sum, adds its WT words in increasing order, then divides each original WT word by that completed sum in increasing order. A nonunit NGC value is not checked against an inferred group count because the source uses only its equality with sixteen. All WT bit patterns use the qualified IEEE status operators; the phase adds no finite-value restriction.

The [device entry](../../../../../src/openifs/radiation/gpu/longwave_corrections_weights_phase.ptx) uses one block of 256 threads and zero dynamic shared bytes. Admission walks the original band order and saves each actual NGN start cursor. Through the [complete value function](../../../../../src/openifs/radiation/gpu/longwave_corrections_weights_values.ptx), threads zero through 198 each own one interior correction pair, while threads zero through fifteen also own one complete band reduction. No output depends on another worker output. All 256 threads initialise their result slot and reach three collective barriers. The parent joins all newly raised flags with bitwise OR. Link each qualified IEEE status provider and its existing arithmetic dependencies once; no fused, approximate or reassociated arithmetic supplies a model value.

The device ABI receives an argument-vector address and a [common-context address](../gpu_call_context.md). The 16-byte vector selects the header and completion. The 16-byte header holds the live record address and zero. Context offsets 48 and 56 select a 32-byte capacity record containing the header, completion and record capacities, then zero. The value function receives a 32-bit lane, 64-bit record address and 32-bit admitted NGN start cursor. Its aligned 16-byte return has new flags followed by three zero words.

The caller supplies the mapped common context, revision one with reserved word zero. Admission checks launch shape, address alignment and bounds, capacities, reserved words and every overlap involving writable storage. Read-only views may overlap. Consumed NGN lengths must be from one through sixteen and reach sixteen without passing it, using at most 256 words in total. Skipped unit-band words remain unconstrained. Every check finishes before endpoint, model or completion writes. Shape, range and reserved/map failures report errors 36000, 36001 and 36002.

Completion has four 32-bit words: return code, flags and two zeros. No source operation writes an error event, so the complete incoming 64-bit context event remains unchanged. The host restores the incoming error indicator and combines the returned numerical flags. There is no numerical fallback.

Three complete live records compare 25776 bytes exactly, with strict ABI, `x18`, FPCR, FPSR, `errno`, actual counter nonchange and complete guards. One bounded unchanged-GPU capture rechecks all 8592 canonical bytes and supplies changed WT/group-map and unread-unit-input records. Fourteen further controls compare entire 65536-byte images, including all 256 NGN words, shared read-only views and nine atomic refusals. Independent source and native reviews pass. The retained independent evidence covers 3443 grouped physical relations and 2770 exact-rational ordered sums, including ninety-digit checks of the correction identities. No CPU or Fortran oracle ran. Every numerical process had an external 14.13-second cutoff. Complete forecast agreement and matched performance remain pending.
