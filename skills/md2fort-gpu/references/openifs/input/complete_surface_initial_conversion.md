# Complete initial surface conversion on the GPU

The assembly interfaces `md2asm_convert_initial_surface_state` and `md2asm_scale_initial_surface_fields` prepare the initial surface fields before the forecast starts. The [surface conversion contract](../../../../md2fort/references/openifs/input/surface_initial_state_conversion.md) and [unit scaling contract](../../../../md2fort/references/openifs/input/surface_field_unit_scaling.md) define their unchanged physical fields and arithmetic order. FP64 means a 64-bit floating-point value. This implementation uses one GPU launch for vegetation checks, all unit scaling and the complete point conversion.

Both public interfaces take eight machine words: the two field addresses and capacities, the parameter address and capacity, and the configuration or constant address and capacity. The mutable fields contain 770048 and 409600 bytes. Parameter identifiers occupy 208 bytes. Full conversion requires 2304 configuration bytes; standalone scaling requires 16 bytes for gravity and water density. Fields and configuration are aligned to eight bytes, and identifiers to four bytes. Each mutable field is disjoint from the other field and both read-only spans. The two read-only spans may overlap. Capacities and address ends are checked before access.

The original integer checks, first matching parameter identifier and optional-current filters remain in the public assembly. Return values are 0 for success, 1 for invalid spans, 2 for nonzero floating-point control, 3 for unsupported configuration, 4 for a missing required field and 5 for an invalid vegetation index. Every rejection precedes field writes and retains the incoming arithmetic flags. The vegetation check preserves the source strict half-away-from-zero bounds and discards its temporary flags before either return or scaling.

One block contains 128 threads and uses 224 bytes of fixed shared storage, with no dynamic shared storage. After thread zero finishes validation, each thread scales separate point indices. All 147456 source multiplications remain, including multiplication by one. A block barrier finishes scaling before conversion begins. Distinct point indices address distinct cells in every mutable field, and the tables remain read-only, so different points have no write/read dependency. Within each point, every snow-layer sum, clamp, table lookup, capacity operation and current adjustment follows the original order. Each arithmetic operation keeps its separate rounding point. Numeric minimum and maximum preserve the accepted not-a-number (NaN) and signed-zero rules, including values formed by finite-input overflow.

The private entry `md2asm_gpu_initial_surface_complete` takes a 64-byte header and 64-byte context. The header contains the four public addresses, mode 0 for scaling or 1 for full conversion, and three reserved zero words. A 64-byte record supplies all capacities. These three private owners are disjoint from one another and all public owners. The complete seven-owner admission retains the allowed parameter/configuration alias. The scaling child completes before the point-conversion child is called, and each child call receives fresh arguments.

The application binary interface (ABI) defines the registers a function must preserve. The host keeps x18 and all ABI saved registers, the full vector state, the floating-point control register and the library error number `errno`. It returns the source result code and adds each new arithmetic flag once. The actual FAST and WIDE product-sum counters remain unchanged because these source bodies do not use product-sum operations. The GPU uses the accepted add, subtract and multiply status functions and the accepted comparison, numeric minimum/maximum and integer-rounding blocks. It uses no fused operation, approximate arithmetic or CPU numerical fallback.

Changed transport checks passed all 12 retained complete surface cases, the retained finite-cover overflow case, complete standalone scaling and an allowed read-only alias. All 17694720 output bytes, read-only bytes, guards, immediate arithmetic flags, control, `errno`, x18, ABI state and actual counter seeds near wrap agreed exactly. A further 48 focused admission controls compared each complete 1191936-byte image. Existing independent physical checks were reused: 344320 surface relations, 2048 overflow relations and 624 exact scaling products. No CPU reference or physical calculation was rerun. Native inspection confirms one host launch, the scaling/conversion barrier and calls to the accepted arithmetic children. These component results do not establish a complete GPU forecast or a comparative forecast time.
