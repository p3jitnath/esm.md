# Complete Initial Virtual-Temperature Cells on the GPU

Virtual temperature is the temperature that dry air needs to give the pressure and density of moist air. The [physical formulation](../../../../../formulations/openifs/dynamics/virtual_temperature_conversion.md) explains this gas-law conversion. The [accepted CPU parent contract](../../../../md2fort/references/openifs/input/initial_virtual_temperature_conversion.md) fixes the selected SPECRT calculation, its live initial fields and its public spectral transforms.

The complete parent keeps its original guards, two temporary arrays, two public ECTRANS calls and 86 ordered blocks. Each block still calls the accepted GPRCP mixture calculation first. This change replaces only the complete temperature-cell child with one synchronous GPU call. It adds no missing numerical stage and reads no archived output in production.

## Inputs and Ordered Arithmetic

The original child is `void md2asm_initial_virtual_temperature_cells(T,gas,active,constants)`. The Arm application binary interface, or ABI, passes these values in x0, x1, w2 and x3. T and gas each contain 24 by 19 FP64 words, or 3,648 bytes, in column-first order. FP64 is a 64-bit floating-point number. The live constant record contains 520 bytes, with the dry-air gas constant RD at byte 184. Temperature is in kelvin; gas and RD are in joules per kilogram per kelvin. Active columns range from 1 through 24. The selected parent uses 24 for its first 85 blocks and 8 for its last block.

For each level and active column, multiply gas by T, round that result in FP64, then divide the rounded product by RD and round again. Use nearest-even rounding and gradual underflow. The qualified pure multiplication and division children retain signed zeros, exceptional values and their new exception flags. There is no fused operation, expression reassociation or reduced precision. Every cell reads only its own two input words and RD. Inactive columns perform no temperature or gas load and keep their incoming bytes, including signalling-NaN payloads.

## Ownership, Launch and Status

All complete numerical spans are mapped, eight-byte aligned, nonwrapping and disjoint. Input constants and gas remain read-only. The complete parent owns both temporary arrays until the following transform and cleanup finish. One block of 256 threads owns the 456 possible cell positions by thread index and index plus 256. All threads reach both collective barriers, which wait for the complete block. A final integer OR joins every newly raised floating-point flag. Each active cell still has its original multiplication-before-division dependency.

The two-address launch vector points to a 48-byte input header and a 16-byte completion record. The common context has 64 bytes and points to a 48-byte capacity record. The header stores T, gas and constants at bytes 0, 8 and 16; active as a 32-bit integer at 24; zero at 28; revision 1 at 32; and zero at 40. Capacity words give 48, 16, 3648, 3648, 520 and zero. Admission checks all eight owners before numerical writes. Writable temperature, context and completion must not overlap any other owner. Read-only metadata views may share storage. Invalid shape, revision, capacity, alignment, active count or writable overlap refuses before numerical mutation; only the context error word changes.

The host has a 2,048-byte aligned frame. It saves the integer and vector registers, requires FPCR zero and serial host use, and makes one synchronous launch. FPCR is the Arm floating-point control register; zero selects the required rounding and underflow rules. The host restores FPCR, errno, x18 and saved ABI state, while FPSR retains incoming flags and unions the new arithmetic flags. FPSR is the floating-point status register. Both helpers have no errno or counter event, so the complete 64-bit no-event context word remains unchanged. The original GPRCP counters and source boundaries stay in the parent. The child has no scalar numerical return; x0 and x1 retain the source-observed addresses advanced by 3,648 bytes for existing verification probes. Transport failure stops without a numerical fallback.

## Accepted Checks and Limits

Three retained dry-air, vapour and cloud records agree in all 10,944 output bytes. They cover active counts 24, 8 and 24, inactive signalling-NaN cells, complete read-only inputs, outer guards, immediate FPCR/FPSR/errno, x18 and the strict ABI. Actual FAST and WIDE counters remain unchanged when seeded near their wrap boundary. The original 1,064 independent high-precision physical relations and the complete 2,748,656-byte SPECRT proof, including all 86 real GPRCP calls, are reused for unchanged mathematics and parent order.

The changed transport passes 33 complete 65,536-byte images: six valid cases and 27 refusals or early returns. These include live active counts 1 and 23, read-only shared metadata, capacity boundaries, writable aliases, launch shape and complete no-event preservation. Native instruction review confirms exactly the two qualified arithmetic calls, immediate returned-flag unions, eight admission calls and two collective barriers. The only native reciprocal outside the qualified helpers implements an integer column remainder from literal 24; it never consumes a model FP64 value. Independent source and native reviews pass. Each numerical process has an external 14.13-second cutoff. No new CPU oracle or unchanged complete-parent run was made. Whole-forecast output agreement and a measured speed gain remain separate requirements.
