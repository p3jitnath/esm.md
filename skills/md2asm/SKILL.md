# Markdown To Assembly

Use this workflow to turn a short physics formulation into a complete numerical solver written directly in native assembly. Write for a first-year undergraduate. Define unfamiliar terms, explain choices, and follow the project [instructions](../../AGENTS.md), [formulation template](../../formulations/TEMPLATE.md) and [writing convention](../../standards/ASD-STE100-CONV.md).

## Define The Solver Contract

Choose and explain a numerical method, which converts continuous equations into calculations at grid points and time steps. Record its grid, complete update, boundaries, constants, initial state, stability conditions, storage and acceptance limits under `references/`. Keep the physics formulation short. Preserve existing verified methods in the [shallow-water contract](references/2d_rusanov_ssprk2.md), [energy-balance contract](references/budyko_sellers.md) and [OpenIFS contracts](../../src/openifs/README.md).

Define every field's meaning, units and model time. State whether an output replaces a value or adds an increment. Match each physical check to the calculation stage whose state it describes. State which bounds apply to temporary calculations and which apply to published outputs, and compare related quantities from the same stage. Derive physical balances from all boundary flows and sources, converting rates to finite changes and weighting quantities by the appropriate cell mass or area. Derive limiting cases, such as a vanishing layer, from the same equations. Report physical validity and agreement with a reference separately, preserving the requested model and documenting its limits.

For a conservative exchange between adjacent cells, define one physical face contract for both directions, including the precision of threshold constants and the branch taken at equality. Verify that the two views transfer the same rounded amount with opposite signs. An implicit update computes a new state together with the losses that depend on it. Preserve the nonnegative solved amounts for outgoing fluxes, and keep later cleanup or history values separately when they differ. Separate each physical amount from any small signed remainder produced by the solve. When enforcing a physical bound, account for that remainder in the same conservation balance, fix the order of the rounded operations, and use the same physical transport in the heat balance. Check the resulting state against its physical bounds and retain the existing acceptance limits. If independent checks expose a reference defect, preserve the earlier evidence and define a corrected canonical revision before making new comparisons.

Freeze complete binary inputs, constant words, output encoding and deterministic metadata. Check decoded inputs against the stated model limits. When the file format rounds a boundary value, derive any permitted input range from the encoding and the equations that use it, and preserve the decoded bits. Specify ordered FP64 arithmetic, meaning 64-bit floating-point calculations, including each intermediate rounding point, reduction order, tie rule, signed zero and subnormal value. Use round-to-nearest with ties to even and gradual underflow. Use separate multiplication and addition, exact division and square root, and the frozen expression order. Preserve the declared numerical status, system error values and counters. Keep the frozen rounding boundaries when qualifying mathematical helpers, and derive their supported arguments through all preceding rounded calculations.

Choose mathematical branches from their physical domains. For an equation with several roots, verify the selected root in the original equations and physical interval. Carry input-rounding and cancellation bounds through independent high-precision or exact-integer checks. Derive admission tests for stored rounded values, and retain signed residuals required by the frozen source arithmetic. Include primitive terms and unit conversions before cancellation when bounding a physical balance. For a direct output check, enclose the exact physical quantity, test the observed output against that interval, and state the resulting absolute error limit. Keep this output evidence separate from claims about the accuracy of internal helpers. A second FP64 word can retain a rounding remainder when a helper requires more accuracy than one word provides. Record its error bound and every supported branch.
