# Markdown To Assembly

Use this workflow to turn a short physics formulation into a complete numerical solver written directly in native assembly. Write for a first-year undergraduate. Define unfamiliar terms, explain choices, and follow the project [instructions](../../AGENTS.md), [formulation template](../../formulations/TEMPLATE.md) and [writing convention](../../standards/ASD-STE100-CONV.md).

## Define The Solver Contract

Choose and explain a numerical method, which converts continuous equations into calculations at grid points and time steps. Record its grid, complete update, boundaries, constants, initial state, stability conditions, storage and acceptance limits under `references/`. Keep the physics formulation short. Preserve existing verified methods in the [shallow-water contract](references/2d_rusanov_ssprk2.md), [energy-balance contract](references/budyko_sellers.md) and [OpenIFS contracts](../../src/openifs/README.md).

Define every field's meaning, units and model time. State whether an output replaces a value or adds an increment. Match each physical check to the calculation stage whose state it describes. State which bounds apply to temporary calculations and which apply to published outputs, and compare related quantities from the same stage. Derive physical balances from all boundary flows and sources, converting rates to finite changes and weighting quantities by the appropriate cell mass or area. Derive limiting cases, such as a vanishing layer, from the same equations. Report physical validity and agreement with a reference separately, preserving the requested model and documenting its limits.

For a conservative exchange between adjacent cells, define one physical face contract for both directions, including the precision of threshold constants and the branch taken at equality. Verify that the two views transfer the same rounded amount with opposite signs. If independent checks expose a reference defect, preserve the earlier evidence and define a corrected canonical revision before making new comparisons.

Freeze complete binary inputs, constant words, output encoding and deterministic metadata. Check decoded inputs against the stated model limits. When the file format rounds a boundary value, derive any permitted input range from the encoding and the equations that use it, and preserve the decoded bits. Specify ordered FP64 arithmetic, meaning 64-bit floating-point calculations, including each intermediate rounding point, reduction order, tie rule, signed zero and subnormal value. Use round-to-nearest with ties to even and gradual underflow. Use separate multiplication and addition, exact division and square root, and the frozen expression order. Preserve the declared numerical status, system error values and counters. Keep the frozen rounding boundaries when qualifying mathematical helpers, and derive their supported arguments through all preceding rounded calculations.

Choose mathematical branches from their physical domains. For an equation with several roots, verify the selected root in the original equations and physical interval. Carry input-rounding and cancellation bounds through independent high-precision or exact-integer checks. Include primitive terms and unit conversions before cancellation when bounding a physical balance. For a direct output check, enclose the exact physical quantity, test the observed output against that interval, and state the resulting absolute error limit. Keep this output evidence separate from claims about the accuracy of internal helpers. A second FP64 word can retain a rounding remainder when a helper requires more accuracy than one word provides. Record its error bound and every supported branch.

## Find The Performance Bound

Profile complete time steps and their external-service waits before changing code. Count executed calls by child and caller, inspect the linked instructions, and identify repeated work. A profiling-only return-address tag can identify callers when its saved register remains unchanged throughout the observed child. Keep the profiling route separate and preserve the public ABI.

Build a [roofline model](https://www2.eecs.berkeley.edu/Pubs/TechRpts/2008/EECS-2008-134.pdf), which compares arithmetic throughput with memory bandwidth. Count useful operations, live working data and traffic at each relevant memory level. Distinguish logical bytes from measured cache refills and main-memory traffic. Measure bandwidth at the workload's read/write ratio, size and alignment, and calibrate the actual instruction mix, including division and square root. Include dependencies and shared execution resources when setting a bound.

Use the smaller justified compute or memory limit and report the achieved fraction, assumptions and variation. Compare complete physical updates per second, since reuse can reduce the work itself. Keep performance conclusions specific to the measured inputs, target and supported configuration.

## Apply Successful Optimisations

Retain a method when its complete-operation improvement exceeds measurement variation and preserves the frozen outputs. Derive each fast-path condition from the admitted mathematical domain, qualify varied inputs and boundaries, and keep the general route available. Preserve arithmetic order, rounding points, source-visible status and counter meanings.

| Method | Required implementation guidance |
| --- | --- |
| Vector execution | Compare supported SIMD and SVE instructions, which operate on several values at once. Vectorise independent outputs while each lane retains its original arithmetic order. Preserve each lane's coefficient words, valid branch operands and bounded tail. |
| Rounded-value reuse | Reuse a coefficient, face, stencil value or decoded field only when its operands and rounding point agree. Keep required stage outputs and checks, and end reuse before an owner write or a call can change the value. |
| Independent instruction scheduling | Interleave independent groups to cover division, square-root and load latency. Start work after its inputs are ready and registers are free, and bound every final look-ahead. |
| Face and update fusion | Place a rounded face beside its immediate update and carry shared faces in registers or a live row. Preserve the last active lane, boundary preparation and every dependency between time stages. |
| Scratch and temporal reuse | Retain only the rows or neighbours still needed. Consume old values before overwriting them. Use registers for private fixed-size scratch while retaining pivot order and every final scratch value that another consumer observes. |
| Address and invariant reuse | Hoist fixed pointers, strides and immutable coefficients after their prerequisites. Advance each pointer by its own signed stride. Reuse a search interval only for a sequence whose ordering proves earlier intervals cannot match. |
| Private numerical entries | Pass qualified input bits and decoded state through private interfaces while preserving public checks. Save return words before reusing call storage, keep all general-path operands, and verify the complete register handoff. |
| Independent workers | Partition independent columns or fields while preserving array origins and each ordered reduction. Give workers disjoint records, scratch, counters and status words. Preserve shared decisions, first-error order and parent completion after all required work. |
| Worker coordination | Publish bounded coordination records before dependent branches. Combine each child's flags and counters once, keep collected status visible at its declared boundary, and preserve the agreed result through release. |
| Status collection | In a private interval without an intermediate observer, collect exception flags in an integer mask and merge them before each public return or service call. Preserve inherited flags and specified signed zeros. |
| Bounded integer arithmetic | Use proved operand bit lengths to keep exact magnitudes and remainders in registers. Preserve carries, cancellation, first discarded bits, nonzero tails and ties-to-even rounding, including shifts at word boundaries. |
| Exact scaling and identities | Use exact zero identities and power-of-two scaling within proved domains. Preserve underflow and sign rules. A separate multiply and add can replace a single-rounding helper only when the product is proved exact on every admitted path. |
| Grouped integer sequences | Derive several exact shift/XOR transitions together from the original state. Use bounded feedback tables, retain discarded samples, and finish with a qualified smaller group. |
| Control specialisation | Select fixed stage variants before repeated work. Use stored-bit properties to simplify qualified decoders, retain unsupported fast-path cases in the general route, and preserve source checks and pre-loop work for empty calculations. |
| Allocation reuse | Reuse aligned storage while its shape and ownership remain valid. Refresh required inputs and address maps, retain true argument bounds and borrowed spans, hold exclusive use through publication, and count actual allocations separately. Release physical pages from retained private scratch after its consumers finish and every later read is proved to follow a new write. Preserve allocation records, shared edge pages, status and floating-point controls. Apply the same lifetime proof when a storage service can change part of a buffer before it reports failure. |
