# Prognostic-cloud parameter setup

This component replaces the complete selected `SUCLDP` calculation. It constructs the rain, ice and snow coefficients used by the prognostic cloud scheme, the cloud and aerosol switches, the precipitation-code map, and two 101-point incomplete-beta tables. A beta table gives the accumulated fraction of a bounded distribution and is used to describe cloud-water variability. The component owns every numerical child implemented inside the original routine and the original `FCGENERALIZED_GAMMA` calculation. It does not replace the complete `SUPHEC` caller or the later cloud time update.

The production files are `prognostic_cloud_parameter_setup.S`, `prognostic_cloud_parameter_fields.S`, `cloud_beta_gamma_functions.S` and the source-literal include `prognostic_cloud_parameter_data.inc.S`, all under `src/openifs/setup/`. The numerical bodies were emitted directly as AArch64 assembly. The include contains typed offsets and source constants; it contains no captured record or model-state payload. No original OpenIFS callable, module value, type record or method table supplies a production stage.

## Owned inputs and output

The guarded procedure is `int md2asm_initialize_prognostic_cloud_parameters(text, text_bytes, output, output_capacity, inputs)`, using registers `x0` through `x4`. Text occupies 1–262144 readable bytes. Output is the complete caller-owned TECLDP record of 2776 bytes, with capacity at least that large. The input table occupies 64 readable bytes and contains four pairs of 64-bit address and capacity words in the following order.

| Input | Required extent | Producer and units |
|---|---:|---|
| Standard pressure | 19 FP64 values, 152 bytes | Owned Geometry STPRE; Pa |
| Physical constants | 520 bytes | `md2asm_initialize_physical_constants` |
| Scaling factors | Two FP64 values, 16 bytes | Owned SUDYNCORE `{RPLRG,RPLDARE}`; dimensionless |
| Physics interval | One FP64 value, 8 bytes | Live `TPHY2.TSPHY`; s |

All numerical addresses and the input table must be nonzero, aligned to eight bytes, mapped over their full declared extents and free from address wrap. Output must be disjoint from text, table and all four consumed input extents. The required capacity, rather than the supplied larger capacity, defines each accessed extent. Read-only inputs may share storage if their contents meet every declared input contract. Return zero means success; return two rejects an unsupported input before any output write. There is no heap allocation, descriptor or retained pointer. The caller releases the outer record after its last consumer.

The selected level count is 19. Standard pressures must be positive and finite. The consumed physical constants are `RPI` at byte 0, `RG` at 112 and `RTT` at 368. RPI must equal the owned FP64 value of pi; RG must be within [1,100] m/s² and RTT within [200,350] K. Each scaling factor must be within [0.25,4], and TSPHY within [1,86400] s. TSPHY is an explicit upstream value: the complete `SUPHY2` producer is outside this component, and its initial source assignment at line 139 is 1 s. TSPHY must not be silently replaced with TRIP.TSTEP.

The original source does not assign `RCLDTOPP`, its top-pressure threshold. Complete owned `SU0PHY` supplies 100 Pa for this selection at TECLDP byte 144. This component accepts a finite nonnegative threshold up to 1000000 Pa and preserves that field. It also preserves every padding byte. The typed field map and local source-write range receipt identify these complete spans; comparison never masks them or changes a returned byte. The output has no pointer words, so complete records compare directly at the same address.

The first source-recognized uppercase `NAMCLDP` group must be empty. The accepted shared reader matches the literal uppercase marker in source columns 1–10, as POSNAME does for this selected subset. It accepts the supported whitespace, comments and closing markers of the shared reader. Missing, lowercase-only or nonempty groups are rejected. The parent checks this condition before constructing fields, so unsupported text cannot leave a partial output.

## Calculations and rounding

The numerical child `md2asm_prognostic_cloud_parameter_fields` takes output in x0, STPRE in x1, constants in x2, the scaling pair in x3 and TSPHY in x4. It requires the parent's valid buffer and FP-control conditions and performs no argument checks. Its frame is 256 bytes. Source-literal stores are collected before the arithmetic; these stores add no floating-point operation and no consumer observes the record during construction. Every dependent arithmetic expression retains the source order and its FP64 rounding points, including the first ice fall-speed calculation that the source later overwrites with 100 m/s.

The source's beta coordinates use `REAL(IX)/NBETA`. The unsuffixed REAL conversion and quotient are REAL32, then the result widens to FP64. This explicit source rounding point remains present. The generalized-gamma source also declares its coefficient literals without `_JPRB`; their REAL32-to-FP64 conversion remains present. The separate internal GAMMLN calculation uses its distinct full FP64 source literals. These source-defined values are not reduced-precision tuning choices.

`md2asm_cloud_gamma_log` implements the two source log-gamma series with d0 as the positive operand and x0 as mode zero for GAMMLN or one for the widened source constants. `md2asm_cloud_generalized_gamma` takes its positive operand in d0 and the owned RPI in d1, then evaluates the source exponential and reflection expression. The selected operands lie within [2,8]. It retains the source SIN evaluation and divisions even though the positive-domain reflection has zero weight. These raw entries are qualified for the consumed positive operands, not the original negative-domain extension.

`md2asm_cloud_beta_continued_fraction` takes P, Q and X in d0, d1 and d2. It retains the modified Lentz recurrence, the source minimum denominator of 1e−30, its 3e−7 convergence threshold and its 100-iteration limit. `md2asm_cloud_incomplete_beta` uses the same three registers and selects the direct or symmetric source formula. The selected shapes are `1+SQRT(2)` and that value plus one, with X in [0,1]. The beta entry uses a 128-byte frame, the log-gamma entry 112 bytes and the generalized-gamma entry 96 bytes; the continued-fraction entry has no frame. These internal entries do not provide general input validation.

The parent uses a 96-byte frame. Its own assembly graph uses at most 592 stack bytes before an external mathematical call; the allowed math libraries have their own stack use. All entries preserve x18, the AArch64 callee-saved registers and stack alignment. Entry FPCR must be zero, which selects round to nearest with ties to even and gradual underflow. FPCR and errno are preserved on the supported mathematical domains; arithmetic flags added to FPSR remain visible. Rejection uses integer checks and the shared integer parser, so it preserves incoming floating-point state. No fused multiply-add, contraction, reassociation or approximate arithmetic is used.

## External mathematics and source comparison

The immutable R8 provider graph supplies LOG from the pinned Arm math `libpressure-math.so`, EXP from the accepted direct scalar exponential body, and POW and SIN from system libm. The new graph preserves these providers. It calls EXP by the unique `md2asm_exp_original_rounding` name, and retains the three public external APIs. A final executable must link the allowed pressure-math DSO before libm and confirm the actual LOG jump-slot owner; an unrelated process's earlier libm mapping can otherwise preempt that API. This is an external mathematical-library boundary, not an original OpenIFS setup call. Existing provider artifacts remain unchanged.

Three genuine original SUCLDP cases compare all 8328 returned bytes with zero differences. They cover selected inputs, strict pressure ties with changed scaling factors, and a pressure profile with no crossing plus the capped supersaturation interval. Each direct raw call passes the seeded ABI check. The three new guarded-parent cases compare with those retained source returns without another original call. The original human-readable namelist and diagnostics return errno zero; the no-I/O utility preserves its incoming errno. Both raw traces remain retained, and their FPCR/FPSR agree exactly. No flags are forced to imitate omitted diagnostic I/O.

The 211 consumed gamma and beta cases compare all 1688 scalar-result bytes and immediate status with unchanged source functions through 422 source/native ABI calls. Every native mask is zero. Independent system-gamma and adaptive-Simpson integration checks give a maximum generalized-gamma relative error of 1.26e−7 and beta absolute error of 6.18e−9, both below the selected 1e−6 limit. Another 1293 relations check monotonic tables, bounds, rate scaling and pressure selection. These limits describe the original approximations and are preserved without repair.

The parent gate passes 45 atomic rejects and 14 successful complete-buffer ranges beside protected pages. An isolated component executable links the production assembly and allowed mathematical/system libraries, compares all 2800 output/status bytes exactly, and checks the actual LOG/POW/SIN slots. It loads no OpenIFS, harness or Fortran library. Its local C driver only reads explicit verification input buffers and writes returned bytes; it supplies no numerical calculation and is excluded from publication. No forecast was run, and enclosing SUPHEC and complete autonomous-forecast claims remain pending.
