# Selected grid field profile defaults

`md2asm_initialize_selected_grid_field_profiles(profiles)` constructs the nine source-input profiles required by the selected eight-field grid configuration. The records are Q, L, I, S, R, A, O3, NOGW1 and NOGW2, each 256 bytes. O3 remains an inactive profile. These are settings used by later registration and attribute calls; they are not completed field records or initial numerical arrays.

The AArch64 interface takes the 2,304-byte profile buffer in x0. The mapped writable buffer has 8-byte alignment and an explicit fresh zero preimage. The child checks every incoming word and FPCR = 0 before any store. It returns 0 on success or 2 before mutation on a checked failure. Zero incoming bytes are a declared owned-storage policy. Source-unwritten names, codes, chemistry members, padding and NOGW REFVALI retain that policy; they are not called source-declared physical defaults.

The fixed supported setup uses ECMWF mode, NCONF 1, 19 levels, LSLAG/LSPRT/LTWOTL/LRHSVWENO true, LEPHYS/LSLPHY/LEPCLD true, LEO3CH false, global spherical geometry and inactive French/composition branches. The incoming LTRAJHR logical is explicit owned zero. Its separate source and ELF evidence shows an uninitialized four-byte original module object in a zero-filled load segment, with no selected initializer; this is a fresh-storage compatibility boundary, not a Fortran declared-default claim. The actual input contains empty dynamics groups and selected NAEPHY controls. Production reads none of those original objects.

For the first seven profiles, source NREQIN is 1, REFVALI and REFVALC are the exact FP64 sentinel −999, and BETAMFBC is 1. LREQOUT, LGPINGP, LPC and LADV are true. The first six have LGP true, while O3 has LGP false. LPHY is true for Q, A and O3; LPT is true except for A. Q and O3 use LQM, the other five use LQM3D, and only Q enables LVWENO. The five water profiles enable LMASSFIX. All remaining declared false settings retain the fresh zero value.

The two NOGW profiles have exact 16-byte names `TENUNOGW        ` and `TENVNOGW        `, GRIB codes 228134 and 228136, LGP/LREQOUT/LT5 true and BETAMFBC 1. Their other supported flags remain false. Their REFVALI is source-unwritten zero, and REFVALC is source-assigned zero. Later selected registration computes actual time-level choices from NCONF and passes fixed no-trajectory flags; therefore the NOGW profile LT5 setting does not itself allocate a trajectory field.

The raw helper performs no floating-point arithmetic and has no child, external callable, original module data, original type object or virtual-table input. It uses no stack and preserves SP, x18, x19–x29, all SIMD registers, FPCR, FPSR and errno. Caller-saved integer registers and condition flags may change. Source constants are written as exact words. The production DSO has no required shared library or undefined symbol.

The original profile assignments are in `arpifs/setup/sudefo_gflattr.F90`; typed profile offsets are retained in `field_component_reset_reference/typed_registration_layout.json`. A separate verification control prepares an explicitly owned typed context and calls genuine full SUDEFO_GFLATTR. Two cases compare all 4,608 source/direct profile bytes, with four direct ABI/status masks zero and matching immediate genuine-source status. The 314 independent relations check species/input flags, mass fixing, exact sentinels and names, and the accepted interpolation-name choices. Guard bytes and four before-write rejection cases pass. The separate original control's x18 difference remains recorded.

This child does not include NAMGFL edits, the complete SUCTRL caller or the full selected configuration. Its source-unwritten boundary and fixed control scope are explicit. No original program, forecast harness or model run is part of production or this qualification.
