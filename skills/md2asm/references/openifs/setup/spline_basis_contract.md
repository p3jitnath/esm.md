# Vertical Spline Basis

A spline joins short polynomial pieces at positions called knots. This child calculates the weight of each basis spline at one dimensionless vertical coordinate. It implements the complete numerical body of `arpifs/setup/suvfe_basis.F90`; the selected caller is `SUVFE_CPSPLINES` inside the new hydrostatic spline route of `SUVERTFE`. Profiling calls are omitted diagnostics. No forecast calculation is omitted.

## Interface And Storage

`int md2asm_vertical_spline_basis(const int32_t *order, const double *value, const int32_t *basis_count, const double *knots, double *weights)` uses the Arm procedure call standard. Its five addresses enter in x0 through x4. The first two integer inputs use four bytes each, `value` uses eight bytes, `knots` contains `basis_count+order` FP64 values and `weights` contains `basis_count` FP64 values. Integer addresses need four-byte alignment and FP64 addresses need eight-byte alignment. All buffers are mapped, with read-only inputs disjoint from the output. The caller owns all storage. The child has no allocation, external call, original module data, class metadata or callable input. Its standalone object uses 224 private stack bytes with 16-byte alignment, touches only caller-saved registers and leaves x18 unchanged.

The supported order is two through four, and the basis count is at least the order and at most 24. Knots are finite, nondecreasing and between zero and one. Both endpoints have exactly `order` repeated knots; any other knot repeats at most `order` times. The value is finite. Return zero means complete weights were stored. Return two means a scalar, alignment or knot check failed before output mutation. Buffer mapping, extents and disjointness are caller preconditions. The routine does not change its inputs or bytes outside the complete output.

## Ordered Calculation

The first-order weight is one when `knot(i) <= value < knot(i+1)` and positive zero otherwise. For each order j from two through the requested order, increasing i replaces its weight by two terms. The first term is `((value-knot(i))*old(i))/(knot(i+j-1)-knot(i))`; the second is `((knot(i+j)-value)*old(i+1))/(knot(i+j)-knot(i+1))`. Each subtraction, multiplication, division and addition rounds separately to FP64. A term with zero old weight is positive zero and does not execute its division. Increasing i keeps the old right neighbour available until it is consumed. If `abs(value-1)` is smaller than the smallest positive normal FP64 value, every returned weight is positive zero except the last weight, which is one. This source endpoint test runs after the recurrence.

Use round-to-nearest with ties to even, gradual underflow and FPCR zero. Fused operations, reassociation and approximate division are forbidden. Incoming floating-point flags are retained, and executed source operations may add flags. The child leaves the C error indicator unchanged because it has no external call.

## Acceptance Boundary

The separate genuine Fortran source supplies the numerical reference. Critical cases include knots produced by the genuine original fixed-order knot setup from retained 19-level eta input, repeated interior knots, exact knots, adjacent floating-point values, both material endpoints and outside points. Every returned byte, input byte, output guard and immediate numerical status is compared. An independent calculation uses the divided-difference definition of a B-spline, with distinct knots for that check, and checks positivity, compact support and a sum of one with a rounding allowance. Unsupported input checks protect output mutation. All production arithmetic is emitted directly in assembly; the source control and input preparation remain verification-only.
