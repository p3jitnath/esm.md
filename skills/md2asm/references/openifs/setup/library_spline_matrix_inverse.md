This child computes the complete `MINV_CALLER` matrix result for the seven distinct 139-by-139 matrices generated by the retained five 137-level integral and derivative spline operators. A matrix inverse converts sampled spline values into their coefficients. FP64 means the IEEE binary64 format, with 53 significant binary digits. Each matrix owns 154,568 bytes, aligned to eight bytes, with the row index varying fastest in column-major order. All four complete spans are mapped and mutually disjoint. The input and scalar words are read-only. The floating-point control register, FPCR, is zero, which selects nearest rounding with ties to even and gradual underflow. The caller provides stack capacity for the 314,976-byte private frame and the public library's nested calls.

Before any floating-point arithmetic or public output write, the child checks null addresses, scalar and matrix alignment, four complete end-address additions for unsigned wrap, pairwise overlap, dimension 139, scaling flag one, FPCR zero and every input word for a finite exponent. Return two means interface refusal; output and status remain unchanged. A mapped span is a caller obligation, not something an address check can establish.

Return zero means the complete output is committed. Return three means a public factorisation argument error, condition-estimation error, reciprocal condition no larger than the source threshold, or inversion error. Such failure leaves the complete output unchanged. Numerical work may add the same floating-point exception flags as the original route. ## Ordered calculation

Start the diagonal average at positive zero. Add each absolute diagonal entry in increasing index order, then divide once by 139. If the result is positive, divide each input entry by that average, with row outer and column inner, into `ZMO`; otherwise copy the complete input. Copy `ZMO` to `ZMAT` with the original row-outer, column-inner order. For each column in increasing order, add absolute entries in increasing row order from positive zero, then update the largest column sum. This is the matrix one-norm supplied to the condition estimator.

Call `DGETRF` with both dimensions and leading dimension 139. Reject negative `INFO`; positive `INFO` proceeds to the original condition check. Next call `DGECON` with norm character `1`, the complete factor, the original matrix norm, the same 556-word FP64 workspace and a separate 139-word integer workspace. Reject nonzero `INFO`. The reciprocal condition estimates how sensitive the inverse is to small input changes; values near zero indicate a nearly singular matrix. Compare it with `100*TINY(binary64)`, where `TINY(binary64)` is the smallest positive normal FP64 number. Reject values no larger than this threshold, whose exact word is `0x0079000000000000`. Next call `DGETRI` with the original pivots, the same FP64 workspace and the original `LWORK=556`; reject nonzero `INFO`.

Copy the complete inverse from `ZMAT` back to `ZMO` with row outer and column inner. Finally, if the diagonal average is positive, divide each inverse entry by the same average with that order; otherwise copy it. Only this final stage writes `output`. Each ordinary addition and division rounds separately. The assembly introduces no fused operation, contraction, reassociation, approximate operation or reduced precision. The qualified public library retains its original numerical implementation.
