# Owned Surface State Startup

Revision 1 joins the accepted selected surface metadata, numerical allocation, default assignment and GRIB input stages. GRIB is the input file format used by this forecast. A surface field stores one value at each horizontal grid point, while soil and snow fields also contain depth levels. This component owns every stage from fresh surface storage through the loaded initial state, with no original MODEL object, module variable, procedure table, prepared model-state packet or OpenIFS callable.

## Input And Output

The interface is int md2asm_initialize_selected_surface_state(path, constants, physics, surface, trajectory, descriptions). Registers x0 through x5 contain a zero-terminated input-file path, an unchanged 520-byte owned physical-constant record, an unchanged 448-byte owned TEPHY record and writable surface, trajectory and description records of 18,224, 408 and 46,080 bytes. All records require eight-byte alignment and complete mapped, nonwrapping spans. The three complete output records initially contain zero bytes throughout and are disjoint from every input and each other. Immutable inputs may overlap. The path contains one through 4,095 bytes before its zero terminator, and its possible 4,096-byte address span must not wrap. Only bytes through the first zero are read.

The constant setup flag is one. The physical and configuration values come from the accepted owned producers and retain their frozen selected meanings. TEPHY must contain LEOCCO and LEOCWA true, while the metadata child checks its ten consumed controls. The selected model has 2,048 points, 24 rows per block, 86 blocks, 19 atmospheric levels, four soil layers, five snow layers and two time levels. The last block contains eight physical points and sixteen padding rows.

The component produces the complete selected surface metadata and its seventy owners, then all thirty-four numerical owners. Their ten nonempty allocations total 7,149,696 bytes. Empty shapes still own a nonnull zero-length allocation. Exactly 348,288 numerical bytes remain source-unwritten after this startup. SP_SB retains all 198,144 bytes in its second time level and 1,536 padding bytes in the last block of its loaded planes. SD_VD retains all 148,608 bytes in its nine input-request-zero diagnostic planes 54, 55 and 115 through 121. These bytes retain the allocator's incoming bytes until a later declared producer changes them; verification supplies matched guarded preimages. The other 6,801,408 numerical bytes are assigned by the source allocation, default or file stages. No production fill is added for those bytes.

## Ordered Ownership

Allocate a private 107,664-byte plan workspace, then construct a private shape record containing the row and block counts at the offsets consumed by the accepted integer default collector. This record supplies those two owned integers only; it is not an original geometry or MODEL constructor. Collect the actual owned field requests and raw defaults, requiring ten nonempty owners and 306 assignments. The accepted default setter writes all allocated rows, including padding.

Read the five complete numerical owner descriptors, checking their complete fixed shapes, bounds, strides, element type, byte capacities and bias. Read all fifty-two input identifiers and request flags from the owned field metadata in the accepted 47-plus-five file order, and check each identifier, destination field index and request against the selected source map. The five owner spans and all identifiers therefore come from their live owned producers.

Call the accepted complete surface loader with the actual GRIB path, configuration, owners and identifiers. It owns decoding, source-order selection, physical conversions and placement into the five affected owners. Only physical points receive file values, while previous defaults and padding retain their declared bytes. All existing FP64 equations, rounding points, source branches and acceptance limits remain unchanged. The earlier independent physical checks and exact child results remain applicable.

The paired md2asm_release_selected_surface_state(surface) entry releases all thirty-four numerical owners first, then the seventy metadata owners, and preserves the source-defined released descriptors and borrowed alias bytes. The caller must not read released owners through an alias. A null release is a successful no-op. The caller retains the three outer records.

## ABI And Failure

Both entries preserve x18 and all saved integer and vector registers. The constructor requires FPCR zero and preserves it. It retains incoming arithmetic status and errno through the metadata, allocation and plan stages, then preserves the loader's returned FPSR and errno across private-workspace release. The constructor has a 272-byte, sixteen-byte-aligned stack frame; paired release uses 32 bytes. Private helpers use only their declared scratch integer registers and introduce no physical arithmetic.

Return zero after complete success. Return two before mutation for unsupported input. A metadata allocation failure returns 101, a numerical allocation failure returns 201 and private plan allocation failure returns 301. Internal default, conversion-configuration and input-plan failures return 401, 501 and 601. A loader failure returns 1000 plus its unchanged child status. Every post-construction failure releases all acquired owners and restores all three fresh output records to zero, retaining the status of the stage that failed. No original fallback is available.
