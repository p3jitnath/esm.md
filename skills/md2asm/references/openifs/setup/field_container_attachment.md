# Selected field-container attachment

This parent follows the selected FIELDS_CONTAIN path after initial and next-time field owners exist. It constructs T1, T0 and T9 containers directly inside the final 529,288-byte FIELDS record, then associates FIELD with T0. The actual owned MODEL has LTWOTL=true, LSLAG=true, LPC_FULL=false, LEPHYS=true and LMPHYS=false. PC and PT therefore remain untouched. The parent composes the qualified container child and owns its call order without original module state, object constructors or method tables.

`int md2asm_attach_selected_field_containers(void *fields, size_t capacity, const void *geometry, const void *model, const void *constants, const int32_t controls[2])` uses x0 through x5. Geometry is the complete live 20,400-byte vertical context, with its first 17,096 bytes in the source Geometry layout. MODEL covers 4,275,088 bytes. Constants covers 520 bytes. Controls contains the source-produced NUNDEFLD and zero dynamic-namespace count. The enclosing input stage must establish that the optional dynamic_namespace file is absent. All root addresses must be nonnull and eight-byte aligned except controls, which needs four-byte alignment. All declared ranges and consumed pointer targets must be mapped, nonwrapping and disjoint as required by the children; the caller owns these range properties.

Fields must have STATE_MODEL associated with the supplied MODEL, TGFL%YGFL associated with MODEL+192, all three containers fresh, and FIELD null. The parent checks those associations and actual selected branches before creation. The final container addresses are FIELDS+28184 for T1, +26432 for T0 and +29936 for T9. Borrowed GMV, TGFL and TSURF are at FIELDS+1856, +3416 and +4512. The live geometry supplies NGPTOT at 7376, NPROMA at 5144 and NFLEVG at 5224. It constructs the eleven level extents from those live values, surface group NLEVS and the six live chemical/emission counts. Four source physical attributes come from constants RV192, RCPV208, RCW344 and RCS352. No constructed numerical packet supplies a production input.

Creation calls T1 without horizontal derivatives, T0 with derivatives and its two live third-dimension counts, then T9 with derivatives. All use fixed nproma attachment. After all three succeed, FIELD receives the final T0 address. The parent preserves every other FIELDS byte and all borrowed numerical owners. The original active-field list is used only for human diagnostics and is omitted by this quiet utility. Every consumed state and normal returned status remains part of the complete source-parent comparison.

Return 0 means success, 1 means allocation failure and 2 means unsupported input. On failure, every new container owner is released and FIELD stays null. Partial descriptor bounds can remain as declared by the child. `int md2asm_release_selected_field_containers(fields)` releases T1, T0 and T9, including the child's explicit cleanup of otherwise leaked allocations. It clears FIELD and leaves all older FIELDS/MODEL/Geometry owners for their existing finalizers. This is an owned attachment lifetime, not whole FIELDS_DELETE body credit.

Both entries preserve x18, callee-saved registers, 16-byte stack alignment, FPCR, FPSR and errno. Their only production dependencies are the qualified attached-container graph and libc allocation services. Exact complete FIELDS state, every new owner, all borrowed owners, source-relative call order and final lifetime state must pass the changed-parent gate before integration. This checkpoint does not create an autonomous forecast or complete remaining field-open methods.

`int md2asm_require_default_field_namespace(int32_t *count)` receives a mapped four-byte output in x0, aligned to four bytes. It checks the optional relative path `dynamic_namespace` with Linux `faccessat`. A missing path sets the count to zero and returns 0. A present or inaccessible path returns 2 and preserves the output. It retries an interrupted call. The leaf uses no stack or allocation and preserves the project ABI, FPCR, FPSR and C errno; Linux returns its error value directly in x0. This selected absent-file utility does not implement dynamic field-name parsing.
