# Computational Geometry And Resolution Scale

The selected regular T21 SUGEM2 route also constructs six nonblocked computational-geometry arrays and one resolution scale. This child uses the same 32 north-to-south Gaussian rows, 64 longitude points per row and 2048 points as the nonblocked spherical point-geometry child. It receives already calculated latitude sines and positive latitude cosines from the admitted direct SULEGA construction. It does not receive calculated longitude tables, computational metrics or a resolution-scale packet.

The constructor ABI is `int md2asm_initialize_computational_geometry(record, physical, latitude_sines, latitude_cosines)`. Registers x0 through x3 address a writable 384-byte TCSGEOM record, the shared read-only 48-byte physical record, and two read-only 256-byte FP64 arrays. Eight-byte alignment, mapped nonwrapping spans and a result record disjoint from all inputs are required. The physical record retains stretch 1, RC2P1=2, positive-zero RC2M1, radius 6371229 metres and pi bits 0x400921fb54442d18 in its first five words. The sixth rotation word is not consumed by this child. Serial partition maps must have the same declared identities as the spherical point-geometry interface; a native caller must check them before using this bounded child.

For each point in original row-major order, calculate longitude as positive zero plus `(pi*REAL(2*(k−1)))/64`. Write RCOLON as its cosine and RSILON as its sine, using the accepted direct original-rounding primitives. Write RINDX as longitude index k and RINDY as latitude index j, each converted exactly to FP64. Write RATATH as `(RC2M1+mu*RC2P1)/((stretch*radius)*cosine_latitude)` and RATATX as positive zero. RATATH has units of inverse metres under this expression. The YOMCSGEOM description instead says radius times tangent; the implemented SUGEM2 expression and its inverse-length meaning are retained here. These are the source SUGEM2 expressions, with separate rounding after every multiplication, addition and division.

The result has six 64-byte GNU Fortran 12 rank-one FP64 pointer descriptors in order RCOLON, RSILON, RINDX, RINDY, RATATH and RATATX. Each owner has 2048 elements, bounds 1 through 2048 and stride one, giving 98304 complete numerical bytes. All six incoming descriptors must be unassociated. Return zero transfers all six malloc owners to the caller. Return one frees prior owners and clears all six data pointers after allocation failure; partial descriptor bounds can remain. Return two rejects an unsupported checked input before mutation. The 176-byte frame is sixteen-byte aligned and preserves x18 and the required AArch64 saved registers. Existing allocation, descriptor and arithmetic mechanisms are reused.

The separate leaf `md2asm_spherical_resolution_scale(output, physical, truncation)` receives an eight-byte FP64 output pointer in x0, the physical record in x1 and a four-byte integer address in x2. The supported truncation N is 1 through 21. It computes integer `N*(N+1)`, converts that exact integer to FP64, then calculates `pi*sqrt(((8*radius)*radius)/REAL(N*(N+1)))`. This is the original SLHDP expression, in metres. It stores exactly one output word, uses only caller-saved registers and allocates no storage. Invalid checked inputs stop through C abort before the result is stored. Its scalar constants retain the same selected physical bits.

Both entries require FPCR zero, preserve incoming sticky FPSR bits while allowing the numerical instructions to add the same flags as the source and retain the source rounding points without fused arithmetic or approximations. Production dependencies are only the already accepted direct sine/cosine and integer rounded-product helper, plus C allocation, failure cleanup and abort. No original Fortran callable, constructor, vtable, type descriptor or precomputed numerical state supplies a production stage.

Focused verification compares all 98304 bytes and complete descriptor headers with a separate source control, using direct SULEGA inputs and preserving its complete numerical owners. Seeded ABI/status checks reuse the existing boundary. The scalar leaf is compared with the source formula at truncations 1 and 21. Independent checks use the longitude unit-circle identity, exact integer coordinate maps, the latitude derivative relation and the physical resolution-scale equation. These children pass in the admitted complete SUGEM2 composition described in [Spherical Geometry Construction](spherical_geometry_setup.md). They add no separate original routine credit.

## Operational Resolution Scale

The standalone `md2asm_operational_spherical_resolution_scale(output, physical, truncation)` extends the same resolution formula to every integer truncation from one through 1279. Truncation is the largest spatial wave number retained by the spectral grid. The output is a length in metres. This entry uses the same radius, pi value and separately rounded arithmetic as the selected leaf above. It does not construct the six operational computational-geometry arrays.

Registers x0, x1 and x2 address eight writable output bytes, the complete forty-eight-byte read-only physical record and a four-byte read-only signed truncation. The caller supplies mapped, nonwrapping, disjoint spans with eight-byte record alignment and four-byte integer alignment. Only the radius and pi words at physical offsets 24 and 32 are read. The remaining physical words retain their incoming bytes. The leaf uses caller-saved registers and no stack, preserves FPCR and adds the original numerical flags to FPSR. Unsupported checked inputs call C abort before storing output. The normal path has no external call.

Both incoming status profiles match the original source formula at every supported truncation, giving 2,558 exact output words and zero ABI masks. Complete inputs, output guards and immediate status are checked. The upper-limit refusal at 1280 leaves shared output unchanged. Independent arithmetic with 120 decimal digits reproduces every ordered FP64 result and checks the physical length within 5e-16 relative error. The earlier lower-bound and physical-input refusal evidence is reused. This qualifies the complete scalar leaf; enclosing geometry and the operational forecast remain separate work.
