# Owned serial partition array storage

This component owns the 34 array allocations used by selected SUMP. Phase 0 implements complete SUALMP1 allocation, phase 1 owns the two block index arrays allocated directly in SUMP, and phase 2 implements complete SUALMP2 allocation. The component allocates metadata and storage only. Transform queries, integer partition calculations and later map filling remain caller stages; the allocator does not substitute stored results for them.

The ABI is `int md2asm_allocate_serial_partition_arrays(void *geometry, const int32_t partition[5], uint64_t phase)`, with x0 through x2 carrying the inputs and w0 returning status. Geometry is a complete caller-owned 17096-byte namespace with source-compatible scalar and descriptor locations from the typed layout receipt. Partition contains NPRTRV, NPRTRW, NPRTRNS, N_REGIONS_NS and N_REGIONS_EW; these five partition counts are all 1 in the supported serial route. Phase 0 reads only its consumed geometry dimensions. Phase 1 reads NPROMA and NGPBLKS. Phase 2 reads local levels, latitude bounds and local/global point counts. These inputs must already come from their source-selected producers. All record and pointer inputs are eight-byte aligned, partition words are four-byte aligned, and all complete buffers are mapped and disjoint. No original module object, type table, method table or constructor supplies a production input.

Before mutation, the selected phase validates dimensions and every selected data pointer is null. Fresh storage has canonical GNU descriptors, preserving original bounds, element types and strides. LSPLITLAT is a four-byte logical array; the other owners are four-byte integers. The source does not write any payload in these allocation stages, so production leaves every allocated byte unchanged. Zero-element owners allocate at least one storage byte while retaining the source empty descriptor. No production allocation preimage fill is applied.

Return 0 means complete, return 2 rejects before mutation, and return 1 reports an allocation failure. Failure frees all owners created by this phase and clears their pointers; partial descriptor bounds may remain. `int md2asm_release_serial_partition_arrays(void *geometry, uint64_t phase)` frees only the selected phase's owners and clears their addresses, preserving every other record byte. Callers release completed phases once, usually in reverse construction order, before destroying Geometry. There are 26, 2 and 6 owners in phase order. The separate source reference and direct allocator use a shared explicit allocation preimage only in verification, so complete returned payload bytes can be compared without assigning undefined source values after return.

The selected dimensions cover T21, 32 Gaussian latitudes, 2048 global points and 24-by-86 block storage, including a final 8-point active block. Halo bounds are supplied explicitly by the earlier dimension stage; the actual default stencil width 2 gives NDGSAG=-1 and NDGENG=34. Empty vertical levels and no-halo bounds are critical storage controls. The exact checked ranges, typed locations and row formulas are recorded in the local source/ready receipts. All integer size products are bounded before allocation. Pure metadata work preserves FPCR, FPSR, errno, x18 and all required saved registers. Only malloc/free and errno access are external services.

Acceptance compares the genuine original allocation bodies and exact SUMP block allocation source statements with complete source-before/after records, every full associated descriptor, complete allocated payload preimages and immediate ABI/status. Original diagnostic allocation prints and profiling may be omitted when their source-selected numerical/state effects are absent and returned status agrees. Complete SUMP partition/map and owned-parent integration remain separate.

The setup frame is 272 bytes with 16-byte alignment, and its sixteen private metadata parameter words occupy bytes 128..255. The release frame is 112 bytes. The three checked source cases are actual halo bounds with 19 levels and two distinct allocation preimages, and no-halo empty-level/local-domain bounds. Nine phase cases compare 119,244 complete allocated payload bytes and 307,728 complete record/released bytes, with 27 ABI/status calls, 102 descriptor invariants and 11 atomic rejections. Actual block index owners each contain 2064 integers, including the sixteen inactive final-block slots. All source-unwritten payload bits retain the verification input preimage. No per-allocation failure injection or extra allocator framework is part of the check.
