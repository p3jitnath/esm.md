# Standard atmosphere at model pressures

This assembly child supplies the single-column ICAO call from `SUSTA` to `PPSTA`. Its inputs are a freshly calculated nine-layer atmosphere, model-level pressure in pascals (Pa), and live gravity and dry-air gas constants. It supplies temperature in kelvin (K) and geopotential in square metres per square second. It does not call the original Fortran or import an initialized atmosphere table.

The application binary interface (ABI) is `int md2asm_standard_atmosphere_profile(double *temperature, double *geopotential, const double *pressure, const double *layers, const double *physical, uint64_t levels)`. Registers x0 through x5 hold these six arguments; w0 returns zero on success or two when a checked shape, address or pressure requirement fails before any output write. All arrays have eight-byte alignment and mapped, disjoint spans. Temperature, geopotential and pressure each contain `levels` FP64 words, with 1 through 256 levels supported. The layer input contains four nine-word arrays in order: height, temperature gradient, temperature and pressure. Its 288 bytes come from the qualified standard-atmosphere layer child. The 32-byte physical input contains gravity, dry-air gas constant, dimensionless RPLRG scalar and surface pressure; this child uses the first two words. Inputs remain unchanged.

The child first calculates each model-pressure logarithm, as the enclosing source `SUSTA` does. It then follows `arpifs/pp_obs/ppsta.F90`: calculate each layer-pressure logarithm, inverse pressure and inverse nonzero gradient; choose the first layer whose next boundary pressure is no larger than the model pressure; and evaluate the source gradient or constant-temperature expression. A pressure exactly on a boundary uses the lower-altitude layer. It supports positive finite pressures from 2^-52 Pa through the largest finite FP64 value. Its numerical inputs must otherwise satisfy the qualified layer-child contract.

For a nonzero gradient, it computes height as `z + (T * inverse_gradient) * (POWER(p * inverse_pressure, (-gradient) * (RD / RG)) - 1)`, then temperature as `T + gradient * (height - z)`. For a zero gradient, it computes height as `z - (T * (RD / RG)) * (LOG(p) - LOG(layer_pressure))` and copies the layer temperature. Both branches store `height * RG` as geopotential. Each arithmetic operation rounds separately in FP64. The source order, signed zeros and existing sticky floating-point status bits are retained; arithmetic may add status bits.

The child calls only the accepted direct POWER and positive natural LOG leaves. It uses a 2,464-byte frame with 16-byte stack alignment, allocates no heap storage, preserves x18, x19 through x29, the low halves of v8 through v15, the incoming floating-point control register and errno, and adds the same numerical floating-point status flags as the source. FPCR must be zero. Original profiling and diagnostic writes are omitted; no forecast calculation is omitted.

Verification uses a separate Fortran control with the original pressure classification and evaluation expressions. It compares complete temperature and geopotential arrays, unchanged input bytes, edge guards, raw status and saved-register state. Independent hydrostatic inversion checks remain separate. The enclosing standard-atmosphere construction passes the selected complete forecast check.

The [complete forecast check](../../../../../src/openifs/README.md#verification) passes for the selected route. Its declared upstream data and branch limits remain in force.
