# Selected Orography Initialisation

This stage implements the selected SUOROG route after SUSPEC loads the spectral terrain, before SUGRIDF places the grid fields. Orography is the shape of the ground. The input stores ground geopotential, which is gravitational potential energy per unit mass, in square metres per square second. Its two horizontal derivatives have units of metres per square second. Assembly calculates the terrain and both derivatives from the live input coefficients, then fills the two Geometry storage layouts. No original OpenIFS routine, global variable or saved numerical packet supplies a production stage.

The supported case is spherical, hydrostatic and serial. It has 506 FP64 spectral coefficients, 2,048 grid points, 24 points per block and 86 blocks. LELAM and LGRADGP are false, while MYSETV and NPRTRV are both 1. The stage first follows SPEREE and calls the public ECTRANS INV_TRANS interface for one scalar field. It then follows SPEUV with KINP equal to 2. Each original terrain coefficient is multiplied by its live negative Laplace eigenvalue, while the other spectral field begins with positive zeros. The imaginary coefficients for zonal wave number zero are assigned positive zero. A second inverse transform produces the two derivatives. The scalar transform precedes the derivative transform, as in the original source.

The interface is `int md2asm_initialize_selected_orography(Geometry, geometry_bytes, spectral, spectral_bytes, controls, control_bytes)`. Its six arguments occupy x0 through x5. Geometry has at least 17,096 bytes, the spectral array has at least 4,048 bytes and controls has at least 16 bytes. Records and real arrays are aligned to eight bytes, while controls is aligned to four bytes. Controls contains four INTEGER4 values in the order LELAM, LGRADGP, MYSETV and NPRTRV. They must be 0, 0, 1 and 1. All declared input and output extents are disjoint. The original-file entry supplies the second field of its live SP2D owner, at base plus 4,048 bytes. The loaded-orography flag is a Boolean and is not this array.

Geometry already owns 86 YROROG records and 258 terrain payloads. Their first three descriptors must have the supported contiguous shapes, including eight active points in the final block. Named typed queries establish the consumed offsets and all three YROROG_B rank-two descriptor locations. The live RLAPDI descriptor covers degrees from minus one through 23 and has offset 1. Each degree uses that declared offset before its separately rounded multiplication. MYMS covers the 22 serial wave numbers, and NASM0 supplies their actual coefficient positions.

After both transforms, the producer allocates three YROROG_B arrays of shape (24, 86). It copies each 2,048-point result into both Geometry layouts in source order. The final 16 unused blocked rows remain source-unwritten. All other Geometry bytes and every input coefficient remain unchanged. A private workspace holds temporary transform descriptors, coefficients and grids. Return 0 means success, 1 means allocation failure and 2 means an unsupported input. Invalid inputs return before public writes. Allocation failures release the private workspace and any newly acquired blocked owners before returning, with the incoming Geometry and existing terrain payloads unchanged.

The release entry `md2asm_release_selected_orography(Geometry)` accepts the Geometry address in x0. It frees the three new blocked owners and clears only their base words. It returns 0 for success and 2 for a null or unaligned address. Call it before the accepted parent Geometry release, which still owns the earlier 258 payloads and outer record array. The constructor admits only fresh blocked owners, so it refuses a repeated construction until release.

The assembly preserves x18, all required saved registers and 16-byte stack alignment. Its construction frame has 1,024 bytes and its release frame has 64 bytes. Every FP64 multiplication rounds separately. Fused operations, reassociation and status masking are forbidden. The caller requires FPCR equal to zero. Public ECTRANS state comes from the already established live owned resolution. The only external production calls are its public `inv_trans_` interface and libc `malloc` and `free`.

The genuine component comparison uses the same live Geometry and original-file coefficients. It matches 156,904 complete bytes with explicit correspondence between owner base addresses. This includes all 86 row records, 258 payloads, three complete blocked owners, Geometry metadata and unchanged input coefficients. Source blocked owners are preallocated with their genuine typed descriptors and a common 0xa5 preimage. Direct allocations receive that same preimage before the call. All 16 source-unwritten final rows therefore remain visible in the comparison, without output repair. A private verification-only library handle calls the original source and supplies no production object or stage.

An independent physical check supplies a constant geopotential of 1,024 square metres per square second. All 2,048 points retain that constant exactly and both derivatives are zero, giving 6,144 physical relations. The original-file case gives 6,144 finite values and 6,144 exact correspondences between the two storage layouts. All 13 native application binary interface checks have mask zero. Four allocation-failure positions and five unsupported extent, layout or model conditions pass their atomic failure checks. Original and direct calls naturally return FPSR 16 and errno zero in the matched warmed transform state. The complete forecast check remains separate and pending.
