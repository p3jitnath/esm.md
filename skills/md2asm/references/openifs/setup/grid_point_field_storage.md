# Owned Grid Point Field Storage

A grid point value describes the atmosphere at one horizontal position. This component constructs the complete selected YOMGFL::TGFL record used by the initial-input path. It composes CNT0's association to an explicitly owned field configuration with the four allocation statements in SUSC2C. It implements the TGFL release statements from DEALXMO and offers ZERO_YOMGFL as a separate operation. The other SUSC2C children, SETUP_GMV and ALLO_SURF, remain separate unconstructed sibling layers; this component does not claim their bodies or the complete SUSC2C body.

The raw initializer md2asm_initialize_gridpoint_field receives a fresh zero 1,096-byte record in x0, seven read-only int32 configuration words in x1, and an eight-byte aligned borrowed address of a caller-owned TYPE_GFLD configuration in x2. The seven words are NPROMA, level count, block count, NDIM, NDIMSLP, NDIMPT and NDIMPC. Supported row length, level count and block count are 1 through 64, 1 through 64 and 1 through 128. The selected field dimensions are exactly 8, 2, 0 and 0. The original selected case uses 24, 19 and 86 for the first three words. All arguments are mapped for their full declared bounds and disjoint; the record is eight-byte aligned and the seven-word input is four-byte aligned. The borrowed configuration must be the caller's persistent 1,359,136-byte TYPE_GFLD namespace and outlive the TGFL record. This component stores its address and does not read its values or construct its field maps. Its producers can construct those maps in phases, but each later consumer must wait for the fields it needs.

TGFL contains eight 136-byte GNU rank-four descriptors, followed by the borrowed YGFL pointer. Allocation order is GFL, GFLSLP, GFLPT and GFLPC. Their shapes are (NPROMA,levels,8,blocks), (NPROMA,levels,2,blocks), (NPROMA,levels,0,blocks) and (NPROMA,levels,0,blocks). The last two arrays are allocated with zero logical extent and a nonnull reservation of at least one byte. GFLT1, GFL5, GFLSLP5 and GFL_DEPART remain unallocated at this source stage. Associated descriptor bytes, including the lower bounds, upper bounds, element strides, offset, element width, rank, type and span, match the typed original source layout. The fresh-record ABI explicitly starts all empty descriptor words at zero.

SUSC2C does not initialize these numerical buffers. The direct allocator preserves every payload byte returned by malloc. A separate md2asm_zero_gridpoint_field entry follows the genuine ZERO_YOMGFL stage: it stores positive zero into the logical elements of allocated GFL, GFLT1, GFLSLP, GFLPT and GFLPC, and leaves the three trajectory arrays unchanged. Its input must be a valid live record from this selected initializer. The raw release md2asm_release_gridpoint_field frees the four selected owners in source order and clears only their base-address words, leaving the borrowed YGFL association and other descriptor words unchanged as DEALXMO does. It can clean up a partially acquired selected record. The caller retains the record, input words and configuration object.

The owned creator md2asm_create_gridpoint_field_context receives the seven-word configuration in x0, borrowed owned YGFL address in x1 and output-pointer address in x2. It allocates a 1,104-byte context whose first 1,096 bytes are the source record and whose final eight bytes hold a private lifetime marker. It publishes the output pointer only after successful construction. md2asm_release_gridpoint_field_context releases the four owners and this outer context. The caller must not use the context after release.

Each public allocator returns w0=0 on success, w0=1 on allocation failure after cleanup, or w0=2 for unsupported inputs before record mutation. The owned creator leaves its output slot unchanged on failure. FPCR, the Arm floating-point control register, must be zero when allocating. All entries preserve FPCR, FPSR, errno, x18, x19 through x29 and v8 through v15, with sixteen-byte aligned stacks. No floating-point arithmetic is needed: descriptor construction, allocation sizes, zero stores and address operations use integer registers. Production depends only on libc malloc, free and errno-address services, with no original callable, module data, type descriptor, vtable or model-state packet.

The raw allocator uses a 160-byte stack frame, raw release and owned creator each use 96 bytes, and owned release uses 80 bytes. The zero stage is a leaf with no stack frame or child call. At the selected shape, the GFL and GFLSLP logical owners contain 2,509,824 and 627,456 bytes. The two zero-extent reservations each retain their one-byte incoming allocation preimage. Verification fills only newly acquired fixture allocations with the same explicit preimage for source and direct calls; production malloc is unchanged.

Three genuine source cases compare 6,276,652 complete payload bytes before and after the separate zero stage, plus 9,864 complete allocated, zeroed and released record bytes, with zero differences after replacing only owner base addresses by owner identities. The borrowed configuration retains 4,077,408 checked bytes across the cases. Eighteen immediate ABI/status calls have zero native failure masks; the genuine original zero stage's x18 change for the smallest shape is retained explicitly. Twenty-four independent origin and zero-value relations, 992 guard bytes, three complete allocation-failure cleanups and four before-mutation rejects pass. A standalone assembly create/zero/release example exits zero with LD_PRELOAD and LD_LIBRARY_PATH removed, and its ELF dependency is libc only. GCC 12.3.0 is the assembler driver. These checks qualify this storage layer, with no complete startup, forecast, timing or whole-parent-body credit.
