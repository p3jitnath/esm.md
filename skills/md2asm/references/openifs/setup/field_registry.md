# Registry Storage Children

This assembly implements storage metadata for the selected OpenIFS forecast. Metadata contains addresses, array dimensions, spacing between elements, names and ownership flags. It contains no weather calculation. The original Fortran source remains a separate control.

`FIELD_REGISTRY_INIT` stores the geometry address and copies the grid dimensions. The registry is 16 bytes. Its geometry address starts at byte 0, its block width starts at byte 8, and its block count starts at byte 12. The geometry holds these 32-bit dimensions at bytes 5144 and 5160. `md2asm_registry_initialize` receives raw registry and geometry addresses in registers x0 and x1. `md2asm_field_registry_init` receives the original two-word class descriptor in x0 and the raw geometry address in x1. It reads the first word of that class descriptor to obtain the registry address. Both entries preserve x18 and all saved registers, require eight-byte record alignment, write only the 16-byte registry, and perform no floating-point operation.

The field-wrapper children construct the original FIELD_2D, FIELD_3D and FIELD_4D records. These records respectively occupy 256, 328 and 400 bytes. Their PTR descriptors refer to the supplied array without copying or changing its values. Their VIEW and DATA pointers are null. ACTIVE is true, THREAD_BUFFER and OWNED are false, and NBLOCKS is the final dimension. The GNU Fortran 12 descriptor has a 40-byte header and one 24-byte stride/lower-bound/upper-bound record for each dimension. A stride counts FP64 elements. Each wrapper rebases the pointer bounds to one while preserving the extent and stride of each dimension. The pointer offset is minus the sum of its dimension strides. No field owns its numerical data.

Each wrapper receives its raw result address in x0 and its input array descriptor in x1. Its input rank is fixed by the entry name. All input descriptors must describe a valid FP64 array of that rank, with addressable bounds and signed 64-bit strides. The result must be eight-byte aligned, must not overlap the descriptor or its numerical owner, and must have the full record size available. The complete result record is initialized deterministically. Unassociated descriptor words that the source leaves undefined are set to zero. A separate typed control compares every source-defined metadata value, normalized PTR descriptor bytes and every numerical owner byte. These deterministic inactive words are a metadata representation rule, and do not alter numerical inputs or output.

These leaf children preserve x18, x19–x29, d8–d15, the stack pointer, FPCR and FPSR. They make no library call. They support noncontiguous input sections and signed strides because registration wraps array sections. Acceptance requires correct geometry/dimension copies, source-equivalent field flags and pointer bounds, exact selected numerical addresses, unchanged complete numerical owner bytes, result guards, and a seeded ABI probe. These leaf checks support the complete registration methods described below; they do not establish autonomous forecast startup.

The direct assembly is written from these records and the source statements. Compiler assembly and intermediate representations are not used to construct it. The typed layout query uses the retained original module interface. Existing accepted weather and input checks are reused.

The three `md2asm_registry_wrap_variable_2d`, `md2asm_registry_wrap_variable_3d` and `md2asm_registry_wrap_variable_4d` entries receive a result record in x0, a sixteen-byte space-padded name in x1 and an array descriptor in x2. Their result records occupy 560, 728 and 896 bytes. They allocate only the corresponding field metadata record through C `malloc`, call the direct field wrapper, then initialize the variable record. NAME and CNAME receive the supplied name, IGRBCODE is -999, LACTIVE is true, all other flags are false, and only FT0 is associated. Return x0 is zero for success. A nonzero return reports allocation failure before the result record changes. The caller owns the allocated field record and must release it once. Its numerical buffer remains owned by its original array. Repeated construction into an existing variable requires the caller to release the previous metadata first. These entries preserve the saved registers and x18 across `malloc`, retain sixteen-byte stack alignment, and use no floating-point instruction. The C runtime allocation may change errno only when allocation fails.

Three registry methods now use the shared variable wrappers. `md2asm_registry_register_geometry` receives the raw registry in x0, the address of its FIELD_VARIABLES pointer slot in x1 and geometry in x2. It allocates the 72,696-byte FIELD_VARIABLES record if that pointer is null. `md2asm_registry_register_ec_physics` and `md2asm_registry_register_radiation` receive the raw registry in x0, an existing raw FIELD_VARIABLES record in x1 and the corresponding source record in x2. They construct respectively 21, 5 and 23 named variable wrappers in original source order. Each source descriptor offset and destination record offset comes from a typed source layout query retained in `registry_wrap_map.json`. That map contains metadata only. No numerical array value is read or written by the assembly.

The FIELD_VARIABLES allocation initializes its complete record to zero, sets each of its 105 scalar variable records' NAME and CNAME to spaces, and sets IGRBCODE to -999. This preserves the original declared defaults and gives deterministic words to the original uninitialized NAME and inactive descriptors. The GMV and GFL methods described below construct their variable records and variable arrays. The geometry, EC physics and radiation methods return zero on success or one on allocation failure. A failure after earlier fields were constructed leaves those metadata allocations live for caller cleanup. They preserve x18 and every saved register, use a sixteen-byte aligned stack, and call only direct children and the C allocation service. They require the complete source records and valid source array descriptors; the caller retains every numerical owner for the lifetime of its views. GMV, GFL and surface registration use the additional direct methods described below.

The GMV constructor receives the result address, padded name, main-array descriptor, next-time-array descriptor, six signed 32-bit field indices and result rank in x0–x5. Its six indices select T0, T1, T9, PH9, DL and DM. T0 is always wrapped, matching the original source. Each optional index is active when it is at least zero. T1 selects the next-time owner; all other views select the main owner. The removed field dimension is immediately before the final block dimension. The constructor retains the original dummy-array convention, so the selected address adds `(index-1)*field_stride*8` to the descriptor base. This rule also preserves source-created inactive addresses; a consumer may read only views whose model contract permits access. The variable flags and all six field-record pointers follow the original constructor. The assembly performs address calculations only. It returns zero on success and one on allocation failure, leaving any earlier metadata records live for cleanup. It uses a 256-byte stack frame with sixteen-byte alignment and preserves x18 and the saved registers across C allocation and direct child calls.

The GFL scalar constructor copies the component name, GRIB code and original flags from a 368-byte TYPE_GFL_COMP record. Its CNAME, IGRBCODE, LACTIVE, LADV, LT1, LT9 and LPHY start at bytes 0, 16, 64, 20, 92, 88 and 100. The original six field indices start at bytes 168, 188, 180, 184, 172 and 176. A field record is created only when LACTIVE is true and that field index is positive. This rule is separate from the variable flags, which retain their original values even when no field is created. Main GFL and GFLT1 descriptors start at TGFL bytes 0 and 136. Each selected view removes the third dimension of its four-dimensional owner through the direct descriptor child. The scalar constructor receives result, padded name, component and TGFL addresses in x0–x3.

A GFL group constructor receives an output descriptor, padded name prefix, component-array pointer descriptor, TGFL address and prefix length in x0–x4. It allocates one 728-byte VARIABLE_3D record for each component. A null component pointer creates an empty associated result. Supported component arrays have lower bound one and at most 255 elements. The original name rule appends an underscore and the single character whose code is the one-based component index; this is not a decimal index. Its original descriptor stride is retained when selecting each component. All associated output-group descriptors use rank one, lower bound one, stride one and 728-byte elements. Their alias descriptors refer to this same owner. These constructors allocate metadata through C malloc, preserve x18 and the saved registers with sixteen-byte aligned frames, and return zero on success or one on allocation failure. They leave earlier metadata live after partial allocation failure. They perform no numerical field calculation.

Surface registration creates three field records for each scalar variable, including inactive variables. A positive MP, MP1 or MP9 index wraps its corresponding source section. A missing component or nonpositive index creates an owned temporary. In this selected one-thread forecast, these temporaries have one final block and THREAD_BUFFER true. A multilevel variable retains TYPE_SURF_GEN%NLEVS, including an empty level extent. No numerical temporary value is initialized by the original allocation constructor or by the direct allocation child; a numerical consumer must define a value before reading it. Their initial bytes are therefore outside this metadata comparison, while every existing numerical source owner remains byte-compared. This does not permit an omitted numerical initialization stage.

The owned-field allocation child receives a raw field record, a signed 32-bit shape array, rank and thread-buffer flag in x0–x3. It allocates the numerical storage through C malloc, constructs matching contiguous DATA and PTR descriptors, marks ACTIVE and OWNED true, and sets NBLOCKS from the last shape element. It returns zero for success or one for allocation failure. Shapes must have two to four dimensions, nonnegative extents and a product that fits the declared allocation bounds. The result has the same record bounds and alignment as its wrapping counterpart. The caller releases the owned numerical allocation and the field record once.

The surface scalar constructor receives result, padded name, source-array descriptor, metadata address or null, TYPE_SURF_GEN address, raw registry and result rank in x0–x6. MP, MP1 and MP9 start at metadata bytes 0, 12 and 8 for both surface metadata types. NDIM and NLEVS start at TYPE_SURF_GEN bytes 4 and 8. The constructor sets variable flags from positive indices, leaves the other flags false, and builds FT0, FT1 and FT9 in that order. It preserves x18 and the saved registers and keeps its stack sixteen-byte aligned. No original Fortran callable target, constructor, vtable or type-descriptor address is used.

Surface variable arrays retain one or two metadata-array dimensions and the source naming rule, with one character for each index. Names longer than sixteen bytes are truncated exactly as the original VARIABLE name. The array constructor receives output descriptor, padded name prefix, metadata-array descriptor, source numerical-array descriptor, TYPE_SURF_GEN, registry, field rank and a two-integer configuration address in x0–x7. The configuration holds metadata rank and original prefix length. Each metadata extent is at most 255 in this supported scope. Empty associated arrays create an empty associated variable allocation; unassociated source arrays are skipped by the method, matching its source guard. The complete surface method receives the registry, the address of the SURFVARS pointer slot and TSURF in x0–x2. It constructs the 160,800-byte metadata owner, then processes all 284 variable declarations and 19 group fields in source order. Source offsets and destination offsets are recorded in `registry_surface_map.json`. Each inactive group owns a one-thread temporary; active groups wrap their original numerical owner. This is metadata construction with allocation, not numerical initialization.

The wrap children rebuild the typed FP64 header of the original assumed-shape argument, with the declared rank, element length eight, span eight and real type three. The first stride becomes one when its incoming word is zero. This boundary rule also applies to the selected unassociated EMTU and RMOON radiation owners, whose raw input descriptor words are zero. Pointer association remains false, while every constructed PTR header word is compared directly with the original. No header bytes are excluded or repaired after comparison.
