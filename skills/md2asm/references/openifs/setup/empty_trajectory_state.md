# Owned empty trajectory state

This utility constructs the empty trajectory state needed before the first selected forecast step. It follows `arpifs/setup/allocate_empty_trajectory.F90`, reached from `SU0YOMB` when `LTRAJALLOC` is false and `NCONF=1`. It supports the selected branch where digital-filter controls `LDFI` and `LJCDFI` are false. This stage allocates metadata records; it does not allocate numerical trajectory fields or mark a trajectory as saved.

`int md2asm_create_empty_trajectory_state(void *state, size_t capacity, const int32_t *controls)` takes a writable 192-byte state in `x0`, its capacity in `x1`, and five 32-bit integers `{NSTART,NSTOP,NGPBLKS,LDFI,LJCDFI}` in `x2`. All three descriptor base addresses must initially be null. The supported bounds are `0 <= NSTART <= NSTOP <= 4096`, `1 <= NGPBLKS <= 128`, and both logical controls zero. The actual case is `{0,25,86,0,0}`. Return values are zero for success, one for allocation failure, and two for unsupported input. Invalid input and allocation failure retain every incoming state byte.

The state contains GNU rank-one descriptors for `MSTEPTRAJW` at byte zero, `MSTEPTRAJR` at byte 64, and `TRAJEC` at byte 128. The timers have bounds `NSTART:NSTOP`, element size four bytes, and values minus 99. `TRAJEC` has bounds `0:NSTOP` and 512-byte elements. Each element holds eight 64-byte pointer descriptors in source declaration order. Only the base word of each initially null pointer is written; all other unassociated descriptor words retain their allocation preimage.

Six owners are allocated in source order: the two timer arrays, the trajectory array, and the `CST`, `SLAG`, and `PHYS` block arrays. These last three arrays have `NGPBLKS` elements of 96, 3536, and 5528 bytes. Their source-declared pointer bases become null. Their uninitialized `LASTCHUNK` scalar, padding, and unused descriptor words retain the allocation preimage. Every time level shares the three complete associated descriptors constructed at time zero. The block-array descriptors are at bytes 128, 192, and 256 of each trajectory element. No source object, original type descriptor, constructor, method table, or OpenIFS callable is an input.

`int md2asm_release_empty_trajectory_state(void *state, size_t capacity)` releases `PHYS`, `SLAG`, `CST`, the trajectory array, and the two timers, then clears the three outer base addresses. It accepts a successfully constructed live state once, or a state whose three outer base addresses are null. The caller must not pass an arbitrary record or independently release a shared block array. The release leaves all other outer descriptor bytes unchanged.

All passed ranges must be mapped, nonwrapping, properly aligned, and disjoint. State and allocation addresses have eight-byte alignment; controls have four-byte alignment. These range and lifetime rules are caller obligations beyond the explicit null, capacity, overlap, alignment, and scalar checks. The routines obey the Arm 64-bit ABI, preserve `x18`, `x19` through `x29`, and `d8` through `d15`, and use a 208-byte or smaller stack frame with 16-byte alignment. They require a zero floating-point control register and preserve that register, the floating-point status register, and `errno`. Production calls only `malloc`, `free`, and `__errno_location` from libc.

The original program remains a separate reference. A common allocation preimage is a verification input, supplied before either implementation receives each allocation. Complete returned owner bytes are compared without masking; corresponding allocation base addresses are checked and translated only in the metadata comparison. Independent checks cover timer values, array bounds, all declared null pointers, and shared block ownership. This selected utility omits profiling calls and does not claim the unsupported digital-filter branch or complete trajectory-saving setup.
