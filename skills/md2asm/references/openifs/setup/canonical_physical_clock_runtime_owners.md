# Canonical physical, clock and runtime owners

This component joins three accepted weather consumers to the same produced data. An owner is the record that holds a value for as long as its consumers need it. The selected surface-radiation, turbulence and cloud component libraries depend explicitly on one owner library. They do not define replacement copies of these records. This is a component check; the complete CALLPAR helper graph and forecast remain unqualified.

The numerical objects and their mathematical helpers are complete accepted objects. No instruction or arithmetic order changes. The selected links remove the old surface-radiation physical and clock storage, the separate cloud single-column flag, and the corresponding turbulence storage objects. They keep one physical record, one clock and one runtime-control record. The unchanged thermal-parameter namespace and false profiling flag also move with these records so that a data-only dependency does not introduce another physical owner. The old component libraries and default source remain unchanged.

| Record | Size in bytes | Produced values and aliases |
| --- | ---: | --- |
| `md2asm_owned_initial_physical_constants` | 520 | The accepted physical initializer supplies the constants. `__yomcst_MOD_rday` is the eight-byte member at offset 40 and contains 86,400 seconds. |
| `md2asm_owned_runtime_convection_clock` | 360 | The accepted clock initializer uses the actual configuration input at offset 51,696. The date, seconds and current-step aliases are four-byte members at offsets 0, 4 and 36. |
| `md2asm_owned_surface_runtime_inputs` | 32 | The accepted runtime initializer supplies false `LSCMEC`, false `LVDFTRAJ`, and the declared zero roughness fields. It preserves padding bytes 12–15. |

`MD2ASM_CANONICAL_INITIAL_CLOCK_ALIASES` selects two additional aliases in [the clock publisher](../../../../../src/openifs/setup/operational_step_clock_publication.S): `__yomrip0_MOD_nindat` at clock offset 0 and `__yomrip0_MOD_nsssss` at offset 4. Both aliases are defined in the object that owns the clock. Without this selector, the whole assembled clock object is byte-for-byte identical to the accepted default. With the selector, its instructions and relocation meanings are unchanged. The existing current-step alias remains at offset 36.

The [physical initializer](physical_constant_setup.md), [clock publisher](operational_step_clock_publication.md) and [runtime-control initializer](ecmwf_physics_control_fields.md) retain their accepted application binary interfaces. This interface defines argument registers, saved registers and storage requirements. The physical initializer takes an aligned writable record and capacity at least 520 in `x0` and `x1`. The clock initializer takes a 40-byte input, an aligned writable output and capacity at least 360 in `x0`, `x1` and `x2`. The runtime initializer takes an eight-byte-aligned writable record and capacity at least 32 in `x0` and `x1`. Each returns zero on success or two for rejected input before a store. The caller must supply mapped, nonwrapping buffers and preserve the accepted floating-point control settings. The existing contracts define their complete bounds and status effects.

Call the accepted physical, clock and runtime producers on these exact owners before a numerical consumer. The physical record retains its accepted fresh zero-filled padding, including bytes 516–519. The 32-byte runtime record preserves the caller's padding bytes at 12–15. Keep all five runtime aliases: `LSCMEC` at 0, `LVDFTRAJ` at 4, `LROUGH` at 8, and the eight-byte `REXTZ0M` and `REXTZ0H` fields at 16 and 24. Freeze the control record while consumers use it, and retain all owners until the final consumer returns.

`LSCMEC` selects the ECMWF single-column model. Original `SUMPINI` sets it false before reading `NAMPAR0`. The frozen operational input has no `LSCMEC` assignment, so this selected route retains false. A true override is outside this component's admitted inputs. The standalone bootstrap already calls the accepted runtime producer on the named owner; the new isolated component check now makes that same producer-to-address association explicit.

The focused check first writes nonzero bytes to the actual runtime record, then calls its accepted assembly producer and compares all 32 bytes, including preserved padding. It also compares all 520 physical bytes with the accepted source record and actual configuration copy, and all 360 clock bytes with the distinct configuration clock. The guarded publisher updates steps 0 and 8 in both clocks and rejects step 9 without changing either record. Fourteen calls compare return values, saved-register checks, floating-point controls and status, and the mathematical error indicator. The physical output also uses a separately loaded accepted initializer for its comparison.

The loaded consumer checks confirm six actual import slots: the surface-radiation day, date and seconds; the turbulence step and `LSCMEC`; and cloud `LSCMEC`. Twenty-seven symbol lookups additionally confirm that every selected consumer reaches all nine named aliases through the same explicit dependency. The other four runtime aliases remain available, although these particular turbulence objects have no import slots for them. The check also confirms each physical and thermal import against the canonical owner.

The selected links use strict missing-symbol checks, immediate binding and local binding for their defined numerical bodies. A separate check decodes 209 actual branch instructions to their unchanged local helper or original import route, confirms seven unchanged original mathematical import targets, and retains the four separate turbulence and cloud product-sum counter owners. There is no symbol localization, multiple-definition override or interposition. Complete unchanged numerical objects retain their earlier scientific checks; this checkpoint calls no weather numerical parent and replays no numerical bank.

All focused comparisons have zero differing bytes. These results do not establish complete CALLPAR output agreement, a complete autonomous forecast, a new supported physical mode or performance. The remaining static helper conflicts, actual caller lifetimes and complete-parent checks are separate work. The same main Fortran reference executable remains unchanged, and this owner selection adds no resolution-dependent build constant.
