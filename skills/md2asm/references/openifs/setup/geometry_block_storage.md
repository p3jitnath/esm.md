# Geometry Block Storage

This component supplies storage and per-block views for the selected serial SUGEM2 geometry setup. It changes addresses and copies stored bits without numerical arithmetic. A descriptor records an array address, its element size, its dimensions and its strides, which give the distance between neighbouring elements.

The allocation entry `md2asm_allocate_geometry_block_storage` takes three writable, eight-byte aligned records: the 2024-byte TGSGEOM_BLOCKED record in x0, a 64-byte spherical view-array descriptor in x1 and a 64-byte computational view-array descriptor in x2. These mapped, nonwrapping records must be disjoint. All 25 incoming data addresses must be null. Return 0 on success, 1 on allocation failure or 2 for unsupported top-level arguments. Allocation failure frees every allocation made by this call and clears all 25 addresses; partial bounds may remain. Existing foreign allocations are rejected before mutation.

There are 21 FP64 blocked owners and two 32-bit integer owners, each with shape 24 by 86, one-based bounds and contiguous strides 1 and 24. Their complete storage occupies 363264 bytes. Allocate them in the source order, including the Cartesian coordinate arrays after the integer arrays. The spherical view array contains 86 records of 1472 bytes, and the computational view array contains 86 records of 384 bytes. Their descriptor type code is the original GNU derived-type code 5. These two allocations own 159616 bytes of metadata and do not own the numerical arrays to which their views point.

The binding entry `md2asm_bind_geometry_blocks` takes the same three records in x0 through x2, the 1472-byte nonblocked spherical record in x3 and the 384-byte nonblocked computational record in x4. All allocations must remain live and disjoint except for the intended views. Each source descriptor must have the checked original GNU header, contiguous stride 1, bounds 1 through 2048 and element size 8 for FP64 or 4 for the last two spherical integer owners. These descriptor requirements are caller preconditions; the binding leaf does not repeat their checks. Destination records and complete allocations must be mapped. The accepted numerical children supply these complete source arrays; stored numerical packets do not supply a production stage.

For each of 86 blocks, bind every view to its nonblocked owner, starting at point 24 times the zero-based block number. The first 85 views have 24 points and the final view has 8 points. Copy the first 2048 points of each spherical owner into its blocked allocation. Preserve every incoming byte in the remaining 16 rows of the last block: 128 bytes for each FP64 owner and 64 bytes for each integer owner, totalling 2816 bytes. SUGEM2 does not initialize those rows. The caller supplies their existing contents as part of the complete allocated preimage; verification compares these bytes without exclusions or output repair.

Allocation uses malloc and free with a 96-byte aligned frame and preserves x18 and all saved integer registers. Binding is a leaf with no stack and uses caller-saved registers only. Neither entry changes vector state, FPCR or FPSR. Successful allocation and binding preserve errno under the checked allocator behaviour. No Fortran descriptor address, type vtable or constructor address is supplied as a production callable target.

The separate control retains the original SUGEM2 allocation, pointer-section association and block-copy statements. Two arbitrary complete blocked preimages compare 726528 owner bytes and 319232 view bytes with zero differences. All 25 descriptor headers, the unchanged 458752-byte numerical source owners, final-block padding, protected input bounds, x18, four seeded ABI calls and immediate status agree. Existing setup allocation and ABI mechanisms are reused; no allocator mock or model run was added. The guarded native caller and admitted complete forecast are described in [Spherical Geometry Construction](spherical_geometry_setup.md).

## Operational Reduced Grid

The additional entries `md2asm_allocate_operational_geometry_block_storage` and `md2asm_bind_operational_geometry_blocks` use the same interfaces and ownership rules for the 9 km grid. There are 6,599,680 physical points in 388,217 blocks of seventeen rows. The last block has eight physical points. The caller supplies complete nonblocked arrays with bounds one through 6,599,680 and the same element types and contiguous strides as above. All source buffers and output allocations remain live and mapped during binding.

The twenty-three blocked owners contain 1,161,545,264 bytes. The two view arrays contain 720,530,752 bytes. A view describes a section of an existing array and does not own another numerical allocation. Each view starts seventeen points after the previous view, and the final view has length eight. Copy only physical points into the blocked owners. Preserve all nine unused rows in the final block, which contain 1,584 bytes in total. The caller releases each of the twenty-five backing allocations once, after every dependent view is finished.

The new allocation entry retains the 96-byte aligned frame and the existing freshness, range, failure-cleanup and register rules. Binding remains a leaf with caller-validated descriptors. The original selected entries and their complete instructions remain unchanged. Production adds only integer address work and exact copies, with malloc and free as its external services.

Two complete raw-input and allocation-preimage profiles match the separate typed original SUGEM2 allocation, section and copy statements. The check compares 3,764,156,336 complete output bytes, 2,956,660,352 preserved input bytes and 22,516,586 independent view relations, with zero differing bytes. It also covers final-block padding, guards, seven zero ABI masks, natural floating-point status, first and last allocation failures, existing-owner refusal and complete release. Earlier descriptor and unsupported-input evidence is reused. These checks qualify storage and binding; spherical numerical construction, enclosing geometry and the operational forecast remain separate work.
