# Distributed Spectral Field Storage

A spectral coefficient describes one part of a field as a sum of waves. This component constructs storage for the four-process TCo1279 model with 137 atmospheric levels. Two process groups divide the waves, and two groups divide the levels. It preserves the complete original `spectral_fields_mod.CREATE_SPEC` and `DEALLOCATE_SPEC` storage rules. It does not advance model time. The [serial contract](spectral_field_storage.md) defines the shared record, descriptor fields, owner order and named views.

The raw entry is `md2asm_initialize_distributed_spectral_field(record, record_bytes, view, view_bytes, identifiers, dummy)`. Registers x0 through x5 carry these six arguments under the Arm application binary interface (ABI). The fresh zero record has 2,992 mapped bytes and eight-byte alignment. The read-only view has 160 bytes and eight-byte alignment. The five identifiers are signed 32-bit integers with four-byte alignment. Their first group contains 138, 155 and 130 once each, and their second contains 152 and 129 once each. Input order can vary within each group. Dummy has 24 writable bytes and eight-byte alignment. All complete spans are mapped, do not wrap the address range and are disjoint from writable record and dummy storage. The caller retains every borrowed input during construction.

| View bytes | Contents |
|---|---|
| 0–15 | Four int32 values, MYSETW, MYSETV, NPRTRW and NPRTRV |
| 16–143 | Eight address and byte-capacity pairs for MYMS, NALLMS, NPTRMS, NUMLL, NPTRLL, NPSURF, NASM0 and NUMPP |
| 144–151 | Two int32 values, local NSPEC2 and NUMP |
| 152–159 | Reserved zero bytes |

MYSETW and MYSETV are one-based process coordinates. Both process-group counts are two. Each wave group has 640 waves and 819,840 real coefficient words. Required input prefixes have 2,560, 5,120, 8, 8, 8, 8, 5,120 and 8 bytes in the table's map order. The live NUMLL and NPTRLL owners each have three entries, while construction consumes only their first two. NUMLL contains 69, 68 and 0. NPTRLL contains 1, 70 and 138. Thus MYLEVS holds global levels 1 through 69 or 70 through 137. NPSURF contains 0 and 1, so the first vertical group has no surface spectral fields and the second has two.

Allocate the same 16 owners in original order. Copy the first six input maps. Copy local NASM0 and NUMPP from the qualified distribution with the same `INI_SPEC_DIST(1279, 1279, 2, MYSETW)` inputs. Form global NASM0G through the source running sum, MS_PROC from NALLMS and NPTRMS, and NS2L as twice NPSURF. Numerical array shapes are `(local_levels, 819840, 3)`, `(819840, local_surface_fields)` and `(1, 2)`. Their consumed bytes start at positive zero. An empty surface array retains a distinct one-byte allocation with zero logical extent. Its SP and OROG views select the rank-one dummy. Preserve every source-unwritten byte, field identifier, descriptor, alias and released-array metadata field.

The production entry is `md2asm_initialize_owned_distributed_spectral_field(record, record_bytes, Geometry, geometry_bytes, partition_owner, owner_bytes, identifiers, dummy)`. Its eight arguments enter x0 through x7. Construct the record at its final address, including FIELDS+22736 in the complete model. Geometry has at least 17,096 bytes and the completed partition owner has 4,096. The owner names this Geometry and has completed lifecycle state 3. Its maps come from the live accepted SUMP and SULAP producers. The adapter derives the raw view from these actual owners. It uses no archived map in production. Retain dummy storage until spectral release.

Return zero publishes the record, one reports allocation failure after complete release, and two refuses a checked input before mutation. The raw constructor uses a 176-byte aligned stack frame, and the live adapter uses 256 bytes. Each entry preserves x18, saved integer registers, the stack pointer and the required saved vector halves. FPCR controls floating-point arithmetic and must be zero at construction. FPSR records numerical events. Integer copies and zero stores preserve both registers and incoming errno. The new `md2asm_release_distributed_spectral_field(record)` entry forwards to the accepted shape-independent [release body](../../../../../src/openifs/setup/spectral_field_storage.S), which releases the same owners and retains their source descriptor metadata. Production uses direct AArch64 assembly and public C memory services.

All four actual layouts match 5,417,596,314 complete backing-owner bytes and 23,936 created and released record bytes, with zero differences. Every native ABI check passes, all acquired owners are released, guards remain intact and natural numerical status is preserved. Both empty source arrays retain their one-byte allocations.
