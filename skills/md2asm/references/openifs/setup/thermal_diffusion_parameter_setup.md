# Thermal and vertical-diffusion parameter setup

This component owns the complete 23-scalar YOETHF thermal namespace assigned near the start of `SUPHEC`, and the complete YOEVDFS stability table built by `SUVDFS`. The table converts the dimensionless Richardson number, which measures the effect of stable air layering on turbulence, into the dimensionless height-to-Obukhov-length ratio $`\eta`$. It also stores second derivatives for cubic spline interpolation between the 101 table points. This component does not replace the complete `SUPHEC` caller.

The production source is `src/openifs/setup/thermal_diffusion_parameter_setup.S`. It contains the guarded parent `md2asm_initialize_thermal_diffusion_parameters`, followed by two numerical children. No original OpenIFS code, global value, type record or method table supplies a production input. The source has no external dependency, heap allocation or retained pointer. The caller owns the output and its lifetime.

## Interface and storage

The AArch64 procedure uses `x0` for a writable output address, `x1` for its capacity in bytes, `x2` for the read-only owned physical-constant record, and `x3` for its capacity. The output requires 1,920 bytes and the constant record requires 520 bytes. Both addresses must be nonzero, aligned to eight bytes, disjoint over these complete extents and free from address wrap. The procedure returns zero on success or two before any write for an unsupported input. Capacities above the required extents do not increase the accessed range.

The first 184 output bytes hold the 23 YOETHF FP64 values in original declaration order. Their offsets are `R2ES` 0, `R3LES` 8, `R3IES` 16, `R4LES` 24, `R4IES` 32, `R5LES` 40, `R5IES` 48, `RVTMP2` 56, `RHOH2O` 64, `R5ALVCP` 72, `R5ALSCP` 80, `RALVDCP` 88, `RALSDCP` 96, `RALFDCP` 104, `RTWAT` 112, `RTBER` 120, `RTBERCU` 128, `RTICE` 136, `RTICECU` 144, `RTWAT_RTICE_R` 152, `RTWAT_RTICECU_R` 160, `RKOOP1` 168 and `RKOOP2` 176.

The following 1,736 bytes hold the complete YOEVDFS namespace. Relative to its start at output byte 184, `RITBL(1:101)` occupies bytes 0–807 and `ARITBL(1:101)` occupies bytes 808–1615. The 15 following FP64 scalars start at byte 1616 in this order: `RCHBA`, `RCHBB`, `RCHBC`, `RCHBD`, `RCHB23A`, `RCHBBCD`, `RCHBCD`, `RCHETA`, `RCHETB`, `RCHBHDL`, `RCDHALF`, `RCDHPI2`, `RIMAX`, `DRITBL`, `DRI26`. All 1,920 bytes are source-written values; there is no pointer or padding normalization.

The constant producer is `md2asm_initialize_physical_constants`. This component consumes `RD` at byte 184, `RV` at 192, `RCPD` at 200, `RTT` at 368, `RLVTT` at 376, `RLSTT` at 384 and `RLMLT` at 408. The first three values must be finite and within [1, 10000], `RTT` must be within [200, 350] K, and the three latent heats must be within [1, 100000000] J/kg. `RD` and `RV` are gas constants in J/(kg K), and `RCPD` is the dry-air heat capacity in J/(kg K). The selected values come from the owned producer, not a retained state packet.

The raw child `md2asm_initialize_thermal_namespace_fields` takes the 184-byte output in `x0` and constants520 in `x1`. The raw child `md2asm_initialize_stability_table_fields` takes its 1,736-byte output in `x0`. These children require the same valid, disjoint and aligned buffers and FP control as the parent; they perform no argument checks. They return zero. The parent uses a 32-byte frame, and the table child uses 832 private stack bytes for the source `ZU(101)` scratch array and alignment. The maximum combined stack use is 864 bytes.

## Ordered calculations and status

The thermal child follows the original `SUPHEC` assignment order, including the rounded product followed by division in `R2ES=611.21*RD/RV`, the temperature-dependent saturation coefficients, and the latent-heat ratios. It initially sets `RTICECU=RTT−23 K` and the corresponding reciprocal. The later accepted `SUCUMF` stage changes that ice limit to `RTT−38 K` when the selected glacier option is true. An enclosing caller must apply the later convection output to thermal offsets 144 and 160 at that source point; this initializer does not anticipate that update.

For table index $`j=0,\ldots,100`$, the target Richardson number is the source-rounded product $`j\,DRITBL`$, where the FP64 step `DRITBL` is computed as `10/100`. The source solves $`Ri=\eta(1+4\eta)^2/(1+5\eta)^2`$ with its original finite-difference Newton update. It uses five iterations below 0.5 and three iterations elsewhere, starting from the preceding table value. The direct child retains each product, division, subtraction and iteration boundary. It then follows the original forward elimination and backward substitution for the cubic spline, with left slope one and right slope equal to the last table secant. The constant `2*ATAN(1)` is the source-folded FP64 value of $`\pi/2`$; no run-time trigonometric call is introduced.

Entry FPCR must be zero: round to nearest with ties to even, gradual underflow and no floating-point exception traps. The procedures preserve FPCR, errno, `x18`, all AArch64 callee-saved registers and the stack alignment. They retain the arithmetic flags added to FPSR. Products and sums remain separately rounded FP64 operations; no fused multiply-add, contraction, reassociation or approximate arithmetic is used. The guarded rejection path uses only integer checks and preserves the incoming FPSR.

## Accepted checks and limits

Two separate verification profiles compare all 3,840 returned bytes with the unchanged `SUPHEC` assignment block and the genuine linked original `SUVDFS` body. One profile uses the selected owned constants and a zero output preimage; the other uses valid warmer constants, a nonzero preimage and preseeded status flags. Six direct child and parent calls pass the seeded application binary interface checks, and their immediate FPCR, FPSR and errno match the reference. The source table's maximum defining-equation residual is 5.60e−7; 816 independent checks cover monotonicity, the stability equation, the spline equations and the thermal range.

The boundary verifier passes 24 atomic rejects and four successful complete-buffer checks beside protected memory pages. A separate assembly `_start` obtains its constants from the owned physical-constant producer, emits every namespace byte and FP status, and matches all 1,936 expected bytes. Its executable has no dynamic section or undefined symbol. The production component has no required dynamic library or undefined symbol. The original program remains a separate verification reference. No forecast was run and no new forecast-body credit is claimed by this component check.
