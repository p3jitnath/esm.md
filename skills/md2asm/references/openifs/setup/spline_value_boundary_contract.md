# Spline Value Boundary Conditions

This child implements the selected value-boundary path of `arpifs/setup/suvfe_implicitbc.F90`. A zero-value top or bottom condition removes the first or last clamped basis function. Removing it means setting every polynomial coefficient of that basis function to positive zero while preserving every other basis byte.

`int md2asm_spline_value_boundaries(const int32_t top[2], const int32_t bottom[2], const int32_t *order, const int32_t *basis_count, double pieces[basis_count*4*4])` takes five addresses in x0 through x4 under the Arm procedure call standard. The first word of each boundary pair is a zero-or-one value flag. The second word is a requested derivative order and must be zero. Order is four and basis count is 21 through 24, or exactly 139 or 140 for the added operational child shapes. Other larger counts remain unsupported. These are the source-selected boundary types for the five actual 19-level operators RINTBF11, RDERBF00, RDERBF01, RDERBF10 and RDERBF11 with NVFE_INTBC and NVFE_DERBC both three. This entry explicitly rejects derivative-boundary modes; it does not alter those source choices.

All buffers are caller-owned and mapped for the stated extents. Integer addresses are aligned to four bytes and the FP64 owner to eight bytes. The integer inputs are disjoint from the mutable piece owner. Pieces have the qualified constructor's column-major layout: basis index varies fastest, followed by the four segments and four coefficients. Return zero completes the selected mutation. Return two rejects null addresses, alignment, unsupported dimensions, flags or derivative order before mutation. There are no allocation or numerical-failure exits.

With a top flag of one, write positive zero at basis index zero in each of the 16 segment/coefficient planes. With a bottom flag of one, write positive zero at basis index basis_count−1 in those planes. If both flags are zero, all piece bytes remain unchanged. This is the source order with both derivative branches inactive. The original interval/segment helper functions are therefore not consumed. Profiling is omitted diagnostics, and the selected path has no source file output.

The leaf uses no stack, floating-point arithmetic, allocation or external callable. It preserves all callee-saved registers, x18, FPCR, FPSR and errno. It requires no original module data, type metadata, descriptor or vtable. The standalone library has no undefined symbol or `DT_NEEDED` entry.
