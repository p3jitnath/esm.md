# Local Geometry Maps

SUGEM3 builds local longitude counts, spectral counts and Gaussian latitudes after spherical point geometry. Its source is arpifs/setup/sugem3.F90. This service retains the source integer bounds and copies stored values without floating-point arithmetic.

The raw interface is `int md2asm_initialize_local_geometry_maps(geometry, process)`. Register x0 points to one mapped, eight-byte aligned 17,096-byte Geometry object. Register w1 is one. The selected serial T21 case has NDGSAG = -1, NDGENG = 34, NDGSAL = 1, NDGLL = NDGENL = 32 and NFRSTLOFF = 0. The source JPSLWIDE parameter is 48. The service calculates NDGSAH and NDGENH from the original maximum and minimum expressions. These quantities are latitude indices without units. The original one-pointer sugem3_ adapter reads the live original MYSETW scalar. This scalar and the already constructed input map owners remain explicit bootstrap dependencies. No original callable or vtable target is retained.

NLOENG and NMENG are contiguous GNU rank-one int32 owners. RLATIG is a contiguous GNU rank-one FP64 owner with latitude in radians. Their allocated bounds contain -1 through 34; this service allows lower bounds -2 or -1 and upper bounds 34 or 35. NPTRLS has one contiguous int32 element with bounds one and value one. Each descriptor has the source element length, rank, dtype, span, unit stride and offset equal to minus its lower bound. Complete owner storage is mapped, does not overlap Geometry or any released owner, and remains alive throughout the call. Invalid consumed dimensions or descriptors return two before mutation.

NLOENG and NMENG contain the global counts, while NLOEN and NMEN hold their local copies. RLATIG holds global Gaussian latitudes and RLATI holds the local copy. NPTRLS gives the first global latitude index for each process. The original integer bounds are `NDGSAH = max(NDGSAG, NDGSAL + NFRSTLOFF - 48) - NFRSTLOFF` and `NDGENH = min(NDGENG, NDGENL + NFRSTLOFF + 48) - NFRSTLOFF`. The integer copy uses global index `NPTRLS(process) + local_index - 1`. The latitude copy uses global index `local_index + NFRSTLOFF`. The direct loops retain these calculations even though the selected guards fix the process and offset.

The service releases old NLOEN, NMEN and RLATI allocations if their data pointers are nonzero. Existing descriptors obey the original allocation ownership rules and use the C allocator. It creates two int32 owners with bounds -47 through 80 and one FP64 owner with bounds -1 through 34. For each integer destination index, it calculates the original global index and copies only when that index lies within NDGSAG through NDGENG. Other allocated integer words retain their incoming allocation bytes. The latitude loop copies all 36 FP64 words using integer loads and stores. The three complete owners span 1,312 bytes. No output byte is repaired after return.

A successful raw call returns zero. Allocation failure frees every new owner, clears all three data pointers and returns one; partial descriptor bounds may remain. The native adapter aborts on nonzero return. Borrowed inputs are never freed. The 160-byte frame preserves saved registers, x18, FPCR, FPSR and errno around C allocation and cleanup. The native counter getter is md2asm_local_geometry_native_count_get, with an expected selected count of one.

The focused comparison uses the genuine original SUGEM3 body and original interface. A verification-only allocation fill gives both calls an equal explicit starting byte pattern for the two 512-byte integer owners and the 288-byte latitude owner before calculation. It compares every returned owner byte, complete descriptors through corresponding owner addresses, untouched Geometry bytes and complete borrowed inputs. Cases cover minimal and wider input bounds, including existing destination allocations. The ABI boundary checks saved registers, x18 and numerical status. The selected complete forecast check passes for this service.

The native service omits the original allocation and geometry printouts and DR_HOOK profiling. These are diagnostics; no forecast calculation is omitted.

The [complete forecast check](../../../../../src/openifs/README.md#verification) passes for the selected route. Its declared upstream data and branch limits remain in force.

The operational entry is `int md2asm_initialize_operational_local_geometry_maps(geometry, process)`, with the same x0 record and w1 process value one. It admits the actual serial 2,560-row shape only: NDGSAG=-1, NDGENG=2562, NDGSAL=1, NDGLL=NDGENL=2560 and NFRSTLOFF=0. All four borrowed descriptors have their exact source type and contiguous stride. NLOENG and NMENG are int32 arrays over -1 through 2562; RLATIG is an FP64 array over those same bounds; NPTRLS has one int32 element equal to one. The complete Geometry record and consumed input spans must be mapped, aligned, nonwrapping and disjoint from the released owners. The new guards reject invalid consumed shapes before mutation.

The original halo expressions give NDGSAH=-1 and NDGENH=2562. The service releases the previous three local owners in source order and returns the following complete arrays. An owner is an allocated array whose storage must later be released by its caller.

Total returned storage is 41,760 bytes. The integer loops copy the exact global indices -1 through 2562 and preserve all other 736 allocation bytes. The latitude loop copies all 2,564 words with integer loads and stores. Production supplies no halo fill or new latitude calculation. The first operational call replaces the two existing integer owners from the qualified reduced-grid and global-cutoff producers, while RLATI is null after latitude setup. A later call can replace all three previous local outputs. The four global inputs remain borrowed, are never freed and remain unchanged.

The new entry retains the existing 160-byte frame, register and status obligations. It adds no floating-point operation.
