# Nonblocked Spherical Point Geometry

This child builds a whole-grid spherical-geometry record before the grid is split into processing blocks. The record, named TGSGEOM, has 23 components from the selected SUGEM2 source route. The admitted T21 settings select stretch type 1 and unit stretch. The supported one-process grid has 32 north-to-south Gaussian latitude rows, 64 longitude points per row and 2048 points. This work does not replace the other SUGEM2 stages: native blocked copies, block views, computational geometry and the final resolution correction remain separate children.

The application binary interface is `int md2asm_initialize_spherical_point_geometry(record, physical, latitude_sines, weights)`. Registers x0 through x3 point to a writable 1472-byte TGSGEOM record, a read-only 48-byte physical input record and two read-only 256-byte FP64 arrays. Every span is eight-byte aligned, mapped and nonwrapping. The result record does not overlap any input. The physical record contains six FP64 values in order: stretch, RC2P1, RC2M1, Earth radius in metres, pi and angular rotation rate in radians per second. This selected child requires stretch 1, RC2P1=2, positive-zero RC2M1, radius 6371229 metres, original pi bits 0x400921fb54442d18, and a positive finite rotation rate between two raised to minus 30 and two raised to minus 8. The latitude inputs are the complete direct 32-row Gaussian outputs, not stored state supplied by a driver. The earlier direct SUGEM1B calculation owns RC2P1 and RC2M1 initialization; this child receives their established values as inputs.

The serial metadata has latitude index j in row j, 64 points per row, first longitude 1 and point start 1+64*(j−1). A later native caller must check these actual partition maps before using this bounded interface. For each latitude sine mu, retain the source operations: numerator=`RC2M1+RC2P1*mu`, denominator=`RC2P1+RC2M1*mu`, geographic sine s=`numerator/denominator`, cosine c=`sqrt(1-s*s)` and mapping factor M=`denominator*(0.5/stretch)`. Coriolis fields are `(2*rotation)*s` and `(2*rotation)*c`; the zonal rotation vector is `((2*rotation)*radius)*c`. The north-vector meridian derivative is `-(1/radius)*s`. Every multiplication, addition, square root and division rounds separately in original source order.

For longitude index k from 1 through 64, source longitude is positive zero plus `(pi*REAL(2*(k−1)))/64`. The child calls the existing direct ASIN, cosine and sine primitives in source point order. It stores geographic latitude as ASIN(s), longitude cosine and sine, Cartesian coordinates `(radius*c)*cos(longitude)`, `(radius*c)*sin(longitude)` and `radius*s`, mapping M, squared stretch, the remaining original zero/one vector values, and Gaussian weight `weight(j)/(64*(M*M))`. Integer fields store j and `64*(j−1)+k`. Positive and negative zeros retain the source operations. No fused caller arithmetic, approximation, interpolation or reduced precision is used.

TGSGEOM has 23 GNU Fortran 12 rank-one pointer descriptors of 64 bytes each. Source declaration order is RCORI, RCORIC, GEMU, GSQM2, GELAM, GELAT, GECLO, GESLO, GEXCO, GEYCO, GEZCO, GM, GMAPPA, GOMVRL, GOMVRM, GNORDL, GNORDM, GNORDLCL, GNORDMCL, GNORDMCM, GAW, NGPLAT and NUNIQUEGP. The first 21 arrays contain 2048 FP64 elements; the last two contain 2048 signed 32-bit integers. Bounds are 1 through 2048 and strides are one. The complete new numerical ownership is 360448 bytes. Each incoming descriptor must be unassociated. The constructor allocates every owner, fills every element and transfers ownership to the record. A caller must free each owner once. No new numerical tail is left undefined in this nonblocked interface.

Return zero means success. Return one means allocation failure: prior allocations are freed and all 23 data pointers are cleared, while descriptor bounds already written can remain. Return two rejects an unsupported physical input, bad checked span or associated output before mutation. The frame is 176 bytes and sixteen-byte aligned. The entry preserves x18 and all required AArch64 saved registers and requires FPCR zero. It uses the same accepted direct Gaussian/arithmetic dependencies and allocation/descriptor mechanism as the preceding geometry children. Original Fortran supplies only a separate source control, with no numerical callable, vtable, constructor, type descriptor or captured state packet in the production library.

The focused check compares all 360448 numerical bytes and all 23 descriptor headers apart from new base addresses with a separate source control. It checks complete input preservation, result bounds, status and saved registers. Independent physical checks require unit spherical directions, the declared rotation relations, unit normalized Gaussian weights and exact integer point maps. Existing Gaussian, ASIN, sine/cosine and allocation edge evidence is reused. The complete SUGEM2 composition passes the admitted native forecast described in [Spherical Geometry Construction](spherical_geometry_setup.md). This child adds no separate original routine credit.
