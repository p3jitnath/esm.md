# Spherical Grid Setup

SUGEM1B calculates small geometry constants and latitude index tables before the model starts. This child covers the selected one-process T21 spherical route, with RSTRET exactly one. It accepts one through 32 Gaussian latitude rows and one through 64 longitude points. RSTRET is a stretch factor with no units; one means the computational sphere has no stretching. The production interface takes raw GEOMETRY storage in x0 and a 24-byte physical-input record in x1: signed 32-bit MYSETW and MY_REGION_EW at offsets zero and four, then FP64 pi and Earth radius in metres at offsets eight and sixteen. These values are physical constants and process indices, not omitted numerical setup results. The selected radius is 6371229 metres.

The existing geometry supplies dimensions, the pole value RMUCEN, global longitude counts NLOENG, wave-number limits NMENG, process latitude offsets NPTRLS and per-process longitude counts NONL. It also supplies writable NLOEN and NMEN owners and their GNU Fortran 12 descriptors. The caller must construct these earlier owners before this child. This child performs the original local copies itself and allocates NSTAGP. Every input and output descriptor has a four-byte integer element, eight-byte alignment, and bounds that cover every accessed source index. The loops use the declared strides and offsets. New NSTAGP storage has stride one and bounds NDGSAL through NDGENL. The caller releases this owner once through C free.

R4JP is `(4*NDGLG+2)/(4*pi)`. RC2P1 and RC2M1 are separately calculated as `RSTRET*RSTRET+1` and `RSTRET*RSTRET-1`. RCOR0 receives positive zero, and RCOR1 is `RMUCEN/sqrt(3)`. RMUCEN is the sine of the physical pole latitude, with no units. RDELXN is `(2*pi*radius)/NDLON`, the equatorial spacing in metres for a regular longitude row. Each multiply, addition, subtraction, square root and division uses FP64 with its own rounding point, in the original source order. No fused operation, reassociation or approximate instruction is allowed. FPCR must be zero. Incoming FPSR flags are retained and combined with the flags raised by these operations.

For local latitude j from one through NDGLL, the global index is `NPTRLS(MYSETW)+j-1`; NLOEN and NMEN copy the corresponding original global values. NSTAGP starts with running position one. Each positive NONL count stores that position and then adds the count; a zero or negative count stores zero. This table identifies where each active latitude row begins in the contiguous local grid-point storage.

`md2asm_initialize_spherical_grid` returns zero on success, one if C malloc fails, and two when the checked shape or stretch is outside this scope. Allocation occurs before any output mutation, so either failure leaves the geometry and its existing numerical owners unchanged. Success creates one NSTAGP owner and preserves all pre-existing input owners. The routine preserves x18 and the AAPCS64 saved registers and uses a sixteen-byte aligned stack. Its only external call is C malloc. It requires no Fortran callable target, constructor, vtable, type descriptor or saved model-state packet. Original diagnostic printing is outside this numerical interface. The native caller has passed the joint forecast gate within this selected scope.

Acceptance uses the complete original SUGEM1B as a separate typed Fortran control. Critical cases cover the selected 32-by-64 dimensions, a small shifted and sparse latitude partition, unsupported stretching, allocation failure, descriptors, output bounds, unchanged input owners, seeded registers and floating-point status. Independent checks require positive equatorial spacing, positive RCOR1 for the north pole, the expected spherical constants, complete latitude copies and exact start positions.
