# Runtime zero-aerosol visibility copy

The original RADVIS_LAYER uses the climatological visibility when the active aerosol count, `NACTAERO`, is zero. The [direct assembly](../../../../../src/openifs/physics/runtime_zero_aerosol_visibility.S) copies each active 64-bit word from `GEMSL%ZVISICL` into `PDIAG%PVISIH`. Visibility is measured in metres. Integer loads and stores preserve signed zeros and every payload bit without floating-point arithmetic. A nonzero aerosol count returns status two before any metadata read or output write.

Let $`P`$ be the allocated column count. The raw entry `md2asm_copy_climatological_visibility` takes $`P`$ in `w0`, first and last active one-based columns in `w1` and `w2`, the source address in `x3`, and the destination address in `x4`. It accepts $`1 \le P \le 128`$, first from 1 through $`P+1`$, and last from 0 through $`P`$. First greater than last gives an empty interval and returns zero without reading either backing. Each nonempty backing owns $`8P`$ bytes at an eight-byte-aligned address. Identical backings or disjoint complete backings are accepted. Partial overlap and address-range overflow are refused before a store.

The typed entry `md2asm_update_runtime_zero_aerosol_visibility` takes a 192-byte `DIMENSION_TYPE` in `x0`, a 4,680-byte `GEMS_LOCAL_TYPE` in `x1`, a 4,104-byte `AUX_DIAG_TYPE` in `x2`, the aerosol count by value in `w3`, and a 16-byte read-only context in `x4`. Each address aligns to eight bytes. Context word zero is the common physical-record pointer and remains unread on this route. The second word points to a 16-byte profiling policy containing a pointer to a four-byte-aligned zero int32 and a reserved zero word. An empty interval reads no GEMS or diagnostic record. Every consumed owner must remain valid for its complete declared size until return.

The typed entry reads DIM first, last and count at byte offsets 0, 4 and 12. It reads the GNU Fortran array descriptors at GEMS byte 4504 and diagnostic byte 600. A descriptor publishes an array address, bounds and element spacing. Each 64-byte descriptor must describe a contiguous rank-one FP64 array, with eight-byte elements, bounds 1 through $`P`$, unit stride and signed offset minus one. These bounds match the selected GEMS allocation. The complete destination backing must be disjoint from every consumed metadata owner, including the context, profiling policy and four-byte flag. The raw child checks source and destination overlap before the first store.

The application binary interface, or ABI, requires preserved saved registers, platform register `x18` and 16-byte stack alignment. Both entries preserve the floating-point control and status registers and errno. The typed entry uses a 96-byte frame and calls only its directly emitted raw child. Status zero means that the active words were copied or the interval was empty. Status two means refusal before an output write.

Five pairs against actual original RADVIS_LAYER passed, using one assembled solver and one reference library: one column and one level; 17 columns and 137 levels with active columns 2 through 16; 24 columns and 5 levels; a 128-column, 137-level tail with active columns 127 and 128; and an empty interval. All 48,052 complete compared bytes agreed. The raw child ran before the typed bridge. The saved states passed 561 independent active-word and inactive-word checks, sixteen before-write refusals, identical-backing and unread-empty-owner cases, and immediate native register, floating-point and errno checks. The actual original call target and direct native child branch were qualified. Process and child-group closure passed without signals.

This component extends an existing RADVIS_LAYER route and adds no original-routine body to the completion count. Its source and verification tools remain separate from the production forecast. The production diagnostic-buffer connection, positive-aerosol route, active parameterisation branch and full forecast require their own acceptance.
