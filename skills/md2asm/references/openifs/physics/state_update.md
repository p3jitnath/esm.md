## Ordered Update And Domain

Reuse the accepted [state object and descriptor ABI](state_increment.md). Let $`K`$ count horizontal columns and $`N`$ count updated levels. Support $`0\leq K\leq4096`$ and $`0\leq N\leq1024`$, valid one-based selected columns and empty ranges. Each active initial, tendency and output descriptor is contiguous with first stride one, contains the selected column indices and levels `1..N`, and has valid complete storage. Owners can have different horizontal and vertical padding and 32-bit lower bounds. Each complete owner has at most 8,192 horizontal elements, 2,048 vertical elements and 64 cloud components. Each cloud owner includes components one through four.

The physics object is 160 bytes. Its FP64 value at byte 8 is `TSPHY`, the finite nonnegative time interval in seconds. For each cell, first round `TSPHY*tendency` to FP64, then separately round `initial+product`. Preserve the source order of increasing levels, then U, V, T, vapour, ozone, cloud fraction, liquid, ice, rain, snow and turbulent kinetic energy. FP64 is the 64-bit floating-point format.

Wind and temperature always update. Every other field updates only when the output state's own logical mask is one. Initial and tendency masks do not control this calculation. Cloud components update through `CLD`, with no separate write through QL, QI, QR or QS views. Other complete output bytes keep their incoming values. Physical inputs must give finite sums, positive temperature, nonnegative water and energy, and fractions in $`[0,1]`$. Wind can have either sign.

Require FPCR zero for nearest rounding with ties to even, gradual underflow and preserved signed zeros. Every product and addition rounds separately. Contraction, fused multiply-add, reassociation and reduced precision are forbidden.

## Five-Pointer ABI And Owners

Registers `x0` through `x4` address the physics object, dimension object, initial state object, tendency state object and output state object. The default entry symbol is `state_update_` with no scalar result. `ORIGINAL_SYMBOL` can change only the symbol. The dimension and state objects use the same 192-byte and 1,240-byte layouts already accepted for state_increment. Descriptor subscripts here use the actual level indices `1..N`, rather than the complete vertical colon used by state_increment.

All metadata and tendency arrays stay read-only. Owners align to eight bytes. Different active output owners are disjoint. A corresponding initial owner can be the same complete owner as its output, with identical descriptor bounds and offset, so each cell updates in place. Other overlaps are unsupported. Tendency owners are disjoint from output owners. Inactive descriptors need not be associated and are never accessed. The assembly must preserve `x19` through `x30`, leave `x18` and the preserved low 64 bits of `v8` through `v15` untouched, and restore its aligned 96-byte frame. It uses no array scratch or external numerical stage. Independent pairs of columns use one Arm SIMD multiplication and one separate addition, followed by a scalar remainder.

## Independent Checks And Canonical Bytes

Reuse the accepted descriptor, mask and register checks. The new physics check uses exact rational multiplication and addition. It bounds each rounded operation by half a unit in the last place, then checks the field's time-update residual using the sum of those two actual rounding errors. It also checks physical field bounds and signed-zero rules. A manufactured wind case has a zero result with two rounded operations but a nonzero result with fused arithmetic, so contraction changes observable bytes.

Canonical bytes concatenate every complete supplied output owner in U, V, T, ozone, vapour, cloud fraction, energy, QL, QI, QR, QS and cloud order. The focused corpus checks independently padded initial, tendency and output owners, different lower bounds, interior columns, masks, in-place initial/output storage, zero and non-unit timesteps, cancellation, halfway rounding, subnormals, empty ranges and dimensions, and the column and level limits. Acceptance permits zero differing bytes, unchanged metadata and no masking or normalisation. The genuine original passed 21 cases, 3,329,056 complete fixture output bytes and 172,308 independent relations, including 60 subnormal results. Native assembly passed 42 guarded calls, 6,658,112 complete fixture bytes and 344,616 physical relations with zero differences, including 120 subnormal results. Metadata and tendencies remain unchanged, registers and stack are preserved, and FPCR is zero. The composable paired relay passed 21 calls, 2,527,960 complete active output bytes and 85,512 unchanged metadata bytes. For an in-place initial/output mapping, it points the original input and output to the same complete clone, preserving that alias without exposing original writes to the real owner. The fixture also checks inactive complete output owners. No comparative timing or speed claim is available.
