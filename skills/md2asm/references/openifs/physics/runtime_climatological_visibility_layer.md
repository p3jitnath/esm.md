# Runtime climatological aerosol visibility layer

The direct [AArch64 source](https://github.com/p3jitnath/esm.md/blob/28940eb213fb69ab2b64cc0bf154ca733f7c1c21/src/openifs/physics/runtime_climatological_visibility_layer.S) implements the original `CLIMAER_LAYER` call order from the [climatological aerosol formulation](../../../../../formulations/openifs/physics/climatological_aerosol_visibility_layer.md). It prepares temperature at layer boundaries, calls the aerosol climatology, computes bottom-level saturation humidity, converts aerosol layer mass to a mass mixing ratio, and calls the shortwave-extinction and cloud-visibility routines. All four numerical children are accepted direct assembly. The original OpenIFS library is used only as a separate verification reference.

Let $`P`$ be the allocated column count and $`L`$ the level count. The entry `md2asm_runtime_climatological_visibility_layer` accepts $`1 \le P \le 128`$, $`2 \le L \le 137`$, first active column 1 and last active column from 1 through $`P`$. Matrices use FP64 values with the column index varying fastest. The same assembled parent and original reference library serve all checked shapes without recompilation.

The application binary interface (ABI) passes eight original addresses in `x0` through `x7`, followed by a ninth address at incoming stack byte 0. An array descriptor is a small record that gives the data address, element size and index bounds. The original argument names and complete borrowed record sizes are:

| Argument | Original identifier | Complete record bytes | Native use |
|---|---|---:|---|
| 1 | `YDSURF` | 18,224 | Read selected surface-field metadata. |
| 2 | `YDMODEL` | 4,275,088 | Read controls, profiles, tables and radiation configuration. |
| 3 | `KDIM` | 192 | Read first, last, column and level counts. |
| 4 | `PAUX` | 1,992 | Read pressure and geography descriptors. |
| 5 | `STATE_T0` | 1,240 | Preserve the original incoming record; no numerical payload read. |
| 6 | `STATE_TMP` | 1,240 | Read temperature, humidity, cloud fraction and cloud fields. |
| 7 | `PSURF` | 13,680 | Read field descriptors; write six selected diagnostic vectors. |
| 8 | `GEMSL` | 4,680 | Read descriptors; write extinction and visibility vectors. |
| 9 | Explicit runtime context | 32 | Read physical owner, false-hook policy, thermal owner and heap budget. |

The context contains four 8-byte words: the actual initialized physical-constant owner of at least 520 bytes, the 16-byte false profiling policy, the actual initialized thermal owner of at least 1,920 bytes, and the available heap bytes. The policy contains a pointer to a zero 4-byte flag and a zero reserved word. The twelve SATUR compatibility aliases must resolve to the stated assembly-owned constant addresses. These names do not permit original OpenIFS global storage to supply production constants.

Pointers must identify accessible memory for every stated owner and payload. Real payloads are 8-byte aligned; integer metadata uses its declared 4-byte alignment. The GNU Fortran array descriptors define dense arrays with checked element size, rank, bounds, strides, origin and nonwrapping spans. Pressure at boundaries has shape `(P,0:L)`; full-level fields have shape `(P,L)`. The nine aerosol profiles each own $`L+1`$ values, and the eleven current climatology tables each have shape `(120,61)`. Configuration descriptors retain the accepted five coefficient and humidity payloads.

The frozen control path requires `LERADIMPL=1`, `LECSRAD=0`, `LUSEPRE=0`, `NAERMACC=1`, `NMCVAR=12` and `N_AER_TYPES=12`. The four-byte logical control `LPHYLIN` can be 0 or 1.

The cloud array can have four or five component planes. The full declared array, including an unused fifth vapour plane, is read-only and must remain separate from outputs. Condensate planes 1 through 4 retain the original liquid, ice, rain and snow order. The selected surface-temperature index is checked against its complete matrix. Six distinct diagnostic indices are checked against the complete diagnostic matrix. Every public output is checked against all borrowed input spans and the other outputs. Other read-only inputs can share storage.

The ordered calculation keeps the original pressure-weighted temperature interpolation, top boundary and selected skin-temperature copy. At the bottom level it forms relative humidity $`r=q/q_s`$, where $`q`$ is specific humidity and $`q_s`$ is saturation specific humidity. With gravity $`g`$ and adjacent full-level pressures $`p_L,p_{L-1}`$, the inverse layer mass is $`z=g/(p_L-p_{L-1})`$. For aerosol layer mass $`M_s`$, the passed mass mixing ratio is $`1000M_s z`$. Pressure is in pascals, temperature in kelvin, relative humidity is dimensionless, and this mass conversion follows the original grams-per-kilogram convention. Inputs must satisfy the accepted child domains, including finite values, positive full-level pressure, nonzero interpolation denominators and the supported controls.

The parent calls [runtime aerosol climatology](runtime_aerosol_visibility_climatology.md), accepted runtime SATUR with bottom level and flag 2, [shortwave aerosol extinction](../radiation/runtime_shortwave_aerosol_extinction.md) at band 10, then [runtime cloud and aerosol visibility](runtime_cloud_aerosol_visibility.md). It does not reorder arithmetic, insert density factors or replace a child with verification code.

The aerosol unit limitation remains open. The mass conversion supplies grams per kilogram, while the shown extinction coefficients are stated in square metres per kilogram and the sum has no air-density factor. Those equations do not independently establish an inverse-length result. CLAERVIS preserves the original division of this result by 1000. Exact component agreement and the independent equation checks therefore do not accept the end-to-end physical interpretation of the aerosol visibility result.

The parent owns a 4,096-byte stack frame and one temporary allocation of $`8P(21L+15)`$ bytes, at most 2,961,408 bytes. The RADACA child uses a separate stack allocation of $`6144+512P`$ bytes, at most 71,680 bytes. FPCR is Arm's floating-point control register, and FPSR records arithmetic status flags. The parent preserves `x18`, the Arm saved registers, stack alignment, FPCR and incoming `errno`; natural FPSR flags remain observable. FPCR must be zero. Result 0 means completion, 1 means a real allocation refusal before public writes, 2 means parent admission refusal before public writes, and 3 means a child refusal after earlier ordered outputs may have changed. Every successful allocation is freed before a defined return.

Three complete original/native pairs passed: P17/L137 with columns 1–16 and five cloud planes, P9/L5 with columns 1–9 and five planes, and P24/L19 with all columns and four planes. Before each original or native call, the verifier restores the same public records and payloads at the same addresses. It therefore compares pointer-bearing records literally. All 15,189,908 compared bytes agreed, including complete input records, unused fields, inactive columns and both fifth-plane payloads. Native status, saved registers, exact `x18`, FPCR, matched natural FPSR and preserved `errno` passed. The original is a void routine, so its raw W0 and `x18` were retained without imposing the native result interface.

The saved inputs and source-initialized private values passed 3,428 independent 100-digit equation comparisons. The local rounding band is $`n u/(1-nu)`$, where $`u=2^{-53}`$: $`n=32`$ for temperature, 4 for the local mass and humidity transfers, and 24 for the extinction sum. Temperature uses the absolute numerator terms to account for cancellation. These are local checked bands, not a global error bound. A further 516 checks covered value identities and input domains, actual argument addresses, failure status and allocation lifetimes. These totals do not recount the accepted unchanged child physics. Thirty-one before-write refusals passed, including an output placed in the otherwise unread fifth cloud plane. A real child result 2 was captured before conversion to parent result 3 and workspace release. A real 393,312-byte malloc NULL and natural `ENOMEM` 12 were captured before parent result 1 restored incoming `errno` 34. All known public bytes remained unchanged for that allocation refusal.

The read-only observer verified twelve actual instruction sites before numerical entry and saved 110 complete events without a refusal. It followed only initialized active values inside the live owned workspace. Four exact process identities and both process groups closed without signals. The numerical process had a 90-second cutoff and a 2-GiB virtual-address limit, followed by a 20-second saved-data check within a 126-second complete allowance. The first attempt stopped during debugger setup with zero original and native parent calls; its records and separate closure remain preserved. No numerical pair was repeated after acceptance.

These results accept the controlled component corpus and its explicit runtime interface. They do not establish actual operational aerosol values, resolve the unit mismatch, or verify a complete forecast. The earlier four-plane domain remains covered; the runtime extent extension does not increase the count of replaced original routine bodies.
