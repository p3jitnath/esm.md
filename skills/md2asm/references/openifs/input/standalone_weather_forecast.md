# Standalone Weather Forecast

The [assembly entry](../../../../../src/openifs/input/standalone_initial_bootstrap.S) owns the selected OpenIFS forecast from original input files through final output. T21 means that the model keeps spherical wave patterns up to degree 21. The selected case has 2,048 horizontal grid points, 19 atmospheric layers and one process. It starts on 15 October 2004 and advances 24 hours with one-hour steps. The unchanged OpenIFS equations include the source limitations documented in the [repository Notes](../../../../../README.md#notes).

Build the Armv8.2-A entry with `-DMD2ASM_ENABLE_FORECAST` to include the time loop and `-Isrc/openifs/setup` to find its two public assembly include files.

The program takes exactly twelve path arguments: four input paths followed by eight diagnostic state-stream paths. The inputs are the original spectral GRIB file, surface GRIB file, upper-air GRIB file and `fort.4` configuration, in that order. The diagnostic streams are spectral three-dimensional fields, spectral two-dimensional fields, upper-air fields, metadata, surface state, vertical state, physics state and setup state.

In the forecast build, these eight streams are written after the forecast returns and contain their buffers and records at that time. They retain the [initial-state interface and binary layouts](standalone_initial_bootstrap.md), with the accepted [later setup extensions](owned_fullpos_initial_state.md). The optional `MD2ASM_RADIATION_ASSEMBLY_OUTPUT` path receives radiation setup output before the forecast. Input paths and output paths must be distinct and valid for the requested operation. Each argument is an operating-system path ending with a zero byte, as required by the process interface.

The working directory supplies the selected original climate forcing file `ICMCLepc8INIT`. Set `DATA` to the directory containing the original `ifsdata` tree; the radiation readers resolve their default files below `DATA/ifsdata`. If `DATA` is absent or blank, those readers use names relative to the working directory. The ecCodes sample directory comes from `MD2ASM_GRIB_SAMPLES_PATH`. The accepted run uses `OMP_NUM_THREADS=1`, and its declared external libraries must be on the runtime library search path.

The current execution protocol sets `EC_PMON=0` before process startup to disable FIAT's optional hardware energy and power monitoring. Their nondeterministic log columns then contain zero. Memory reports, progress reports, timing fields and all numerical calculations remain enabled. Canonical weather files and declared state streams retain their exact-byte requirements. Every numerical timing comparison must use the same monitoring setting for both variants; earlier results with monitoring enabled remain a separate protocol.

The floating-point control register must hold zero (`FPCR=0`) at entry, which selects the frozen arithmetic rules. The program checks this register without changing it. Assembly reads live configuration, constructs its own state and array descriptors, loads the input fields, creates the grid and physical tables, runs the forecast, updates the state and writes output. An array descriptor holds an array's address, shape and spacing between elements. Its buffers remain live until the matching final cleanup. Private helpers preserve the declared Arm application binary interface, including `x18`, saved registers and 16-byte stack alignment.

libc provides process startup and memory allocation, while libc and direct Linux system calls provide file operations. ecCodes decodes and encodes GRIB records, and NetCDF reads radiation tables. Public transform, Atlas, mathematical, linear-algebra, profiling and required language-runtime interfaces remain external. Assembly selects their arguments and call order. The [transform arithmetic bindings](../../../../../src/openifs/spectral_transforms/transform_arithmetic_bindings.S) connect library callbacks to the same accepted Legendre arithmetic as direct forecast calls. The production executable has no OpenIFS harness or original OpenIFS numerical provider. The separate original program supplies verification results only.

The canonical forecast outputs are `ICMSHepc8+HHHHHH` and `ICMUAepc8+HHHHHH` at hours 0, 6, 12, 18 and 24, with each hour written as six decimal digits. The ten complete GRIB files contain 618,140 bytes. Their field records, packing and deterministic metadata must match the frozen reference without changing any byte. Diagnostic field arrays retain their earlier little-endian FP64 encoding and declared field order; metadata and owner headers keep their existing layouts. FP64 is the eight-byte floating-point format. Timing records remain separate from all numerical files.

The full comparison also retains every raw byte in 685 internal storage owners, which hold the model's allocated arrays and declared scalar state. A separate verification input contract defines common incoming values for source-unused storage before the first forecast calculation. Its initializer must preserve every source-defined physical value and record its complete before-and-after bytes. It supplies no numerical stage and changes no returned state. Verification keeps the production original-file run separate from this controlled input comparison. Floating-point control and status values remain visible without resets or masking.

The existing independent checks cover the accepted numerical components and the saved trajectory's humidity bounds, finite spectral coefficients, positive mean temperature and pressure conditions, grid and time metadata. Saved files do not contain every store and flux needed for a full water or heat budget. They also do not establish pointwise temperature and pressure bounds or every unsaved state. Exact output agreement preserves source behaviour but does not remove those scientific limits.

The monitoring-disabled selected image uses eight workers for independent cloud columns. The [cloud contract](../cloud_microphysics_contract.md) defines their bounds, private storage and diagnostics.
