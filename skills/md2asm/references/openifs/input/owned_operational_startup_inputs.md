# Owned Operational Startup Inputs

This assembly utility replaces file and vertical-state orchestration in the verification driver. It reads live spectral and grid headers, reads the bounded configuration file, creates physical constants, parses the accepted first NAMCVER group and creates and completes the accepted 137-layer vertical owner. It neither starts MPI nor creates horizontal Geometry, MODEL, fields or a forecast.

The interface is int md2asm_create_operational_startup_inputs(spectral_path, grid_path, configuration_path, output_pointer). Registers x0 through x3 carry these four addresses. Each path has a nonempty readable zero-terminated string with at most 4095 characters. The aligned eight-byte output slot starts null, is disjoint from each path and stays unchanged on failure. Record allocation uses calloc; configuration text uses one 262145-byte allocation so an excess input byte can be detected. Open, read and close use the Linux AArch64 system-call interface; interrupted open and read operations retry, and close never retries. Empty text and text longer than 262144 bytes are refused.

A successful 9968-byte owner has a cookie at 0, live vertical Geometry pointer at 8, text pointer at 16, text byte count at 24, six vertical controls at 48, two vertical scalar inputs at 72, two bound outputs at 88, their two addresses at 104, the complete 9328-byte header record at 120 and the 520-byte physical constants at 9448. All header and constant addresses are final. The owner and its text remain live through every borrowing Geometry, MODEL and forecast consumer. No pointer-bearing record is copied.

The accepted NAMCVER parser receives file layer count and the selected source mode controls ECMWF true, nonhydrostatic false and two-dimensional false. It must produce the supported six-word configuration before any vertical allocation. The two scalar inputs come from the newly created reference-pressure word at Geometry offset 20,320 and the accepted pi word at constants offset 0. Existing ordered numerical children retain their contracts and independent physical checks.

Return zero publishes a complete owner. Return one reports allocation failure, two an invalid entry, and three configuration-file access or length failure. Header, NAMCVER, vertical-creation and vertical-completion errors return their child status plus 10, 20, 30 and 40 respectively. Cleanup preserves the originating return and releases every acquired owner. FPCR must be zero; the utility keeps its required saved registers and the natural child floating-point status. Release md2asm_release_operational_startup_inputs(owner) requires every downstream borrower to have been released first. Null release succeeds. The release checks its own lifetime cookie and releases vertical state, text and the outer record.

The focused gate matches all 975,236 compared bytes, including 939,384 complete vertical payload bytes, with zero differences. It compares the same accepted children, live file text, complete headers and constants, controls, bounds and explicit pointer-owner relationships. All 12 raw ABI observations, six new file or entry refusals and four allocation-failure paths pass. All 106 acquired owners are released, buffer guards remain intact and no file descriptor leaks. Natural successful FPCR, FPSR and errno are 0, 24 and 777. Existing independent physical checks and numerical banks are reused. Independent worker review passes without replay. This is a component check on an owned exclusive node, with a 120-second cutoff and 2 GiB address-space limit, and makes no operational forecast or timing claim.
