# Owned Initial Spectral Caller

Revision 1 composes the accepted spectral file decoder and coefficient-placement routine for the selected coarse forecast. It implements the field-selection and owner-access stage of the normal initial SUSPECG route. Geometry, configuration and spectral records are supplied by the caller and may be constructed by assembly. No OpenIFS executable, script, module data, constructor, type table or Fortran service is required by the production library. The original program remains a separate reference.

The supported route has 19 model levels, 506 real spectral coefficients, one wave processor, one thermodynamic field, three upper-air fields and two surface fields. The upper-air parameter codes are 138, 155 and 130, for vorticity, divergence and temperature. Surface codes 152 and 129 describe logarithm of surface pressure and orography geopotential. Vorticity and divergence use inverse seconds, temperature uses kelvins and geopotential uses square metres per square second. The pressure field is the natural logarithm of pressure expressed in pascals and has no unit. Exact placement follows the [spectral reader](initial_spectral_field_reader.md) and [placement](spectral_initial_state_placement.md) contracts. This caller adds no floating-point equation or conversion.

The interface is int md2asm_load_spectral_initial_state(path, geometry, configuration, spectral, loaded_orography). The five addresses occupy x0 through x4. The first points to a readable C string ending within 4096 bytes. Geometry has 17096 bytes, configuration 1556112 bytes and spectral 2992 bytes. Their addresses are eight-byte aligned. The final pointer selects a writable four-byte logical flag, aligned to four bytes. All three records remain unchanged. The flag and complete numerical output extents are disjoint from each other, every input record and the path. The caller supplies mapped storage of the declared size.

The owned configuration must select normal initial input, with no ensemble-control fields, low-resolution increments or spectral-to-grid conversion. Its typed YRDIMF code descriptor supplies the first three upper-air codes, in source order. YGFL contains at most 2163 component records and no spectral component. Each requested grid-point field must already select grid-point or trajectory input, so this caller does not omit a required spectral-to-grid stage. These are supported-route conditions, not silent defaults.

The spectral record contains complete GNU 12-compatible contiguous descriptors for SP2D at offset 0 and SP3D at 88. SP2D has shape (506, 2), and SP3D has shape (19, 506, 3), with lower bounds 1 and the standard contiguous strides. The exact metadata offsets are obtained with a typed source query, rather than guessed addresses. Their complete numerical extents are 8096 and 230736 bytes. Views into these owners remain valid because the caller changes no record address or descriptor. Every numerical output word preserves the decoded 64 bits.

The caller first validates metadata, field-selection scope, pointer bounds and disjoint extents. It then allocates 317616 scratch bytes, decodes all 78 records and checks complete success, before calling the accepted placement child. The decoder and placement children are unchanged. The loaded-orography flag becomes true only after complete placement. Failed argument, scope, allocation or decoding checks leave every public output unchanged. The scratch owner is released on every allocated path. A decoded scratch prefix is never supplied as a complete state.

The return value is 0 for success, 1 for an invalid argument or buffer contract, 2 for unsupported metadata, 3 for allocation failure, 10 plus the decoder code for file/format failure, and 20 plus the placement code for a rejected placement. FPCR must be 0. The utility preserves caller FPCR, FPSR, errno, x18 and all required saved registers. Its declared interface does not reproduce original diagnostic text, profiling, stream bookkeeping or discarded source-library arithmetic.
