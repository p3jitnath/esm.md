# Runtime Partitioned Surface Input

This assembly route loads the part of the surface state that belongs to one process. A process is one running copy of the program. It reads the local grid dimensions from the same live Geometry record that supplies the point map. The point map gives the global input position of each local cell. The existing physical conversions and their ordered 64-bit floating-point calculations remain unchanged.

Let $`P`$ be the number of allocated rows in a block, $`Q`$ the number of local physical cells and $`B=\lceil Q/P\rceil`$ the number of blocks. The selected route accepts $`1\leq P\leq1024`$ and positive $`Q`$ up to 6,599,680. This input qualification uses the existing 81-record surface file, 6,599,680 global cells and 137 model layers. Other global input schemas need separate qualification. A configurable local block size does not establish support for every global resolution.

The application binary interface, or ABI, uses eight addresses in registers x0 through x7. They identify the input path, physical constants with 520 bytes, physics controls with 448 bytes, surface record with 18,224 bytes, trajectory with 408 bytes, field descriptions with 46,080 bytes, configuration with 48 bytes and the upstream record with 48 bytes. The upstream record contains the reset-word address, the same live Geometry address, local cell count, point-map address, map capacity in bytes and local block count. Geometry supplies the row count and global layer count. Records use eight-byte alignment and the point map uses four-byte alignment. Complete mapped views must fit their declared bounds and obey the existing [surface startup ownership rules](partitioned_surface_state_startup.md).

Define `MD2ASM_RUNTIME_SURFACE_DIMENSIONS` when assembling the six affected sources. This selects `md2asm_initialize_runtime_partitioned_operational_surface_state` and `md2asm_release_runtime_partitioned_operational_surface_state`. The sources also select their matching allocator, default collector, default writer, loader and placement names. Without that definition, the previous complete objects remain unchanged. Keep the new owning surface record in the same model and field lifetime as its live Geometry.

The source order is metadata construction, allocation of 34 numerical arrays, default collection, ordered default writes, input configuration, field routing, file decoding, field selection, physical conversion and local placement. Array descriptions hold each buffer address, extent and stride. Their first and last extents now use $`P`$ and $`B`$. Initial defaults fill the complete allocated rows. File placement changes physical cells and retains unused rows at the end of the final block. For zero-based local cell $`q`$, field plane $`r`$ and an owner with $`F`$ planes, the stored word position is

```math
(q\bmod P)+P\left(r+F\left\lfloor q/P\right\rfloor\right).
```

The private plan needs 119,680 bytes. Its six-owner input table has 144 bytes, including the row count and global input count. The separate accepted file stage still needs an 8,236,403,880-byte temporary buffer. Include that buffer, live model arrays and public-library storage in the process memory budget. The default writer receives a final integer argument with $`P`$ in its low 32 bits and $`B`$ in its high 32 bits. Its 112-byte frame and the placement entry's 128-byte frame hold these live dimensions. The startup frame remains 336 bytes and its private field-routing helper adds 16 bytes.

Return values retain the previous stage and failure meanings. Input refusal occurs before output writes. A later failure releases new numerical and metadata owners and clears the fresh outer records. The ABI preserves x18 and the required saved registers. The floating-point control register must be zero for the declared arithmetic. The entries retain the accepted floating-point status and system error behaviour. Resolve dynamic library entries before seeding an ABI comparison so that the comparison measures the assembly call.

Four small shapes passed 36 critical calls and 37,714,080 complete compared bytes. They cover row counts 1, 5, 24 and 1024, partial final blocks, first and last global map positions, all 34 descriptors, every default assignment, unused storage, guards, refusal before writes and complete release. The full 98,304-byte default-assignment table matches the retained original-source table for each shape. A separate enclosing call reaches every changed startup stage and the complete input plan, then refuses the deliberately unavailable large file buffer and releases all 35 new owners. No passed earlier case was repeated for that enclosing check. All default and selected public objects reproduce their checked images exactly. Actual complete file loading through this new owning route and the operational forecast comparison remain pending. Detailed records stay locally under `.runtime/`.
