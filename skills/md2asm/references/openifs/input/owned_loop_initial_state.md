# Owned initial state with loop data

This entry extends the accepted complete-physics initial-state executable with the selected loop data producers. It preserves the original input files, live configuration, complete Geometry and MODEL construction, complete SUPHEC order and external library boundaries. It does not run a forecast timestep. All new data comes from named owned source producers or the explicit source-described initial-storage policies in their component contracts.

The entry first constructs all 28 SUINTDYN field maps. After the complete Geometry continuation succeeds, it reads its 1,872-byte sidecar, copies the live 32-bit integer process count at byte 880, and binds the live 576-byte standard/post-processing atmosphere tables at byte 1280. The sidecar is distinct from actual Geometry: the first 17,096 bytes of the separate 20,400-byte vertical owner remain actual Geometry. The newly exposed data has no original module input.

After selected TDYNA construction, a 96-byte argument table joins six complete live spans: vertical 20,400, sidecar transform controls 304 at byte 880, forecast controls 51,512, MODEL TDYNA 456 at byte 1,564,136, MODEL TRIP 175,976 at byte 1,359,328, and the original namelist text and length. The loop-data child validates the actual selected controls and text, constructs all four live filter owners and commits their descriptors only after complete success. The separate physical-data initializer reads those live forecast controls and the same text. The original-compatible LOCEDELAY alias shares the actual SU0PHY output word in this entry instead of creating a duplicate scalar.

The global `md2asm_owned_loop_data_ready` label marks successful completion of these joins for read-only verification. It adds no runtime operation or numerical stage. Cleanup releases the four new loop allocations first, before existing complete-physics, radiation, field, Geometry and MODEL cleanup. Existing early failures remain safe because the static loop ownership mask starts zero and release is idempotent. A new child failure follows the existing cleanup route and keeps its existing nonzero exit policy.

Only the entry and new direct assembly objects are built. Existing qualified child objects, complete source gates and external APIs are reused. The changed ordinary startup returns zero and preserves all 2,748,656 initial spectral/upper-air bytes exactly against R16. The complete 30,160,836-byte radiation stream passes its existing source comparison over all 27,197,300 defined bytes and 145 typed owner relations; source-unwritten allocation bytes remain recorded without repair. The production ELF loads no original OpenIFS or verification provider. No original source numerical rerun or forecast is part of this checkpoint.

The original twelve command-line arguments, source file paths and retained output formats follow the [complete physics entry](owned_ecmwf_physics_initial_state.md). This checkpoint changes no command-line or emitted field format. Its ten new direct objects are listed in the local build manifest for integration.
