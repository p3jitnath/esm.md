# Runtime Polar Halo Fill

Revision 1 extends the [spherical boundary values](../../../../../formulations/openifs/transport/spherical_halo.md) to the configured operational map sizes. The [direct entry](https://github.com/p3jitnath/esm.md/blob/28940eb213fb69ab2b64cc0bf154ca733f7c1c21/src/openifs/transport/runtime_polar_halo_fill.S) is `md2asm_runtime_fill_polar_halo`. It implements original SLEXTPOL mode one with an absent demand mask. The existing qualified full-mode entry remains available under its existing limits.

A halo stores extra points outside a process's main grid. Reflect each row beyond a pole to its physical row, copy a matching point when this process owns it, then multiply by the field's dimensionless parity. Parity one keeps the sign and parity minus one reverses it. The field keeps its supplied unit. Complete longitude rows receive one western and two eastern copies for stencil width two, or two western and three eastern copies for width three. Preserve the source signed integer remainder, separate FP64 multiplication, source point order and individual periodic copies. An original PB1(IPT+1,field,1) address is zero-based point IPT.

The application binary interface, or ABI, keeps the original eight address slots in `x0` through `x7`. They are 304-byte TDIM, 1800-byte SL, field-count int32, unused fixed-field endpoints, mode int32, FP64 parity, FP64 PB1 and the absent mask. A ninth context address enters at incoming stack byte zero. Its 16 bytes contain the PB1 byte capacity at 0, the caller-produced false LHOOK word at 8 and a zero reserved word at 12. The unused fixed-field slot is not dereferenced. Retain the public FIAT GSTATS entry and exit calls with tag 1133 and switches 0 and 1. No OpenIFS global or original routine supplies a production stage.

Read dimensions from the supplied live records. Admit 1 through 16384 fields,2 through 65534 physical latitudes, positive signed32-bit NASLB1, and width two or three. Each of the four GNU rank-one int32 map descriptors has unit stride, element length four, source lower/upper bounds, offset equal to minus its lower bound and at most 131072 elements. The producer supplies valid source signed32-bit row counts and start indices whose intermediate additions stay in range. Northern and southern extension bounds and halo widths have the explicit limits in the entry, each at most 1024 rows beyond the physical region. The latitude offset is nonnegative and less than the physical latitude count.

The complete PB1 owner contains 8 times NASLB1 times the field count bytes. Parity contains 8 times the field count bytes. Records and FP64 arrays are eight-byte aligned, scalars and maps are four-byte aligned, and every complete borrowed extent is mapped and does not wrap an address. PB1 is disjoint from all consumed inputs and map payloads. The caller owns these records and complete arrays. The entry uses a 384-byte stack frame and no heap. It preserves `x18`, the saved Arm registers, stack alignment and FPCR. FPCR must be zero. Keep natural multiplication and public profiling FPSR and errno effects.

An integer preparation pass checks descriptor forms, complete capacities, disjoint writable storage, all consumed map bounds and every polar or periodic point before the first output or profiling call. Return 2 refuses an unsupported scalar, descriptor, capacity or computed point without changing PB1. Return 0 completes all source stores and both profiling boundaries. Unsupported mask, mode or LHOOK choices require a separate entry.

The component gate reconstructs the four accepted operational SL/map views without creating Geometry again. It compares complete PB1 and raw status over 677860992 bytes, with zero differing bytes. Both implementations pass 223728 independent polar-parity and periodic relations. The native entry passes 32 nominal and 20 atomic-refusal ABI calls. Inputs and guards remain unchanged, and all verification owners are released. The actual maps use 2560 latitudes and width two, with NASLB1 values 1744925 and 1783837. An explicitly expanded row-spacing fixture checks width three at the same latitude counts. This storage case does not establish a second operational resolution. The process bounds are 120 seconds and 1 GiB resident memory. No complete CALL_SL, forecast or comparative timing is claimed here.
