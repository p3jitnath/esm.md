# Runtime Tracer Mass-Correction Dispatcher

Revision 1 implements the selected TRMFIXERS call from `ifs-source/arpifs/control/trmfixers.F90`. A dispatcher chooses the calculation that runs next. This [assembly entry](https://github.com/p3jitnath/esm.md/blob/28940eb213fb69ab2b64cc0bf154ca733f7c1c21/src/openifs/transport/runtime_tracer_mass_correction_dispatch.S) checks the actual tracer controls and calls the qualified [runtime tracer mass correction](runtime_tracer_mass_correction.md). It adds no numerical equation or temporary array.

The entry `md2asm_runtime_tracer_mass_correction_dispatch` keeps the original sixteen address arguments and appends dependency32 as argument seventeen, at incoming stack byte 64. Arguments one through eight use x0 through x7, with later addresses in consecutive eight-byte stack slots. Start from the mass child's fifteen-address list, replace its YGFL argument with GCONF, and insert the four-byte CALL_SL logical address at slot seven. GCONF is the general configuration record, and its YGFL record starts at byte 184 relative to that argument. The child receives this YGFL address, the other original arguments in order and dependency32 in its slot sixteen. This is an argument-relative offset, rather than an offset from a complete MODEL.

The selected configuration requires LTRCMFIX and LTRCMFBC true, CALL_SL true and the other tracer-fixer controls false. Hook reporting is disabled on this source route. Unsupported selections return 2 before a public write. Dependency32 is nonnull and eight-byte aligned. All complete records, active input and output owners, alignment, separation and source-index bounds obey the child contract. The child reads grid dimensions and strides from live metadata. The dispatcher has no fixed grid or layer count.

A 352-byte frame preserves 16-byte stack alignment, x18 and all required saved registers. The entry uses no floating-point instructions, retains the incoming floating-point control register and forwards its child's natural numerical status and integer result. Its production dependency is the accepted direct mass-correction entry, with no original OpenIFS numerical routine, state or hook provider.
