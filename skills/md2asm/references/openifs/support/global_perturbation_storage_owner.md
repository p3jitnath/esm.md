# Global perturbation storage owner

This direct AArch64 assembly component owns the 1,584-byte global perturbation metadata record used by the CPU physics driver. Metadata describes arrays; it does not contain their weather values. The original global PERTURB_TYPE has UPDATE_VIEW and FINAL methods, but no INIT method. This component supplies explicit outer storage without an original constructor. It is separate from the local ZPERTL work record and from the temporary temperature value owned during each block.

`int md2asm_create_global_perturbation_owner(out_slot,capacity)` receives an address in x0 and a byte capacity in x1. The complete eight-byte output slot must be mapped, nonzero, aligned to eight bytes and free from address overflow. Capacity must cover eight bytes and the incoming slot must be zero. The entry calls public `calloc(1,1584)` and publishes the returned address only after success. The complete fresh record contains zero metadata. It does not allocate cellular or other weather arrays. Return zero means success, one reports allocation failure with the slot still zero, and two refuses an invalid slot state before allocation or mutation.

`int md2asm_release_global_perturbation_owner(out_slot,capacity)` uses the same interface. A zero slot succeeds without a free. Otherwise the slot must hold this component's live, complete, aligned 1,584-byte owner, separate from the output slot. Its PTEMP base at byte 1,272 must be zero. A nonzero base returns two while preserving the complete owner and slot. With a zero base, the entry frees only the outer record and clears the slot. Every other description remains opaque: its target is never read, freed or repaired. Calling release again on the cleared valid slot returns zero.

This release policy covers the selected source branch with false LSTOPH_SPBS_T. In that branch, each successful global UPDATE creates a separate eight-byte dummy temperature owner. Its value is undefined and must not be read as weather or checked as initialized data. Run the accepted raw FINAL after the block's last numerical consumer and before its next UPDATE. FINAL frees the dummy and clears PTEMP. The true borrowed-temperature branch needs a separately extended outer-release contract because FINAL can retain its borrowed nonzero base.

Keep one independent outer record for each active runtime physics lane. The original OpenMP region declares ZPERT private to each lane, while its dimensions and work-view metadata are also private copies over retained shared FIELD owners. The caller owns lane scheduling and the number of records. The fixed 1,584-byte type layout is independent of grid resolution, layer count and process count. This storage entry fixes no loop, stride, partition or thread count, and it does not extend the bounds of its numerical consumers.

The enclosing source sequence is DIMENSION, three registry-borrowing views, global PERT and seven local views. Keep the outer owner through all block consumers and finalization. After the final block, retire the work owners in source order, release the outer record after its last FINAL, and only then retire the registry/model lease. A late UPDATE failure retains its reached source prefix; it cannot be reported as rollback or successful block completion. Source-valid inputs and the accepted child contracts remain caller obligations.

Inactive cellular descriptions have positive shapes and opaque nonzero bases even though they have no numerical owner. Their original bytes must stay exact. All collection, copying of pointed-to values, packing, transfers, checksums, value diagnostics, numerical argument construction and cleanup must classify this inactive route before following any target. Copying the flat metadata record is permitted. This storage component does not establish a complete transport or forecast path.

The application binary interface (ABI) defines argument registers and saved state. Both entries preserve x18, required saved integer and vector registers, the floating-point control and status registers FPCR/FPSR, and `errno`, the C error word. They use integer instructions and an 80-byte frame aligned to sixteen bytes on their public-service paths. The invalid-slot and null-release leaves need no public call. Only libc `calloc`, `free` and the errno-address service are imported. Public library internals are outside the stated private frame.

Complete saved metadata and raw defined status fields agree. The fixed observer recorded one real outer and two sequential dummy acquisitions, with three matching frees. No dummy payload byte was read. All 15 combined calls passed their in-process ABI assertions; masks are separately reported, while each archived 40-byte status contains the defined status and result fields.

The combined check used captured global 137/local 69 records and actual source-ordered cellular and stochastic calls on those detached records.
