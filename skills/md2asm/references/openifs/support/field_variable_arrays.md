# Private Field Variable Arrays

A variable record holds labels, time-level field pointers and views of those fields. A view records an address, array dimensions and element spacing. These services clone private variable records for a physics block, update their views, then release them and restore their shared record pointers. They do not calculate or change a weather value. The separate original controls are FIELD_VARIABLES_MOD and VARIABLE_MODULE from their FYPP sources.

The typed GNU 12 query gives a 72,696-byte FIELD_VARIABLES record. There are 18 array families, each with a shared allocated descriptor and a private pointer descriptor. Each variable in these arrays spans 728 bytes. UPDATE_VIEW follows the original declaration order across 61 scalar entries and the 18 array entries, with the five ECPHYS scalar entries last. Geometry and radiation subrecords outside this source list remain unchanged. Names and offsets are queried individually.

The raw clone and reset entries receive the complete record in x0. The raw parent update receives that record in x0 and the positive block index in w1. All record bounds remain mapped, have eight-byte alignment and are disjoint from their owners. The caller supplies all shared arrays as true original contiguous GNU one-dimensional descriptors with one-based bounds, including allocated zero-length arrays. Each stored element spans 728 bytes, its stride is one and all size products fit the allocated address range. Clone begins with private descriptors aliasing shared arrays. Reset follows exactly one completed clone and releases only the new private records.

Clone nullifies each private data pointer, allocates its source array count and sets the complete private descriptor. Empty arrays still receive an allocation address. Each new record has the declared CNAME spaces, GRIB code minus 999, false logical flags and null views. It copies the six associated field pointers in source order FT0, FT1, FT9, FPH9, FDL and FDM. New private NAME bytes and unused words of unassociated view descriptors have no source-defined value. The direct representation sets them to zero. No physical field, source variable record or existing field metadata is copied or changed by this allocation.

The variable update supports the source two-dimensional and three-dimensional field types. Their variable records span 560 and 728 bytes, and their view descriptors span 64 and 88 bytes. For each associated field, it obtains the complete block descriptor through the accepted direct field-view child, in order T0, T1, T9, PH9, DL and DM. Null fields retain their old views. It then aliases P to T0. Thread-buffer, owned, borrowed and inactive field rules remain those of the qualified field-view leaves. Complete parent updates include every source-listed scalar and every private array element.

Reset releases each private allocation and copies the shared array's complete descriptor back to its pointer descriptor. Shared arrays, all existing variable metadata, field metadata and numerical owners remain unchanged. The direct clone owns the new metadata allocations until reset. Allocation failure terminates through the declared C system boundary, with no original Fortran fallback.

Original-interface adapters read the raw object address from the first word of the class descriptor. UPDATE_VIEW also reads its by-reference block integer. Raw clone and reset use 160-byte aligned frames and C allocation, release, copying and error-address services. Raw parent update uses 112 bytes and the variable update uses 80 bytes. All preserve x18, saved integer registers, required vector-register halves, floating-point controls and flags, and the library error value. Metadata-only view children make no numerical update.

Three critical cases cover empty arrays, mixed active arrays, final blocks, private ownership and borrowed source identities. Eleven seeded original-interface and raw ABI calls pass. The comparison checks the complete outer record and all source-defined private metadata, including every complete view descriptor after association. Undefined NAME bytes and unused words of null descriptors are recorded as an explicit metadata limit, while complete numerical buffers remain byte for byte unchanged. Complete reset records match exactly. The complete native forecast passes all 685 final owners and ten saved files, with zero differing numerical bytes. It executes 2,150 clone, parent-update, reset and two-dimensional variable updates, and 167,700 three-dimensional variable updates. The enclosing context and model construction remain separate work.
