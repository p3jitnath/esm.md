# Owned Forecast Step Listing

This component replaces the project-authored Fortran step_log helper used by the accepted STEPO calculation. It writes progress text and changes no forecast value. The exact source line contains the eight bytes ` NSTEP =`, a six-character right-aligned step, the nine bytes ` STEPO   `, nine configuration bytes and a newline. The selected forecast calls it at steps zero through twenty-four.

The raw application binary interface (ABI) is int md2asm_write_forecast_step_listing(int descriptor, const int32_t *step, const char configuration[9]). Arguments use w0, x1 and x2. The descriptor is open and nonnegative. The step occupies four mapped, nonwrapping bytes at a four-byte-aligned address and contains zero through twenty-four. Configuration occupies nine mapped, nonwrapping bytes and needs no terminator or special alignment. All input bytes remain unchanged, and the caller retains every input and the file descriptor.

Return zero after all 33 bytes are written, two before writing for unsupported basic input, or one after a failed or zero-length write. The Linux write loop retries interrupted and partial writes. A failure can leave part of the current line in the caller's file. The routine owns a 112-byte, sixteen-byte-aligned frame. Its integer decimal conversion places each digit in the original six-character field and retains its leading spaces.

The original-compatible void md2asm_step_log_ entry takes the step and configuration addresses in x0 and x1, plus the GNU hidden character length nine in x2. It uses the owned int32 md2asm_owned_forecast_listing_descriptor, whose default is standard output descriptor one. The enclosing assembly program can bind that word to its own listing file. No Fortran unit or original module storage supplies the destination. The adapter has a sixteen-byte frame and terminates with status 126 on unsupported input or write failure. Its return register is unspecified by the original subroutine interface.

Both entries preserve x18, saved registers, the floating-point control register FPCR, arithmetic-event register FPSR and C library error indicator errno. They use only integer formatting and direct Linux writes. The unsupported native path uses the declared process exit service. No original Fortran routine, numerical fallback or prepared output supplies production text.

Four separate original/native pairs match all 132 complete line bytes. The cases cover steps zero, nine, ten and twenty-four, so both ends and the change from one digit to two digits are checked. All eight immediate source/native ABI and arithmetic-status observations pass, and all input bytes remain unchanged. Original output-service errno is recorded separately, while direct writes preserve incoming errno. One unsupported step leaves its file unchanged, and a full output device returns raw write-failure status.

A static assembly entry writes the exact two source lines for steps zero and twenty-four, totaling 66 bytes, without a library or undefined symbol. Independent source and ABI review passes without repeating the checks. This component supplies no weather calculation and has not yet been admitted in a complete autonomous forecast. LOGDIS, OPDIS and remaining startup and control integration are separate work. No forecast or performance measurement ran.
