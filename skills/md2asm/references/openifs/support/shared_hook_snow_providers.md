# Shared hook and snow providers

An alias is another name at the same memory address. These two assembly sources provide one read-only false hook flag and one existing snow-grid calculation with both required tail-entry names. A hook is an optional profiling call; the selected flag keeps it disabled. This checkpoint establishes the providers and their names. Consumer bindings remain a separate integration step.

`shared_false_hook_policy.S` owns one four-byte, four-byte-aligned integer with value zero. The canonical name is `md2asm_owned_shared_false_hook_policy`. The existing names `__yomhook_MOD_lhook` and `md2asm_owned_height_wind_hook_policy` are typed aliases of that same word. All three names have size four and refer to the same assembly-owned read-only storage. The source has no instructions, numerical operation or relocation.

`shared_snow_grid_entries.S` includes the unchanged [snow-grid source contract](../surface/snow_grid.md). Its main entry remains `md2asm_snow_grid`. The names `md2asm_snow_grid_private_entry` and `__srfsn_vgrid_mod_MOD_srfsn_vgrid` both refer to its existing four-byte tail branch, 1,128 bytes after the main entry. That branch enters the main calculation. Adding the second name adds no instruction, constant or call target.

The snow application binary interface (ABI) remains the existing fifteen-address interface. Its argument order, mapped buffer spans, descriptor strides, alignment, saved registers, sixteen-byte stack alignment, floating-point rules and physical domains remain those of the snow-grid contract. The shared source gives these same entry names to the same machine instructions. It does not extend the numerical domain.

Four fresh isolated assemblies reproduce the complete two old hook objects and two old snow variants byte for byte. The new canonical objects preserve every allocated code and constant byte, and every semantic relocation, which records a linker target and its offset. Their symbol tables give the declared aliases their explicit object or function types and sizes. The accepted numerical, physical, status and interface evidence for the unchanged bodies is reused.

A separate strict provider image contains only these two canonical objects and normal linker startup records. Passive inspection confirms that all hook names share one mapped read-only zero word. It also confirms that both snow tail names share one address and that the loaded branch targets the main snow entry. All 88 loaded read-only data bytes match the linked image, including the unchanged snow constants. This inspection calls no provider entry and adds no numerical or timing observation.

The local handoff contains an explicit proposed replacement map for the old helper objects. It selects one hook object and one snow object, rather than selecting duplicate definitions by link order. That map has not been applied to an accepted consumer. Actual consumer addresses and global-offset-table bindings, which hold linked service addresses, must be checked after a real join. This checkpoint does not accept the complete CALLPAR parent, change any routine count, rebuild the main Fortran program or alter an existing accepted component route.
