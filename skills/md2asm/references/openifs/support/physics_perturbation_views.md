# Selected Perturbation Views

The global `PERTURB_TYPE` stores 18 array descriptions for stochastic physics, which adds controlled random changes to a forecast. A description gives an address, element type, shape and strides; a stride is the distance between adjacent elements along an index. This component implements the selected `UPDATE_VIEW` and `FINAL` methods from `arpifs/module/ecphys_perturb_type_mod.F90`. The source has no global `INIT` method. Numerical values and their physical units are unchanged.

The raw update is `int md2asm_update_perturbation_views(record, model, stoph, controls, forcing_descriptors)`, with pointers in Arm registers x0 through x4. The complete records occupy 1,584, 4,275,088 and 2,904 bytes, respectively. Controls contains five int32 words ordered block index IBL, first point IOFF, active point count ICEND, block width NPROMA and layer count NFLEVG. All complete spans are mapped, eight-byte aligned and nonwrapping, distinct where ownership requires it, and alive through each consumer. IBL and IOFF are positive, ICEND is from one through NPROMA, and NFLEVG is nonnegative. The source sum `IOFF+ICEND-1`, byte products and addresses must fit their declared types.

The source flags LSPSDT and LSPP must be false. Either true value returns two before record mutation or allocation; their owned SPPT and SPP copies remain outside this component. Scalar logical values use canonical zero or one. Consumed allocated descriptions are true contiguous GNU FP64 allocatables, where FP64 means an eight-byte floating-point value. Their rank, element type, span, lower bounds and strides are valid, and descriptor offset plus the sum of lower bound times stride is zero. Every consumed section fits its mapped owner. The direct methods rely on these valid-source conditions rather than validating arbitrary external descriptions.

PSTOPHCA is selected only when RSTOPHCA is allocated. PGP2DSDT and PGP2DSPP become null. GPTOTDISS allocation controls both dissipation views, using the corresponding separate source owners. GPVORTGRAD allocation controls vorticity and its two horizontal-gradient views over the original three layer groups. LFORCENL controls four forcing views at block IBL and time index zero. Its explicit argument is four description addresses ordered GPFORCEU, GPFORCEV, GPFORCET and GPFORCEQ; a false flag permits a null argument. GPSTREAM allocation controls PSTREAM. A false source condition retains the incoming destination bytes unless the source explicitly nulls that view.

For allocated cellular arrays, PCUCONVCA and PNLCONVCA select IOFF through IOFF+ICEND-1. LCUCONV_CA controls the same section of RCAPECONVCA. A separate runtime path requires LCUCONV_CA false and both complete 64-byte RCUCONVCA and RNLCONVCA descriptions zero. It writes the observed original rank-one metadata: base `8*IOFF`, descriptor offset minus one, element length and span eight, stride one, lower bound one and upper bound ICEND. The original first and final block witnesses produce bases 8 and 13,199,352. These opaque descriptions have no cellular owner. Forming a Fortran section of an unallocated array does not establish valid array access; this path reproduces the selected compiled metadata only. Mixed zero/allocated descriptions, null bases with other metadata and active unallocated cellular states remain outside the supported bounds. Valid allocated paths retain their existing equations.

LSTOPH_SPBS_T true selects a borrowed GPTEMP block. When false, update allocates the original one-by-one FP64 dummy PTEMP. Its eight numerical bytes are undefined and must not be read or compared. The cleanup is `int md2asm_finalize_perturbation_views(record, model, stoph)`, using x0 through x2. On the selected path it frees only that dummy and clears its base. Finalize a successful dummy update before another update, using the same ownership flag. Update returns zero on success, one on allocation failure or two for unsupported flags; cleanup returns zero or two. Allocation failure can leave earlier source associations in the record without retaining a new owner. Cleanup never frees a borrowed or inactive cellular target.

The caller follows EC_PHYS_DRV source order: update DIMENSION, then the three borrowed work views, then global ZPERT, then the seven local work views. Global ZPERT and local ZPERTL are distinct records. Keep borrowed inputs alive through the numerical block, then finalize global ZPERT before its next update. Source CALLPAR guards global cellular accesses with LCUCONV_CA and LMFCUCA together. Every host or GPU collector must classify inactive fields before following a base or enumerating a numerical span. Their descriptions may be copied as opaque metadata without changing any bit, but must never supply payload staging, copies, transfers, checksums, value diagnostics, numerical array arguments or deallocation. Generic transport must skip their targets despite the positive shape and nonzero base. Each joined caller must establish this policy across packing, diagnostics and numerical calls.

The application binary interface (ABI) defines argument locations and preserved machine state. The raw methods use a 192-byte frame, keep 16-byte stack alignment, and preserve x18, required saved registers, the floating-point control register FPCR, floating-point status register FPSR and the C error word errno. Only integer metadata operations are added. Public libc calls provide the existing error-word address, allocation and deallocation. The optional `MD2ASM_PERTURBATION_RAW_ONLY` build includes only the two raw methods and private helpers, with libc as its sole dependency.

The normal compatibility build also exports the original names `__ecphys_perturb_type_mod_MOD_perturb_type_update_view` and `__ecphys_perturb_type_mod_MOD_perturb_type_final`. UPDATE retains the original nine arguments: SELF, MODEL and TSTOPH in x0–x2, five scalar pointers in x3–x7, and the rank-five argument on the incoming stack. SELF is a GNU class description whose first word points to the record. The selected adapter does not read the unused rank-five argument. Its frame is 112 bytes; native FINAL uses 32 bytes. The adapters abort on a nonzero raw result and make no original method call. They obtain forcing descriptions from four original module-data exports, which is a retained compatibility boundary rather than autonomous construction. Two uint64 counters record original-interface UPDATE and FINAL entries; raw callers need their own route record.

The retained allocated-path check has three cases and 12 immediate original/direct ABI calls, with complete record and input agreement. It covers optional owners, final rows, non-one lower bounds, empty vertical sections, forcing at time index zero, the ninth stack argument and pre-mutation refusal of both unsupported flags. The inactive extension reuses its accepted original first/final metadata and runs four direct UPDATE/FINAL calls without an original replay. Complete 1,584-byte records agree, with only the corresponding live dummy base substituted in the expected UPDATE record; FINAL needs no substitution. Complete MODEL, stochastic record, controls and guards remain exact. All four archived 48-byte mask/status records have mask and integer result zero, FPCR zero, preserved FPSR zero or 24, errno 117 and preserved x18. Dummy and cellular payloads are unread. All mappings close, file counts balance and the child exits. Source and passive checks retain the unchanged allocated helpers, finalizer and compatibility tail, with exact revised raw code and actual libc bindings.

These results qualify the bounded view component. Previously checked allocated paths retain their earlier [complete forecast evidence](../../../../../src/openifs/README.md#verification) within its original limits. The inactive extension does not accept an active cellular scheme, a genuine enclosing owner producer, host/GPU transport, the complete ordered caller or a whole forecast.
