# Auxiliary Physics Work Records

These three services replace the original `AUX_TYPE` initialization, block-view update and finalization methods. They allocate or select storage without calculating a weather value. Their source is `ecphys_aux_type_mod.F90`. An owned field belongs to this record and must be freed once. A borrowed field belongs to the caller and stays unchanged. A view describes a selected part of a field.

The raw initialization entry is `int md2asm_initialize_auxiliary_work_record(record, geometry, variables, levels, persistent)`. Its first three arguments are eight-byte aligned addresses in `x0` through `x2`. The last two are integer values in `w3` and `w4`. The objects span 1,992, 17,096 and 72,696 bytes and are mapped and disjoint. The record owns no live fields at entry. `levels` is nonnegative, `persistent` is zero or one, and the original geometry supplies positive row and block counts. Supported shape products fit signed address arithmetic and their complete allocations. The selected forecast uses 24 rows, 19 levels and 86 blocks. The critical boundary also checks empty vertical layers.

Initialization copies ten source field pointers from the exact typed variable slots and creates eleven owned fields in source order. Three fields have shape `[rows, blocks]`. Four have shape `[rows, levels + 1, blocks]` and four have shape `[rows, levels, blocks]`. A nonpersistent field uses one block and the thread-buffer flag for the selected one-thread execution. A persistent field uses every geometry block. The accepted direct registry allocator owns DATA and PTR descriptor construction. New numerical bytes remain undefined until their producer writes them. Initialization preserves every public view, the unused NLEV member and all other record bytes. It returns zero on success. On allocation failure it frees only the fields created by this call, clears those slots and returns one.

The raw update entry is `void md2asm_update_auxiliary_work_views(record, block)`, with a record address and one-based integer block value. All 21 field pointers must be live, with valid original headers and mapped storage. The accepted rank-three field-view leaf selects the two-dimensional fields. The new rank-two leaf uses the same integer address mechanism for one-dimensional fields. Four half-level views have their second lower bound changed from one to zero. Their offset increases by the second element stride, and their second upper bound decreases by one. This preserves their first element and complete original descriptor meaning. Borrowed and owned numerical buffers stay unchanged.

The new leaf `md2asm_physics_field_view_2d(output, field, block)` takes a 64-byte output descriptor, a 256-byte original FP64 FIELD record and a one-based integer block. The records are disjoint and eight-byte aligned. The caller supplies the same true original descriptor, valid block and nonwrapping stride invariants as the admitted rank-three and rank-four leaves. ACTIVE selects storage or the inactive VIEW. OWNED selects DATA or PTR. THREAD_BUFFER selects block one. This leaf uses caller-saved integer registers, has no stack or calls and changes no floating-point state or library error value.

The raw final entry is `void md2asm_finalize_auxiliary_work_record(record)`. It releases the eleven owned DATA and FIELD allocations in source order and clears their record pointers. It leaves borrowed fields, public views and unused slots unchanged. Null owned slots are supported for partial initialization cleanup. The original fully constructed path always owns these eleven fields.

Each parent service has a 192-byte frame aligned to 16 bytes. It preserves `x18`, required saved registers, FPCR, FPSR and errno across allocation or cleanup. Original GNU class adapters expose `AUX_TYPE_INIT`, `AUX_TYPE_UPDATE_VIEW` and `AUX_TYPE_FINAL` under their original module symbols. They translate the raw object, registry geometry pointer, referenced integers and absent persistent option. The native constructor stops on allocation failure. No original numerical or metadata procedure is called by production code.

Individual typed queries establish all field-pointer, view and borrowed-variable offsets. Three critical source cases cover thread-local storage, a persistent final block and empty vertical layers. Nine seeded ABI calls check raw and original interfaces. Every source-defined PTR and DATA descriptor byte, storage flag, pointer relationship, complete updated public descriptor, unchanged record byte, borrowed buffer and complete numerical owner agrees. Independently allocated addresses are compared by their ownership and offsets. Undefined new numerical values are not compared before a producer writes them. Independent source review and the complete joint forecast passed. All three work-record types had 25 native INIT calls, 2,150 UPDATE_VIEW calls and 25 FINAL calls. All 685 complete owners, spanning 27,486,113 bytes, and all ten saved files, spanning 618,140 bytes, matched the original forecast exactly. The existing state-view count remained 17,200. The enclosing context and its original metadata construction are separate remaining boundaries.

The three original-interface entries also increment their own aligned 64-bit integer counters in INIT, UPDATE_VIEW and FINAL order. These private observations use only caller-saved integer registers and do not change a field, numerical flag or library error value. The joint gate reads these three words and retains the earlier state-view counter scope.
