# Native scalar exponential names

This assembly adapter exports the original scalar `exp` and `__exp_finite` interfaces. Both names receive one dimensionless FP64 input in d0 and return its exponential in d0. They tail-jump to the independently checked direct body `md2asm_exp_original_rounding`, whose numerical source and full special-case arithmetic remain unchanged. That body follows the pinned original Arm scalar implementation with FPCR zero, gradual underflow, preserved signed zeros, source NaN behaviour and source FPSR/errno results.

The alias entry increments one uint64 counter using only caller-saved integer registers x9 and x10. It then jumps directly to the numerical entry. It uses no stack and preserves x18, saved registers and the incoming numerical input. The getter `uint64_t md2asm_exponential_native_count_get(void)` returns the number of scalar exponential evaluations represented by scalar and paired calls. The selected serial forecast requires a positive count and records its actual value. Calls to private raw EXP children are outside this alias counter.

The selected numerical provider contains these aliases, the unchanged direct EXP numerical object and its literal table object. Its only external service is the C error-slot lookup used by the qualified numerical range-error paths. It has no original Fortran callable, constructor, vtable or module-data input. The focused binding check compares both original names against the retained C control for ordinary, tiny, underflow, overflow, infinity and signalling-NaN inputs, with result bits, raw status, errno and saved registers checked. Existing 1,868 numerical cases, 24 retained forecast operands, the independent high-precision result and the numerical source peer are reused. Actual consumed EXP bindings and the selected complete forecast check pass. The __exp_finite alias has separate interface checks but no consumed relocation in this case.

The [complete forecast check](../../../../../src/openifs/README.md#verification) passes for the selected route. Its declared upstream data and branch limits remain in force.

The private `md2asm_try_exp_pair_counted` adapter uses the same counter storage as the scalar aliases. It first applies the paired helper's integer admission guards. A success adds two with unsigned wrapping arithmetic and then enters the qualified paired numerical body; a refusal changes no counter, floating-point state, error indicator or input. The raw private paired entry remains outside this counter. A complete parent call therefore retains the original number of scalar-equivalent EXP evaluations, including scalar refusals and odd remainders. The combined graph replaces the previous alias object rather than adding another counter owner.

The selected paired caller passes the [complete reflection forecast checks](../physics/calc_reflectance_transmittance_sw.md#current-critical-evidence), including every numerical owner, all saved files, the matched final views, the actual ABI and natural final status. The same process-boundary and whole-forecast physical limits apply. Component and matched complete-process measurements remain in their separate local records and the [README](../../../../../README.md).
