# Runtime Local Departure Weights

Revision 1 extends the complete [LASCAW contract](lascaw.md) to the configured local-halo route. The [direct entry](../../../../../src/openifs/dynamics/runtime_local_departure_weights.S) is `md2asm_runtime_local_departure_weights`. It shares every numerical expression and qualified child with the existing entry, which retains its original single-process admission and byte-identical default object. The [physical input](../../../../../formulations/openifs/dynamics/departure_point_weights.md) is unchanged.

The halo is extra stored data around a process's main grid. The caller's configured SL record owns the demand-active flag at byte 1036. The local-halo route requires this flag to be false. Every original process-count condition also requires the active flag, so its demand branch is false for every valid process count on this route. The new entry checks the live false flag before numerical or output work. It needs no OpenIFS process-count global. The caller must bind this record to its qualified configuration and halo producer.

Keep the original 78-address application binary interface, or ABI. The first eight addresses enter in registers and the remaining 70 enter on the stack. The existing 1600-byte frame, complete buffer capacities, index bounds, ordered FP64 arithmetic, source coefficient choices and status rules remain in force. FP64 means a 64-bit floating-point value. Read the column count, level count, map bounds and array strides at runtime. The supported range is 1 through 1024 columns, 2 through 256 levels and at most 4096 stored latitude rows, subject to the complete child domains and valid signed 32-bit source addresses. FPCR must be zero. All complete mapped owners, disjoint outputs, optional coefficient views and caller lifetimes remain those of the existing contract. The selected complete latitude, longitude and vertical child providers are `md2asm_lascaw_cla`, `md2asm_lascaw_clo` and `md2asm_lascaw_vintw`.

An active demand flag refuses before a public write, with the existing unsupported-route process exit status 116. Other existing unsupported controls retain their previous refusal. The new object imports only standard allocation, release and process-exit services. It calls no original OpenIFS numerical routine and imports no OpenIFS state. The current actual halo producer is qualified for 2560 physical latitudes and four processes. Those producer limits remain separate from the runtime dimensions accepted by this numerical child.

The source and direct component gates use the same objects at 17 columns and 137 levels with source-plane widths 1744925 and 1783837, including full, final-two and empty intervals. An 8-column, 5-level case checks changed dimensions without rebuilding the main Fortran program. All eight calls per route pass, with zero differing bytes across 9326928 complete output and raw-status bytes, and 130050 independent coordinate and polynomial relations per route. Native ABI masks are zero. Natural incoming FPSR values 0 and 24 and errno 777 agree. The active-flag refusal leaves all 1915176 shared owner bytes unchanged. Inputs and guards remain intact and every verification owner is released. Both phases have a 120-second timeout and a 1 GiB resident-memory bound. These results qualify this component, with LARCINA, LAPINEA and the complete forecast still separate.
