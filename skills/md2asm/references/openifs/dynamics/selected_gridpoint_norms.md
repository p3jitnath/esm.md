# Selected grid-point tracer norms

This utility computes the selected `GPNORM_GFL` diagnostic from live owned Geometry and TGFL records. A norm here is a mean or an extreme value used to check the forecast state. The selected route is serial, hydrostatic, spherical, `NSPPR=0`, with absent optional `LDPRINT_TL`. The shape is 24 rows, 19 levels, eight grid-point fields and 86 blocks, with only eight active rows in the final block. All eight component `LGP` flags must be true. Inputs are finite values in the already qualified selected forecast range; unsupported shapes and options are rejected before any result is written.

`int md2asm_compute_selected_gridpoint_norms(geometry, tgfl, controls, results, capacity)` receives complete mapped Geometry17096 in `x0`, TGFL1096 in `x1`, three int32 controls `{NSPPR,LELAM,NPROC}` in `x2`, a writable 264-byte result in `x3`, and its capacity in `x4`. Controls must be `{0,0,1}`. All record addresses have eight-byte alignment and controls have four-byte alignment. Descriptor and pointed-owner bounds, disjointness, finite values and nonwrapping mapped ranges are caller obligations. The GFL owner is a true GNU REAL8 rank-four contiguous descriptor with bounds 1:24,1:19,1:8,1:86. The live transform resolution is already constructed by the accepted owned Geometry graph. It remains alive throughout this call.

For each field and block, first set the active vertical-sum rows to positive zero. Add the 19 level values in increasing level order, with a separate rounded FP64 addition for each value. In the same source loop, reduce the level/cell minimum and maximum. Reduce those extremes over blocks in source order. No final-block padding value is included. The allowed public ECTRANS `GPNORM_TRANS` interface computes the latitude-weighted mean of these completed vertical sums, using `LDAVE_ONLY=true`, the live NPROMA and resolution. Complete caller-owned GNU array descriptors describe its input and three eight-element output arrays. Copy the returned extremes and mean, then divide the mean by 19 with one FP64 division, as in the source.

The result has eight 32-byte rows `{weighted_vertical_sum_mean,field_mean,minimum,maximum}` in source component order. An int32 field count of eight is stored at byte 256; bytes 260 through 263 retain their incoming values. The temporary blocked sum owner contains 132096 bytes and is released before return. Its inactive padding remains incoming and is not a result. Return zero means success, one means allocation failure before result mutation, and two means unsupported input. The implementation omits human-readable printing and profiling, while retaining the numerical diagnostic stage and its observable result data. It claims no external ECTRANS body or whole diagnostic-printing body credit.

FPCR must be zero. Source additions, extrema and division retain their ordered instructions; no fused operation, reassociation or approximate arithmetic is introduced. The external library is the same qualified public ECTRANS provider as the source. Its natural status, together with the source-required arithmetic status, is returned without forcing flags. The routine preserves `x18` and all Arm callee-saved registers and uses an aligned 4096-byte own frame. Its only external calls are `malloc`, `free` and public `gpnorm_trans_`. The production graph has no original OpenIFS state, type descriptor, constructor or callable input.

The numerical loops reuse the accepted grid-tracer diagnostic assembly. The original-source packet and independent 120-digit vertical-sum, weighted-mean and extreme-value checks remain evidence for unchanged arithmetic. A focused complete parent comparison must additionally qualify the direct public transform call, descriptor packing, exact returned bytes, natural processor status, allocation lifetime and native ABI on the actual selected route before readiness. No forecast or timing run is part of this component gate.
