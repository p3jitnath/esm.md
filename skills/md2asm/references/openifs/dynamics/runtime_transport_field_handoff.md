# Runtime Transport Field Handoff

CPG first forms the local transport fields through CPG_DYN, then copies each active column into the latitude buffer through NSLCORE. NSLCORE maps a local physical point to its row in that buffer. This component joins those two stages. It preserves every stored field bit and each field's original physical units. It adds no floating-point calculation.

The original assignment is CPG section 5.2 in `arpifs/adiab/cpg.F90`, following the [grid-point update formulation](../../../../../formulations/openifs/dynamics/complete_grid_point_update.md). The [shared copy loop](../../../../../src/openifs/dynamics/shared_transport_field_scatter.inc.S) visits fields first and active columns second. The existing [default CPG source](../../../../../src/openifs/dynamics/complete_grid_point_update.S) includes this loop and produces its complete unchanged object. The [runtime scatter](../../../../../src/openifs/dynamics/runtime_transport_field_scatter.S) uses live column and field counts.

Let P be the allocated columns in one block, F the transport field count, and N the complete latitude-buffer row count. Read P from Geometry byte 5144, F from MODEL byte 1573016, and N from SL byte 1016. The scatter supports P from 1 through 1024, F from 1 through 4096, and N from 1 through the largest positive signed int32 value. Its required source and destination lengths are 8PF and 8NF bytes. All products and addresses use 64-bit integer arithmetic. The complete supplied capacities must cover these lengths, must not wrap, and must remain mapped.

The entries `md2asm_scatter_transport_field_block` and `md2asm_admit_transport_field_block` receive six addresses in x0 through x5: Geometry, MODEL, SL, local source tile, destination buffer and a read-only 96-byte context. Admission performs the same checks without copying. Both return zero on success or two on a checked refusal before writes. Geometry, MODEL, SL, tile, destination and context have eight-byte alignment; the map has four-byte alignment. Geometry, MODEL, SL and context require at least 20400, 4275088, 1800 and 96 bytes respectively.

| Context byte | Meaning |
| --- | --- |
| 0, 8 | Complete tile and destination capacities in bytes |
| 16 | Global first point of this block, numbered from one |
| 24, 32 | First and last active local columns |
| 40, 48, 56 | Complete Geometry, MODEL and SL capacities |
| 64 | Complete NSLCORE owner capacity in bytes |
| 72, 80 | SL and destination addresses for the joined parent |
| 88 | Reserved zero word |

The first active column lies from 1 through P+1, the last from 0 through P, and the interval is empty only when first equals last plus one. The block start is a positive int32 value. SL byte 1456 contains the original contiguous rank-one int32 NSLCORE descriptor. Its element size is four bytes, its stride is one, its lower bound is positive, and its upper bound fits int32. Its descriptor offset is minus its lower bound. The complete map owner and every selected global point lie within these bounds. Every selected map value lies from 1 through N. Repeated valid map values retain the source's ordered writes.

The destination's complete supplied range must be separate from the source, context, metadata records and map owner. The guard checks those ranges and the complete source and destination products before copying. Mapping validity remains a caller obligation. All metadata and map owners stay read-only and live through the call. Floating-point control FPCR must be zero. The scatter's 128-byte frame preserves x18, saved integer registers, the return address, required vector-register halves and sixteen-byte stack alignment. It leaves floating-point status and errno unchanged.

The [joined parent](../../../../../src/openifs/dynamics/runtime_grid_point_transport_handoff.S), `md2asm_complete_grid_point_transport_handoff`, takes two addresses in x0 and x1. They name a read-only table of 47 ordinary addresses, occupying 376 bytes, and the context above. The table retains the original 46 CPG_DYN arguments followed by its accepted 88-byte dependency-record address. The tile is table entry 37 when counting from zero. Geometry and MODEL are entries zero and two. The parent requires SL at MODEL+1573768 and checks that the original KST, KPROF and KIBL arguments agree with the context. The block start equals (KIBL−1)P+1.

The parent admits the complete scatter before calling the exact accepted `md2asm_operational_grid_point_dynamics` provider. It forwards all 47 addresses unchanged, then performs the shared scatter. Its 448-byte frame has separate outgoing-argument and saved-register regions. It owns no allocation. The numerical provider retains its existing bounds, owned constants, arithmetic, dependency record, nested stack and fatal policy. The joined numerical scope is the qualified P=17 and L=137 operational family. Other supported scatter shapes do not extend that provider's numerical scope. Every original child owner and alias prerequisite remains required. In particular, the table, context and all read-only metadata must be separate from every child-mutable owner, and the destination must be separate from every owner that the numerical provider can change. The final scatter alone changes that destination. No child stage may change the admitted metadata. Checked parent refusal returns two before numerical entry; the existing numerical child's fatal paths remain fatal.
