# Runtime Prognostic Departure Update

The new entry `md2asm_runtime_prognostic_departure_update` extends the complete [LAPINEB contract](prognostic_departure_update.md) with explicit physical constants and forecast controls. Its [direct assembly](../../../../../src/openifs/dynamics/runtime_prognostic_departure_update.S) and the original entry share one numerical body. The original entry retains its complete object bytes. The physics, units, ordered arithmetic, source call order and narrower child domains are unchanged.

The application binary interface, or ABI, retains the original 36 pointer arguments and appends a 16-byte context as argument 37, at incoming stack byte 224. The context contains a pointer to the complete 520-byte physical record at byte zero and a pointer to the complete 51512-byte forecast-control record at byte eight. The canonical physical producer stores the dry-air gas constant RD at physical byte 184, in joules per kilogram per kelvin. The control producer stores the four-byte LRPLANE flag at byte 35292; this spherical route requires zero. The context and complete borrowed records are read-only, aligned to eight bytes, mapped for their complete capacities and alive until return.

Read the column count P and full-level count L from the live Geometry record at bytes 5144 and 5224. The parent admits P from 1 through 1024 and L from 4 through 256, subject to each child's narrower qualified limits. All strides, work sizes and loop bounds use the live records. The active interval includes its first and last columns; an inverted interval is empty. Changing supported dimensions uses input records and the same assembled solver and main Fortran reference executable.

The 2048-byte frame stores the context and borrowed pointers at bytes 1504, 1512 and 1520, outside every original live frame region. The assembly preserves x18, x19 through x29, the lower 64 bits of d8 through d15 and 16-byte stack alignment. FPCR must be zero, selecting round-to-nearest with gradual underflow. The added admission and address instructions use integer arithmetic, preserving natural FPSR and errno. The runtime object calls direct LARCINB and vertical-integral assembly. FIAT supplies only its public fatal-error and OpenMP runtime query interfaces. No original OpenIFS numerical routine or global state supplies a production stage.

Before allocation or a public write, the runtime entry refuses a null, misaligned or wrapping context or new owner, an invalid nonempty returned-owner range, a negative returned count, or overlap between a complete return owner and either new read-only record or the context. Zero-capacity owners occupy no byte range. The caller supplies correct mapped capacities; these checks do not query operating-system mappings. The original scratch allocation, complete returned-owner sizes and child status rules remain in the original contract.

The source and native component gates pass 22 calls per route with zero differing bytes across 9814336 complete output and raw-status bytes. They cover P17/L137 finite differences and finite elements, full, two-column split, final-two-column and empty intervals, P8/L5 convergence and spectral-copy branches, and incoming FPSR values zero and 24. They include source leading dimensions 1744925 and 1783837 with complete read-only sparse PB1 capacities of 54329984800 and 55541548832 bytes. Every populated source prefix has 4096 constructed columns; the values are constructed constant fields. Independent 120-digit checks pass 151444 wind-projection, scalar and pressure-integral relations per route. The finite-element gate uses retained source-produced RINTBF11 and reciprocal-depth owners with private pointer rebasing. No original numerical routine supplies the independent oracle.

Native ABI masks are zero, raw FPCR, FPSR and errno agree, inactive return bytes and input guards remain intact, and every verification owner is released. Eighteen new-context refusals leave all 587602488 shared owner bytes unchanged. Three complete-PB1 pointer refusals leave all 56727876 shared bytes unchanged. Each phase has a 120-second deadline and a 1 GiB resident-memory bound. The original main Fortran program was not rebuilt, accepted child banks were not replayed, and these results make no forecast or comparative timing claim.

The actual source-width calls require a separate [LARCINB capacity correction](departure_field_transport.md). Its whole-owner product and source byte addresses use 64-bit integer arithmetic, with a carry-checked complete PB1 span; individual interpolation indices keep their signed 32-bit domain. The former provider and its accepted 4096-column results remain retained. The new provider is qualified only for the passed actual source-width calls. The loaded weather-state join, communication route, CALL_SL, CALL_SL_HEAP2 and autonomous forecast remain separate work.
