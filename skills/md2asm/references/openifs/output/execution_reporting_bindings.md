# Owned forecast reporting bindings

These adapters connect the original `LOGDIS` and hydrostatic `OPDIS` calling interfaces to the accepted direct reporting utilities. They own argument packing and one attached-context address. The caller owns the 152-byte reporting context, GNU unit setup, norm scalar and all input values. No original module address, object, procedure table or callable supplies a production stage.

`int md2asm_attach_execution_reporting_context(context, capacity)` takes an eight-byte-aligned complete context in `x0` and capacity at least 152 in `x1`. It checks process and unit signs, the zero-or-one `IFIRST`, a nonnull aligned norm address, and single-context attachment. The context follows `execution_progress_reporting.md`: process at zero, listing/error/status units at 4/8/12, `IFIRST` at 16, 120 source-produced path characters at 24 and the live norm address at 144. All mapped, disjoint, nonwrapping range and lifetime requirements remain caller obligations. Reattaching the same context is permitted; replacing a live attached context is rejected. The adapter stores no copy of its pointer-bearing context.

`logdis_` receives six original scalar addresses in `x0` through `x5`: step, model seconds, first CPU seconds, second CPU seconds, timer logical and date logical. The optional character address in `x6` and its hidden length in `x7` must both be zero. It packs the accepted 40-byte record and calls `md2asm_logdis_selected`. `opdis_` receives the two character addresses and five FP64 scalar addresses in `x0` through `x6`, then the step address in `x7`. Its incoming stack holds the nonhydrostatic logical address, the first character length of nine, and the caller-text length from one through 18. It packs the accepted 80-byte record and calls `md2asm_opdis_selected`. These original void interfaces terminate with exit code 126 if no context is attached or the raw utility rejects or reports an I/O error. Successful calls preserve the raw utility's natural FPCR, FPSR and `errno`.

`int md2asm_detach_execution_reporting_context(context)` requires the exact attached address. It calls the accepted status-unit close operation, clears the attached address only after success, and returns the child's status. Release this attachment before releasing the norm scalar or context. No heap storage is owned by these adapters. LOGDIS uses an 80-byte frame, OPDIS uses 128 bytes, and detach uses 32 bytes; each keeps 16-byte alignment and preserves `x18` and all Arm callee-saved registers. Their raw children retain their existing stack and external-library contracts.

The changed check compares the real raw utility with the new original-ABI adapter under the already accepted deterministic external date/memory services. It reuses genuine-source numerical, format, bounds and failure evidence for the unchanged raw children. Both initial and repeated status writes, all incoming stack words, live norm changes, complete context lifetime and immediate native ABI/status are checked. The production graph retains only GNU runtime, FIAT and libc dependencies. No forecast run or diagnostic omission is introduced.
