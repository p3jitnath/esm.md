# GRIB Template Initialization

The direct entries build fresh GRIB headers through the ecCodes C interface. GRIB is the binary weather-data format. The selected source is `PRESET_GRIB_TEMPLATE`, with forecast type `fc`, class `rd`, local definition 1, a regular unstretched T21 grid, 32 latitudes, 64 longitudes and 19 model levels. The caller supplies live configuration and geometry metadata, with no forecast field bytes or saved-message payload.

`int md2asm_prepare_grib_template(void *sample, const void *metadata512, uint64_t kind, void **owner)` clones an ordinary ecCodes sample and applies the original common-header updates. Kind 0 selects surface spectral, 1 selects model-level spectral, and 2 selects model-level Gaussian grid data. A successful return transfers one live ecCodes handle through `owner`; the caller must delete it. On failure, `owner` is unchanged. `int md2asm_initialize_grib_template(const void *metadata512, uint64_t kind, void **owner)` first reads the corresponding ordinary `sh_sfc`, `sh_ml` or `gg_ml` sample, updates the latest table version for GRIB2, and recreates the exact message bytes before applying the same direct preparation route. This follows the original sample-loading and preset stages.

The 512-byte metadata record has signed 64-bit integers at byte offsets 0 date YYYYMMDD, 8 time HHMM, 16 generating-process cycle, 24 local definition, 32 stream, 40 spectral degree, 48 latitude count, 56 longitude count, 64 model-level count, 72 grid type NHTYP, and 80 spectral type NSTTYP. FP64 values are at 88 stretch factor, 96 first latitude in radians, and 104 last latitude in radians. NUL-terminated strings occupy 112 forecast type, 120 class, and 128 the four-character experiment identifier, each with eight bytes. Forty FP64 vertical-coordinate parameters start at 144, with twenty A values followed by twenty B values. A has units of Pa and B has no unit. Remaining bytes are reserved. All buffers are aligned to eight bytes and disjoint. The caller must establish the selected original date branches, including no variable-resolution ensemble date shift and no active observation-cycle date adjustment.

The setter order is cycle, local definition, stream, type, class, date, time, experiment and ensemble flag. Grid headers then set truncation, latitude count, first latitude, first longitude, last latitude, last longitude, Gaussian order, grid type, longitude count and longitude increment. Spectral headers set grid type and then J, K and M. Model-level headers finally set the complete forty-value vertical-coordinate array. Each radians-to-degrees conversion evaluates 180 divided by twice the rounded FP64 asin(1), then multiplies by the latitude. Longitude arithmetic keeps division and subtraction separate. There is no fused multiply-add, reassociation or reduced precision.

The Arm application binary interface uses x0 through x3 for preparation and x0 through x2 for initialization. The stack remains aligned to 16 bytes. Both entries preserve x18, x19 through x30 and the lower 64 bits of v8 through v15. They require FPCR zero, which selects round-to-nearest with ties to even and gradual underflow. Floating-point status and errno follow the called ecCodes services and direct arithmetic; focused source comparisons establish the complete observed return state. No original OpenIFS callable or numerical fallback is used. Unsupported shapes or metadata return 2, sample or clone failure returns 1, and ecCodes errors return their original code. Three genuine common-template controls match all 45,844 message bytes, status and seeded ABI.

The required joint selected forecast passes the unchanged complete-owner, raw-status and ten-file byte gate through the [GRIB field writers](grib_field_writers.md). The format boundary remains the ecCodes C interface, with no original Fortran numerical callable.
