# Selected spectral and grid-point output lists

The direct wrapper `md2asm_output_request_metadata_`, also named `md2asm_output_request_metadata_direct`, receives the original seven pointers in x0 through x6: FPOS, the dynamic request, spectral request, grid-point request, int32 scan, int32 level count and FP64 levels. It implements the selected `SUVFPOSL` construction with NFPCONF zero and one domain. Both TRQFP output records contain 744 bytes. Their sixteen selected allocatable components must be unallocated. Genuine GNU Fortran 12 descriptors from the qualified request allocator are required. The supported counts are at most 686 requested field codes, 64 input levels and 4,096 output records. Invalid or unsupported metadata and allocation failure exit with raw status 116.

The wrapper reads every selected field code, spectral flag, level index, domain count, processor-set number and local field index from the live dynamic request. It reads GRIB codes, surface flags and names from the live FPOS field table. A scan of five supplies the prefix S; another scan supplies P, as the original wrapper specifies. Spectral flags at least one select the spectral list, and the other fields enter the grid-point list. Field and level order are unchanged. Surface fields receive positive zero level bits and the source four-character prefix and twelve-character name. Upper-air fields receive the exact selected FP64 level bits, the scan prefix and the source name bytes. No rounding or numerical field calculation occurs; the signed-zero case is copied unchanged.

The private allocation child creates all sixteen owners in original source order. Empty arrays retain allocated one-byte backing and zero logical payload bytes. Each complete associated descriptor contains the source rank, type, element length, span, offset, bounds and strides. Grid-point IDMP has shape `(1,NFIELDG)` and offset -2. The wrapper fills every declared logical payload byte. The unique cleanup child `md2asm_release_output_io_requests(SP,GP)` frees the same owners in source order and clears only their base words. It leaves counts and all remaining descriptor bytes unchanged, exactly as the source cleanup does.

The wrapper and heap children each use a 144-byte aligned stack frame. Saved integer registers and x18 are preserved. The heap children also preserve FPCR, FPSR and errno across libc malloc/free/error-slot calls, so the composed wrapper preserves those values. There is no floating-point calculation, original Fortran callable, original module-data input or original-library dependency. Optional original console diagnostics and hook services are omitted under the declared output scope. `uint64_t md2asm_output_io_request_count_get(uint64_t index)` reports completed construction at index zero and cleanup at index one, with zero for another index.

Five focused cases cover empty requests, mixed spectral and grid-point pressure requests, nineteen model levels, a surface-only request with no input levels and a negative-zero level bit pattern. The field table is the retained complete original FPOS metadata packet, and request objects are constructed by typed Fortran fixtures before each probe. All 2,208 complete returned owner bytes, 1,488 complete associated-record bytes per case and complete post-cleanup records agree, with only allocated pointer identities represented by exact owner identity. The sixteen-owner free order agrees in every case. Twenty source/direct ABI probes preserve raw FPCR/FPSR/errno and have zero register masks. Complete read-only records and owners total 6,279,616 checked bytes with no change. These are component checks; source peer, actual consumer binding and native forecast admission remain separate.

The [complete forecast comparison](../../../../../src/openifs/README.md#verification) passes for this selected route, with every final owner and saved file compared. Original startup and remaining runtime services still prevent an autonomous-executable claim.
