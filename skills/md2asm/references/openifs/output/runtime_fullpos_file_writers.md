# Distributed GRIB File Writers

These assembly routines select weather fields, collect their distributed values and write complete GRIB files. GRIB stores a field with labels such as its variable, level and time. A spectral field stores wave coefficients, while a grid field stores values at points. The original WRMLFP, WRPLFP, IOSPECE and IOGRIDE routines remain separate verification controls. Production uses the accepted [GRIB encoder](runtime_grib_encoding.md), public ECTRANS communication, FIAT services, ecCodes and operating-system file calls.

## Source And Interfaces

The application binary interface, or ABI, defines arguments, registers and stack storage. Ordinary helper arguments occupy x0 through x7, with further arguments in eight-byte stack slots. An int32 value is a 32-bit integer, and FP64 is a 64-bit floating-point value. Registers marked w use 32 bits. Addresses and byte capacities use 64 bits. Array descriptions follow the qualified GNU Fortran layout, which records an array address, element size, bounds and strides. A stride gives the distance between successive elements.

## Buffers And Lifetime

Geometry has 20,400 mapped bytes, the completed partition has 4,096 bytes, each request has 744 bytes, the output context has 128 bytes and the plan has 64 bytes. The original filename record has 1,536 bytes. Individual filename views have at most 256 bytes. Spectral filenames retain the original first-210-character rule. Typed records and FP64 buffers align to eight bytes. Integer arrays align to four bytes. Every complete range is mapped, does not wrap an address and remains live through its last reader. Output owners are separate from borrowed inputs.

Let $`F`$ be the global requested-field count and $`Q`$ the local point count. Spectral codes use $`16F`$ bytes, physical codes use $`8F`$ bytes and upper-grid codes use $`12F`$ bytes. A dense grid selection uses $`8QF`$ bytes in field order. Blocked inputs have shape block width by field by block, with one-based contiguous bounds and enough blocks to cover all $`Q`$ actual points. Copy actual points and retain source field order. Validate byte products before allocation. Slot counts and byte capacities remain separate values at every call.

The enclosing bounds include spectral degree one through 4,096, block widths one through 1,024, positive local and global counts, at most 65,536 general fields and at most 1,639 physical fields. Physical and upper-grid leaves support at most 6,599,680 local points. Live partition maps determine process-local coefficients and points. These bounds describe admission checks, while the verified dimensions below state the tested scope. The selected route has no I/O server, NOUTTYPE one, NCONF one, inactive observation-only and ocean-field branches, and the original false-LFPDIST distribution.

Initialize the unique writer state after its loop producer and before the first file. Retain it through the final output. WRMLFP performs the two distinct source MAX reductions in their original positions and updates the five previous physical-output steps after writing. Release temporary arrays in reverse order. The shared family reserves 8,192 bytes within its nested budget before charging retained arrays, and the backend charges its simultaneous global-field owner before entering the encoder. Public-library memory remains part of the enclosing process limit.

## Arithmetic And Files

Use FP64 with the Arm floating-point control register, FPCR, set to zero. This selects nearest rounding with ties to even and gradual underflow. Preserve signed zeros, separate operations and the source integer-rounding rules. Do not fuse multiply and add or change operation order. Physical selection copies each field before applying its source gravity or water-density scaling. Upper-grid selection retains source level conversion and cloud quantization. Parameter 248 selects cloud cover, while parameter 164 remains total cloud cover. Spectral selection preserves the source skipped-field and compacted-index rules. Complete source and descriptor checks precede selector writes.

The backend keeps each encoded message live until its synchronous write finishes. A file stores the complete message followed by zero through three ASCII space bytes to complete its source four-byte word. The GRIB end marker, source append or truncate mode, split-file selection and field order remain exact. A service failure can leave a completed file prefix. Cleanup closes the current descriptor and releases reached message, template and private-array owners.

Entries preserve x18, x19 through x29, the required lower 64 bits of v8 through v15 and sixteen-byte stack alignment. FPCR remains unchanged. The floating-point status register, FPSR, retains natural arithmetic events. The common native status values are zero for success, one for allocation failure, two for refused input and three for a public-service failure. Private selectors return zero or two. Public file operations can change errno, so raw enclosing errno is recorded separately from exact numerical status.
