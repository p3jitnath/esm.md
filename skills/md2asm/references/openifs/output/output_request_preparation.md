# Live Output Request Preparation

This service reads the live output namelist and builds the field, physical and dynamic request records used by the accepted FULLPOS controllers. A request says which field and level to save. It contains metadata, which describes the field, and owned arrays, whose allocation must be released once. No forecast field values or encoded output messages are supplied by a verification driver.

## Original Interface And Selected Route

The original md2asm_fullpos_request_prepare_ entry receives ten addresses. Registers x0 through x7 hold F, Geometry, Model, KTIME, KLAG, LDELAY, LOCE and P. Entry stack offsets 0 and 8 hold PHY and DYN. F is a 503824-byte TFPOS record, Geometry is a 17096-byte record, Model is a 4275088-byte record, P is a 1424-byte TFPFIELDS record, PHY is a 744-byte TRQFP record and DYN is a 3696-byte TRQFPDYN record. The four scalar addresses refer to 32-bit integers or logicals. All objects and their complete owners must be valid, suitably aligned and disjoint as in the original caller. The entry returns no value.

The admitted source branch is ECMWF=true, LARPEGEF=false and LELAM=false, with F.NFPCONF=0, LFPCNT=false, a blank control filename, one contiguous output domain and 1 through 64 model levels. The live F.YFPVAB.VBH upper bound must cover those levels. The selected caller accepts model-level, pressure-level and two-dimensional surface requests. The other five level families and physical fields are rejected in this caller. Each count is at most 64, and active pressure levels are exact integral FP64 values from zero through 100000 Pa, including signed zero. The separate raw children support the wider seven-family metadata scope recorded in their checks.

The entry reads fort.4 in its current working directory through Linux openat, read and close system calls. It accepts 1 through 262144 bytes, retries interrupted reads and rejects a larger file, an incomplete group, an unsupported request or a missing live field code with exit 116. It parses the first selected NAMFPC group through the direct bounded parser described in selected_output_namfpc.md. The text and every request value come from that live file. There is no stored model-state packet or original Fortran call.

## Construction And Source Correspondence

The graph follows the selected SU4FPOS route through SUFPC, SUFPFIELDS, ALLOC_FPFIELDS, empty SUFPPHY and SUFPDYN. The original sources are arpifs/fullpos/{su4fpos,sufpc,sufpfields,sufpphy,sufpdyn}.F90 and arpifs/module/{type_fpfields,yom4fpos}.F90. Other SUFPC optional interfaces, control-file selection, satellite and snow requests, and original startup callers remain outside this service. This component exports only the original selected wrapper, so it does not intercept those other original interfaces.

On entry, release existing P, PHY and DYN allocations in the original argument and component order, then form fresh declared defaults. Construct all 21 P owners in source declaration order. Character names are blank, code lists copy the parsed integers, and FP64 levels retain their exact bits and order. The −99 model-level marker generates levels 1 through the live model level count. It requires a positive NFP3DFS count. The selected caller rejects −99 with zero NFP3DFS before P construction, because the original source would write model levels into a zero-length owner. The raw P child requires this same source-valid input precondition. Other selected model-level lists must stay inside the original VBH bound.

Construct the seven dynamic records in source call order: pressure, height, potential temperature, potential vorticity, model, temperature and flight levels. Construct the two-dimensional record last. Each three-dimensional record owns six arrays; the two-dimensional record owns three. Level indices run from 1 through the requested count, and the single domain index is 1. Search the live 686-entry F field table for each external GRIB code; surface fields must also have the original surface flag. Copy each live NFIT and NSPFIL science control from its typed offset. No internal field index is hardcoded.

Every associated GNU 12 descriptor is complete: address, signed element offset, element length, version, rank, type, attributes, span, bounds and strides. First strides are 1; later strides include zero extents. Array lower bounds are 1, and the signed offset is minus the sum of the dimension strides. Empty allocations obtain the source minimum one byte without writing that incoming byte. Allocation failure terminates with exit 116. The successful caller owns all returned allocations, and the accepted release service owns their later cleanup.

The four common SUFPC writes remain live: LTRACEFP=false, LFPPACKING=(NFPOS differs from 0 and NGRIBFILE equals 0), LOCEDELAY=true and RWIDOM=the largest finite FP64 number. The nine original compatibility data symbols are LECMWF, LARPEGEF, LELAM, NFPOS, NGRIBFILE, LTRACEFP, LFPPACKING, LOCEDELAY and RWIDOM. They are explicit data inputs or destinations, with no original procedure, constructor, type descriptor or virtual method. Complete bootstrap still has to own equivalent configured data.

## Status And Ownership Boundary

The complete caller uses 5952 stack bytes, with 16-byte alignment. The parser needs a further 6240 bytes while called. Every required saved register and x18 is preserved; d8 through d15 are unused. FPCR is the frozen round-to-nearest, gradual-underflow configuration. The raw children preserve FPCR, FPSR and incoming errno. Model-level integer-to-FP64 conversion and the pressure bounds are exact within this count range. No fused instruction, reassociation or approximate operation is used.

The successful original external NAMFPC input returns errno zero. The direct original entry returns that same zero after successful reading and construction, while preserving the incoming FPCR and FPSR. Five genuine source cases capture status immediately at return, before fixture cleanup, from errno 777 and FPSR 0 or 31. Their flags agree exactly. No flag is forced or hidden.

The source fresh-metadata map is release_metadata_map.json: unallocated descriptor base words and declared defaults are compared, while source-unwritten null descriptor words and the four private padding bytes at P+1420 and DYN+3476 are documented separately. Every associated descriptor word and every numerical owner byte remains compared. Native private fresh words are zero. Raw source records, including the initial failed padding and errno diagnostic, remain local. No final-owner exclusion or output normalization is introduced.

The implementation uses only malloc, free, __errno_location and the stated Linux input services. It omits diagnostic console formatting, DR_HOOK profiling, Fortran unit position bookkeeping and unreturned source scratch arrays. It keeps the original initialized field/science tables and the stated live metadata words. There is no production allocation fill or interception. Those omissions change neither a returned numerical owner nor a saved-file format; the complete forecast gate remains separate and exact.
