# Output Request Array Allocation

This direct child replaces the selected `ALLOCATE_FPRQDYN` and `DEALLOCATE_FPRQDYN` methods in TYPE_FPRQDYNS. A request record stores integer field selections and array descriptors. The child allocates and releases their storage; it does not select a field, initialise a payload or evaluate a physical equation. Production uses only libc malloc, free and the C error-slot service.

`md2asm_allocate_output_request(Q,D,L)` receives three addresses in x0 through x2. Q owns a complete aligned 1,160-byte TYPE_FPRQDYN record whose fourteen allocatable components are unallocated. D and L address signed 32-bit domain and level counts. The selected forecast uses one domain and zero, four or nineteen levels. The direct entry accepts one through eight domains and an effective level count no greater than64; as in the source, the effective level count is max(1,L). Inputs and allocation extents must fit the declared integer representation. Allocation failure, an unsupported dimension or an already allocated input component stops through raw operating-system exit116; these paths provide no normal return contract.

The typed PARFPOS constant JPOSDYN is686. Allocate NFPTRDYN, LL, ISF, ISKP, ILED and ILEV with J elements; then ILVP and IDOM with shape L by J; IDMP with D by L by J; IGPX with J elements; IGT1 with J by3 elements and second bounds0 through2; then ISET, ILOC and ISPD with L by J elements. L in these shapes means the effective level count. Allocation order is unchanged. Every element occupies four bytes; LL has GNU logical type2 and the other arrays have integer type1. No new owner is filled or zeroed by production code. Only NFPOSDYN resets to zero during allocation; the other incoming scalar counts remain unchanged.

Each associated GNU12 descriptor is constructed completely. It contains the allocation base, signed element offset, four-byte element length and span, version zero, its exact rank and type, attributes zero and all contiguous strides and bounds. Dimensions normally start at one; the second IGT1 dimension starts at zero. Its element offset therefore differs from a one-based rank-two array. Component offsets, ranks, shapes and the exact complete descriptor byte ranges are listed in request_allocation_layout.json.

`md2asm_deallocate_output_request(Q)` receives Q in x0 with all fourteen components allocated and exclusively owned. It resets NFPOSDYN, frees owners in the same fourteen-component source order and nulls each base. Every other descriptor byte remains unchanged. It then resets the sixteen scalar counts in bytes1096 through1159. The child does not release borrowed storage or accept aliased owners. No output object or numerical array is removed from the enclosing final comparison.

Allocation uses an aligned 176-byte stack area, including a16-byte saved argument area; deallocation uses a160-byte frame. Both preserve x18, saved general registers, required saved vector halves, the stack pointer, FPCR, FPSR and errno on successful return. They contain no floating-point arithmetic. The original diagnostic-hook flag is false on this selected route, and original diagnostic output is omitted. `md2asm_output_request_allocation_count_get(index)` reports successful serial allocation calls at index zero, deallocation calls at index one and zero for other indices.

Four focused cases cover levels 0, 4 and 19 and a two-domain shape. The source and direct children receive the same explicit allocation starting byte pattern through a verification-only malloc wrapper. This is supplied before either procedure receives its owner; no returned owner is repaired or filled. Every byte of 562,520 owner bytes agrees. All associated descriptor bytes, exact owner identities, complete 1,160-byte returned records after deallocation, fourteen malloc counts and fourteen-owner free sequences agree. Sixteen source/native ABI calls, including eight native calls, preserve all saved registers and raw status with FPSR seeds 0/31 and errno 777. Production has no allocator interception. These memory operations add no physical equation and need no separate physical oracle. The complete final-owner and ten-file forecast checks pass. Direct replacement of the enclosing selection caller is separate work.

The [complete forecast check](../../../../../src/openifs/README.md#verification) passes for the selected route. Its declared upstream data and branch limits remain in force.
