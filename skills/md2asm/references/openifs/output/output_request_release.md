# Output Request and Header Release

This local component replaces `md2asm_fullpos_request_release_` and `md2asm_output_header_release_` from the selected output metadata source. It frees existing request storage and restores the declared initial state. No field value is calculated, and no original Fortran procedure or constructor is called. The only C services are `free`, `memset` and `__errno_location`.

The request entry receives three addresses in x0 through x2: a complete 1,424-byte TFPFIELDS record P, a 744-byte TRQFP record PHY and a 3,696-byte TRQFPDYN record DYN. All records and their allocations must be genuine, mutually separate GNU Fortran 12 owners. Each non-null allocation base belongs exclusively to its record and can be passed to libc free. A zero-size allocated array still has its own base and must be freed. Input pointers and descriptor bounds require eight-byte alignment; integer scalar fields require four-byte alignment.

The original PHY and DYN arguments have INTENT(OUT). Fortran therefore releases their allocatable components and applies declared scalar defaults before the explicit body releases P. The direct entry preserves that owner-release order: eleven PHY descriptors, forty-five DYN descriptors, then twenty-one P descriptors. The complete P record retains all other incoming bytes, including counts and non-base descriptor words. PHY resets NFIELDG and NFIELDL to zero. Each of the seven three-dimensional DYN request records resets NPPFIELDG, NPXLEV and NFIT to zero and NSPFIL to one; the two-dimensional record resets NPPFIELDG to zero. Every returned allocation base is null.

The header entry receives one address in x0 for a complete 856-byte FPOSBUF record. Its original empty body still has INTENT(OUT) cleanup. The direct entry releases the eleven embedded physical-request owners followed by its rank-three FPBUF owner, then applies the physical-request scalar defaults and null allocation bases.

The Fortran language does not define the private non-base words of a descriptor once its allocatable array becomes unallocated. The retained original control copies process and stack words into some of these positions. All complete raw records and the first failed raw comparison are retained locally. The direct implementation explicitly writes zero to these private words and record padding. The exact byte ranges, null-base words and declared scalar defaults are listed in release_metadata_map.json. This does not remove or alter an associated descriptor, numerical owner or saved-output comparison. Every complete associated descriptor and all numerical owners remain in the unchanged enclosing forecast gate.

The two entries use aligned 128-byte frames. The private descriptor-release child uses a 64-byte frame. They preserve x18, x19 through x29, the link register, required saved vector register halves, FPCR, FPSR and errno. The entries have no floating-point arithmetic. The caller must supply valid owners; invalid ownership and allocation corruption are outside this interface. The source-selected diagnostic hook is disabled. Source-defined allocation and cleanup semantics are retained while original diagnostic text is omitted.

`md2asm_output_release_count_get(index)` returns unsigned 64-bit integer observations: index zero is the request release and index one is the header release. Other indices return zero. Counter updates assume the selected serial forecast. The complete caller and its source order remain separate qualification boundaries.

Six focused cases cover unallocated, allocated-empty and populated records for both entries. All 6,300 source-defined returned bytes agree, including every byte of each P record. The two populated ownership cases preserve all seventy-seven request and twelve header free events in the exact source order. Six native seeded ABI calls preserve x18, all saved registers and raw status FPCR zero, FPSR 31 and errno 777. No original release procedure or model is rerun by the native check; it reuses frozen reference records and release traces. Null private words follow the declared representation because the source assigns no value to them. The complete final-owner and ten-file forecast checks pass.

The [complete forecast check](../../../../../src/openifs/README.md#verification) passes for the selected route. Its declared upstream data and branch limits remain in force.
