# Preallocated grid angles and extrema

This entry computes latitude and longitude in degrees, and then finds their smallest and largest values. It also retains the complete degree work arrays needed by the source-order radiation setup. Latitude and longitude inputs are in radians. The selected source equations are the same as the accepted [angular extrema calculation](grid_angular_extrema.md).

The entry `md2asm_calculate_preallocated_grid_angular_extrema` takes eight arguments. Registers `x0` and `x1` hold the latitude and longitude array addresses. Register `x2` holds the point count, from 1 to 268,435,456. Each input has at least that many FP64 values. Registers `x3` and `x4` hold the initialized physical-constant owner and its byte capacity, which must be at least 520. Its first FP64 word is `RPI`, the value of pi. Registers `x5` and `x6` hold the four-value extrema output and its capacity, which must be at least 32 bytes. Register `x7` holds an eight-byte-aligned, 32-byte workspace record.

The workspace record has four unsigned 64-bit words: the latitude work address, its byte capacity, the longitude work address, and its byte capacity. Each work capacity must be at least eight times the point count. Work addresses must be aligned to eight bytes. Both complete workspace spans must be separate from each other, the two input spans, the physical constants, the extrema output, and the workspace record. The extrema output must also be separate from the workspace record. Address calculations must not wrap. A capacity states how many bytes the caller has actually allocated.

The output arrays use the original ordered FP64 calculations `((latitude/RPI)*2)*90` and `(((longitude-RPI)/RPI)*180)+180`. The scalar loop uses the accepted divide, multiply, subtract, and add instructions without contraction or reassociation. It adds only the two work-array stores to that loop. The extrema retain the first encountered value when values compare equal, including signed zero. The four extrema output words are minimum latitude, maximum latitude, minimum longitude, and maximum longitude, all in degrees. Bytes after the last used work value remain unchanged.

The entry performs no allocation, library call, or stack access. It preserves `x18` and all callee-saved registers. It returns 0 after success or 2 after refusal. The floating-point control register must be zero, which selects ordinary FP64 rounding with gradual underflow on this target. The floating-point status register retains the natural result of the ordered arithmetic. The physical constants, input arrays, and workspace record stay unchanged.

The accepted default entry and this entry use one shared source body. The complete default angular object remains byte for byte unchanged. The focused numerical check used all four retained main-grid coordinate pairs, both actual radiation shapes on all four processes, latitude and longitude boundaries, both signed-zero orders, and a single point. Thirty-two calls to each route compare 232,182,016 degree-field bytes, 3,584 untouched work-tail bytes, 1,024 extrema bytes, and 768 raw control/status/`errno` bytes with zero differences. An independent 90-digit calculation checked 29,022,816 input, degree, and extrema relations over every retained point. The complete saved source/native equality applies those checks to both routes.

The numerical packet is preserved. A later integer-only admission correction refuses an extrema output that overlaps the workspace record. Removing that added block reproduces the complete prior shared source. The arithmetic and work stores are unchanged, and 13 focused workspace refusals preserve all guarded buffers and raw status. The numerical fields were not replayed for this guard correction.

This is a child calculation. The enclosing source-order allocation and release of the degree work arrays, halo publication, local interpolation, and communication remain separate unfinished stages. The new entry does not complete `SUECRAD` or an autonomous forecast.
