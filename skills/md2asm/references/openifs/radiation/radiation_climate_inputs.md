# Owned radiation climate inputs

The assembly reads the three climate files needed by the selected SUECRAD route and builds four owned records. Solar irradiance is incoming sunlight in W m−2. Gas values are volume mixing ratios, so they have no unit. The monthly climatology varies with latitude, pressure in Pa, and month. NetCDF C supplies the file-format service, and libc supplies storage. Sine and cosine use the same system libm provider as the frozen reference.

`int md2asm_create_radiation_climate_context(owner, paths, constants, capacity)` uses x0 for an initially null writable eight-byte owner slot, x1 for three `{address, uint64 byte_length}` pairs, x2 for the owned 520-byte physical-constant record, and x3 for its capacity, at least 520. Paths are ordered solar, climatology, and gas series. Each is a complete resolved filename with 1 to 511 nonzero bytes. For this source-matched interface it starts with `.` or `/` and has no trailing Fortran blank. The caller owns filename selection and DATA-directory resolution. The records, pointer slot and path table are eight-byte aligned, mapped for their complete spans and nonwrapping. The output slot must be disjoint from all input spans. Only the RPI binary64 word at constants offset zero is consumed; it must be the owned producer's exact value. FPCR must be zero.

The function returns zero on success, one on allocation failure, two for rejected bounds or controls, and three for a NetCDF failure or unsupported file shape. Success publishes one 2,792-byte context. Failure leaves the owner slot unchanged, calls close for any current NetCDF handle, and frees all acquired context owners. The context has TSOLARIRRADIANCE at byte zero, TGHGTIMESERIES at 136, TGHGCLIM at 656, and TRADGHG at 1,864. Fresh metadata starts at zero; the declared latitude and pressure defaults are zero. This is the selected fresh READ/INIT route, rather than reallocation of an existing record or repeated INIT.

All 32 owners contain 5,621,016 bytes. GNU rank-one, rank-two and rank-three descriptors have 64, 88 and 112 bytes. A descriptor gives its base address, binary64 width eight, rank and real type, span eight, then element stride and inclusive bounds for each dimension. Fortran dimension order is the reverse of the file's C dimension order; the payload byte order does not change. Every origin equation is `base + 8*(offset + sum(lower*stride)) = base`. All lower bounds are one except the half-level pressure lower bound, which is zero. Typed GNU12 queries establish the full offsets and header fields; no original type or procedure table is a production input.

The source call order is solar READ, climatology READ, gas-series READ, then gas INIT. Each file is closed before its post-read calculations. The climatology reads pressure, latitude and eight gases, then creates zero NO2. It uses cosine latitude weights divided by twelve times their sum. For each gas it first sums its twelve surface-month values at each latitude, multiplies by that latitude weight, and then sums latitudes. Each binary64 addition, multiplication and division rounds separately, and indices increase from their first source element. The source scratch weight allocation becomes a private 512-byte stack buffer with the same values and arithmetic.

Gas-series HCFC22 and CCl4 are optional. Each missing variable creates a zero owner of 2,501 values; both are absent in the selected real input. Gas INIT computes sine latitude and half-level pressure. Interior half levels are half the sum of adjacent full-level pressures. Its last half level is the larger of 110,000 Pa and `1.5*last − 0.5*previous`, with separate multiply and subtract operations. The nine gas-mass arrays are allocated and left unwritten, as in the source. A later time update must produce them before any consumer reads their values. Production does not fill these arrays with a saved packet or a verification pattern.

`int md2asm_release_radiation_climate_context(owner)` uses x0 for the original writable owner slot. It frees the 32 listed owners and the context, then clears the slot. An already-null slot succeeds. The caller must retain the live context and its descriptor bases until release and must not replace their owner addresses. Path buffers and constants remain borrowed and are not retained after creation. Release preserves floating-point state and the natural libc errno result.

The raw children are `md2asm_allocate_radiation_array(descriptor, rank, uint32_extents, first_lower, zero_payload)`, `md2asm_read_radiation_netcdf_array(ncid, name, descriptor, rank, uint32_extents, optional_zero)`, `md2asm_initialize_radiation_climatology_means(climatology, RPI_address)`, and `md2asm_initialize_radiation_gas_coordinates(gas_workspace, climatology, RPI_address)`. Their caller must supply the exact selected shapes and complete valid descriptors or fresh owner slots. They are internal composition boundaries, rather than general checked array APIs. The guarded constructor validates file ranks and every extent before reading each payload.

The code preserves x18, x19 through x29, the low 64 bits of v8 through v15, and sixteen-byte stack alignment. Constructor stack use is 832 bytes; its largest nested own frame is 1,504 bytes through the means child, excluding external library frames. Creation preserves FPCR and leaves the natural FPSR and errno from arithmetic and file services. Invalid integer-only input checks leave status unchanged. The separate genuine whole read/init gate ends at FPCR/FPSR/errno 0/16/0 from fresh flags and 0/24/0 from seeded flags for both implementations. Human diagnostic writes, MPI broadcasts, DATA resolution and later ecRad setup are outside this serial raw boundary.
