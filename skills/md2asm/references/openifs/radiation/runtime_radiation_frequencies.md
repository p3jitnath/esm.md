# Runtime Radiation Frequencies

Radiation calculations run on scheduled time steps. This component converts the original configuration values into step counts. It preserves the selected original `SUECRAD` defaults, both `NAERAD` reads and the later frequency calculations. It adds no radiation physics and does not complete radiation setup or a forecast. The existing fixed-grid component remains unchanged.

The input time step is the live FP64 `YDRIP%TSTEP`, in seconds. FP64 means a 64-bit floating-point value. Its accepted operational owner is MODEL at byte 1359528. This value is distinct from the physics interval `TSPHY`. The hour length comes from the owned physical constants at byte 56 and must equal 3600 seconds. The actual input gives a 450-second time step, eight steps per hour and 24 steps per three hours.

The application binary interface, or ABI, defines each argument and register obligation. `md2asm_initialize_runtime_radiation_frequencies` takes TERAD, its byte capacity, TEUVRAD, its byte capacity, constants, the time-step address, text and text length in x0 through x7. TERAD requires 2040 bytes, TEUVRAD 229312 bytes and constants 520 bytes. The time scalar requires eight bytes. These five complete spans must be mapped, nonwrapping and pairwise disjoint. Every word-bearing span is aligned to eight bytes. Text has 1 through 262144 bytes. Return zero means success. Return two means admission refusal or no terminating schedule before public stores.

A private bounded record receives the original defaults `NRADFR=-1`, `NRADPFR=0`, `NRADPLA=15`, `NRADUV=-1` and `NLNGR1H=12`. The selected scanner reads the first matching group twice under the original search rules. It supports the existing sixteen keys and these five integer names. Names are case insensitive, repeated assignments keep their last value and the group marker follows the accepted uppercase source search. Unsupported keys and `LSRTM=false` reject. Parsed values belonging to another setup stage do not become completed setup through this helper.

The admitted time step is finite and between 1 and 3600 seconds. Radiation and ultraviolet frequencies have integer magnitudes at most 65535. Radiation frequency cannot be zero. `NRADPFR` is between zero and eight, `NRADPLA` between zero and 65535 and `NLNGR1H` between one and 64. These bounds keep all source integer products representable. Negative frequency values mean hours and use the original separately rounded conversion to step counts. Positive values already count steps.

The source calculates `ZSTPHR` by dividing the hour length by the time step. It preserves each FP64 multiplication, addition, integer conversion and public `fmod` call in order. It also preserves the source search used when the time step does not divide an hour closely. That search selects the first larger integer count that divides the separately formed long-period count. The helper admits this search only when the computed long-period count exceeds the initial hour count. The long-period count itself is then a larger divisor, so the search terminates within 230400 candidates. Otherwise it returns two before public stores, retaining the natural arithmetic-prefix status. This preserves the original scheduling rule on its terminating domain and does not promise an exact one-hour period for every admitted time step. No fused operation or reassociation is used.

Only TERAD int32 words at bytes 12, 16, 20, 32, 36, 40, 44 and 132, and TEUVRAD int32 at byte zero, are written. They are `NRADFR`, `NRADPFR`, `NRADPLA`, `NRADNFR`, `NRADSFR`, `NRADE1H`, `NRADE3H`, `NLNGR1H` and `NRADUV`. Every other byte remains unchanged. All outputs commit after admission and calculation. No allocation is required. The enclosing frame is 1536 bytes, with 1200 more bytes for the scanner or 128 for the raw calculation, excluding libm.

`md2asm_calculate_runtime_radiation_frequencies` is the raw calculation entry. Its x0 through x4 arguments are TERAD, TEUVRAD, constants, the time-step address and five int32 choices in the order NRADFR, NRADPFR, NRADPLA, NRADUV and NLNGR1H. Its caller must already meet every enclosing span, value and FPCR condition. The choices occupy twenty mapped bytes, are aligned to four bytes and remain live and disjoint from outputs. It returns zero after the complete update, or two when the calculated schedule has no larger positive divisor. That refusal retains the original arithmetic-prefix FPCR, FPSR and errno, with unchanged public outputs. This raw entry supplies the separate exact arithmetic comparison and does not admit unchecked production inputs.

FPCR, the processor floating-point control register, must be zero. Both entries preserve it, x18, saved integer registers, required saved vector-register halves and sixteen-byte stack alignment. Natural floating-point status remains observable. The quiet enclosing helper preserves incoming errno for valid calculations. Genuine formatted input has its own errno effect, which is reported separately. The exact two arithmetic entries agree in FPCR, FPSR and errno. No status is masked or forced. The separate source component has profiling disabled and does not claim the full original profiling boundary.

Sixteen source/native enclosing pairs and sixteen source/native raw-arithmetic pairs compare 14806528 complete returned record bytes across all four routes. Eight input profiles use time steps of 1, 450, 599.9, 700, 1800, 3599.9 and 3600 seconds, signed and positive frequencies, opposite protected placements and actual operational text. The two enclosing routes return identical records. Their FPCR and FPSR agree, while the formatted source has errno zero and the quiet native entry retains 777. The raw numerical routes agree in all three status values. Native ABI masks are zero. Independent 100-digit arithmetic and integer-divisor checks pass 160 schedule relations.

Thirty-nine pre-arithmetic critical refusals cover invalid spans, capacities, alignment, overlap, time values, hour length, integer bounds, text and FPCR, with complete output preservation. Six additional native-only edge calls check the new termination refusal through both entries at 599.9, 700 and 3599.8 seconds with a one-hour long period. They preserve complete public outputs and return natural FPCR zero, FPSR 24 and errno 777. Two terminating 700-second native calls retain exact frozen source records and numerical status. Existing source comparisons are reused without replay. A separate clean production check consumes actual header/text-produced MODEL, FIELDS and configuration, the live MODEL time scalar and owned constants. Its corrected-provider complete MODEL and separate ultraviolet record agree with the source case. Configuration, FIELDS and Geometry remain unchanged, all constructor owners release and no original numerical library is mapped. The ultraviolet record is an explicit stage input and is not claimed as a completed whole-MODEL radiation owner.

The shared scanner has a 1072-byte default record and an explicitly selected 1104-byte frequency record. Fresh assembly preserves both complete old thirteen-key and sixteen-key objects. Production uses directly emitted AArch64 assembly and public libm `fmod`; source controls and host verification tools remain local. Coefficient, Planck, aerosol and other intervening setup calculations remain separate dependencies. Complete `SUECRAD`, CALLPAR, loaded-weather physics and the operational forecast remain unqualified.
