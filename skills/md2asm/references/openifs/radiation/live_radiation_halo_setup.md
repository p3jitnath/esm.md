# Live radiation work arrays, halo and latitude setup

This component continues the accepted radiation setup through line 1814 of `SUECRAD`. Assembly calls the accepted live point parent, retires its actual `ZMU` owner, computes degree limits on both grids, publishes the halo widths, and creates the local latitude and interpolation arrays. A halo is the extra set of rows needed around a process's own grid region. The same four processes call the component together.

The create entry is `md2asm_create_live_radiation_halo_setup`. Its first eight arguments are `MODEL` and its byte capacity, the completed partition and its capacity, the ownership sidecar and its capacity, and the initialized physical-constant owner and its capacity. They occupy `x0` through `x7`. Minimum capacities are 4,275,088, 4,096, 160 and 520 bytes. The ninth and tenth arguments are a configuration-record address and its capacity, at incoming stack offsets 0 and 8. The configuration record needs 48 bytes and eight-byte alignment.

The six unsigned 64-bit configuration words hold the radiation interpolation mode, stencil width, main `Geometry` address, its capacity, the extrema output address, and its capacity. The main record needs 20,400 bytes. The extrema output needs 64 bytes. The mode is 2 or 3, and the stencil width is 1 through 16. Configuration storage must be separate from the writable model and sidecar, partition, physical owner and extrema output. The local latitude and interpolation base words in the initial radiation record must both be zero. The wrapper derives the radiation-record address from the owned model; the caller supplies no numerical stage.

The record and array bounds retain the accepted child limits. The main coordinate descriptors must name complete FP64 arrays, which store 64-bit floating-point values, with unit stride, lower bound 1 and upper bound equal to the live main point count. Both point counts must be positive, no larger than 268,435,456, and no larger than their allocated maximum counts. The observed configuration has main latitude count 2,560 and actual completed partition dimensions 3 by 2, with four occupied regions. The gate uses radiation latitude counts 800 and 32. The original stored bounds, strides and owner addresses are checked before each dependent stage.

After retirement, assembly allocates the radiation latitude work array, then its longitude work array, using the live maximum point count. The accepted [degree child](preallocated_grid_angular_extrema.md) fills both arrays and computes their four extrema. Assembly frees latitude work first and longitude work second. It then performs the same four steps for the main grid. These private arrays remain live until their degree values and reductions are complete. The four temporary work arrays do not become persistent model owners.

The parent passes its eight returned extrema directly to the accepted [halo calculation](radiation_halo_widths.md). It then passes the resulting live local bounds and retained global latitudes to the accepted [latitude interpolation child](radiation_latitude_interpolation.md). This child allocates `RLATI` first and `RIPI` second. The parent publishes the 64-byte extrema result only after both children complete. The output order is radiation minimum/maximum latitude, radiation minimum/maximum longitude, and then the same four main-grid limits, all in degrees.

The sidecar tag changes from `0x52414453544f5232` after ZMU retirement to `0x52414453544f5233` after the new stage. It retains eight original storage owners, five point-field owners and two new latitude owners, for 15 owners. The entry `md2asm_release_live_radiation_halo_setup` takes the sidecar and capacity in `x0` and `x1`. It collectively checks every owner before release, including separation of both new arrays from all older owners. It releases the new arrays in reverse order and calls the accepted retired-state release for the other 13. A wrong ownership tag, damaged descriptor, overlapping owner, or repeated release is refused before any free.

All ranks agree after each new allocation and child return. A failed stage releases its partial new owners and restores the preceding radiation record, eight halo-width words and extrema output. A failed enclosing create also releases the 13 preceding owners and restores the initial radiation record. The return is 0 for success, 1 for allocation failure, or 2 for unsupported or damaged input. Private agreement calls preserve the floating-point control register, status register and `errno`. Numerical children and actual allocation calls keep their natural status. Each parent frame uses 2,048 bytes with 16-byte alignment and preserves `x18` and all registers that the function must preserve for its caller.

Thirty-two selected-source calls and 32 native calls compare 105,648,000 complete live-owner payload bytes, 39,680 nonaddress radiation-record bytes, 1,024 halo-width bytes, 2,048 extrema bytes, 512 input-label bytes and 768 raw-status bytes with zero differences. The saved records also contain 4,352 zero address encodings for 17 base words in each of 32 radiation records. Those encodings are excluded from actual byte-agreement counts. Each actual pointer is checked separately against its live owner and declared span and stride.

The source suffix starts from the actual archived return of the preceding point and ZMU-release stages. A separate boundary receipt checks all 32 preceding raw-status records: control is 0, status is 16 or 24, and `errno` is 777. The native enclosing entry starts with the original 0 or 24 status and reaches that boundary through its own point calculation. Both routes retain the complete final status without adjustment.

The verifier fills every source and native allocation with byte `0x5a` and places 16-byte guard regions filled with `0xc7` on both sides. Source-unwritten private work tails retain this shared incoming pattern during complete buffer comparison. These patterns define the frozen incoming storage used by the check.
